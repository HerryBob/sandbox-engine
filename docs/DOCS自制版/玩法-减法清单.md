# 玩法 · 减法清单

> **状态**：定案（2026-11-16）。本文是《玩法决策.md》的**收敛表**——把"保留什么、砍什么"集中到一页。
> **判定标准**（引自《玩法决策.md》）：
> ① 一条 9 分 + 三条 6 分 优于 五条 7 分；
> ② 30–60 分钟能造出第一个会动的东西；
> ③ 它让"想造会动的东西"的人更想买，还是只让游戏更完整？

---

## 一、三档定义

| 档 | 做到什么程度 | 标准 |
|---|---|---|
| **保留**（1.0 必做） | **能玩**：可调参、能与其它系统联动、进官方包 | 30–60 分钟体验成立 |
| **原型**（1.0 后实装） | **能跑通**：一条最短路径，能演示"它可以这样接进架构" | **能演示 + 不调参** |
| **砍掉** | 不做 | 写清理由 |

> "原型"不是"做一半"，而是**验证架构能容纳它**；好不好玩、数值怎么调，是 1.0 之后的事。

## 二、砍掉的功能与内容（12 条）

| # | 砍掉什么 | 理由 | 替代路径 | 来源 |
|---|---|---|---|---|
| 1 | **无线电波**（第三套能源） | 离"造会动的东西"太远，且需信号传播基础设施 | 旋转（保留）+ 线信号（后置） | 🆕 2026-11-16 |
| 2 | **饥饿系统** | 生存是"支撑 6–7 分"，饥饿要带一整条资源链 | 只留血量 + 坠落伤害；要饥饿交给模组 | 🆕 2026-11-16 |
| 3 | **温度模拟** | 只需知道"哪里有热源"，不需逐格温度 | 静态标注温差源（风场基场用） | ✅ 原定案 |
| 4 | **上层悬浮空岛** | 世界骨架定案为大陆 + 海洋 | 垂直探索靠气流柱 + 山脊风 | ✅ 原定案 |
| 5 | **鞘翅式特化玩法 / 专用移动道具** | "移动能力 = 结构物理化的自然延伸" | 浮力块 / 旋翼块（**原子方块**，非特化道具） | ✅ 原定案 |
| 6 | **剧情 / NPC / 任务系统** | 弱叙事路线；"A 古文明陨落"只留功能设定与留白 | 遗迹 = 实物教学 + 环境叙事 | ✅ 原定案 |
| 7 | **装饰系统**（家具分类 / 装饰评分 / 套装 / DLC） | 装饰方块是"材质选项"，不是系统 | 提供装饰方块，不做系统 | ✅ 原定案 |
| 8 | **波次式怪物 / raid / 刷屏威胁** | 威胁走"环境遭遇 + 行为引发" | 3–5 种生态位生物 + 环境危险 | ✅ 原定案 |
| 9 | **群峦式全面物理化** | 过度写实会让玩法变窄 | 只保留"局部化、可预判、直接结算" | ✅ 原定案 |
| 10 | **12 种生物** | 生物是"见闻"，不是核心 | 3–5 种（2 氛围 + 1 威胁），其余交给模组 | 🆕 2026-11-16 |
| 11 | **生态规模超越 MC** | 需数十年积累，明确不作目标 | 只追求**开放性深度 + 性能**两项 | ✅ 原定案 |
| 12 | **科里奥利力 / 全球环流** | 不需要全球信风带 | 静态主风线（冷→热） | ✅ 原定案 |
| 13 | **局部时间 / 时间膨胀**（飞船内时间与世界不同速） | ① 不是"建造"玩法，吃掉概念预算；② **飞船与世界不同速本身不合理**——碰撞/站立/物流全部失去定义；③ 收益可用"时间跳进 + 世界自演化"替代，成本低一个数量级 | **全局时间控制**（见保留项 13）+ 将来的"时间跳进"结算 | 🆕 2026-11-17 |

## 三、永久红线（做法层面，不是功能）

| # | 永远不做 | 出自 |
|---|---|---|
| 1 | 强制任务链、限时挑战、"必须看攻略才能过第一关" | 引导原则 |
| 2 | 用降画质 / 减少方块掩盖性能问题 | 性能原则 |
| 3 | 把"有趣"寄托在剧情、过场、数值奖励上 | 有趣原则 |
| 4 | 为单一玩法造专门道具（特化） | 设计总纲 |
| 5 | 玩家侧出现"引擎 / 整合包 / DLL / API / 模组"等词 | 商业文档 |
| 6 | 依赖"选整合包"这一步（必须开箱即玩） | 发布方案 A |
| 7 | **重新发明 MC 已成熟验证的解法**（快捷栏 9 格 / 背包格子 / 挖与放 / 3×3 合成界面 / 16×16 像素风） | 2026-11-17 定 |

### 开发纪律：成熟解法照搬 MC（2026-11-17 定）

> 交互设计是**十五年、上亿玩家磨出来的**。重新"优化"它，是新手最常见的浪费。

| 类别 | 例子 | 怎么办 |
|---|---|---|
| **成熟解法**（时间验证过的） | 9 格快捷栏、背包格子、挖/放、WASD、16×16 像素、3×3 合成 | ✅ **照搬行为，不要重写** |
| **差异化**（MC 做不到/做不好的） | 会动的结构、旋转机器、风、复合体、性能 | ✅ **全部力气投这里** |

**照搬行为，不照搬实现**：

| 照搬（对玩家可见） | 不照搬（内部） |
|---|---|
| 9 格、滚轮、数字键 | MC 的 `ItemStack` + NBT → 我们用"计数池" |
| 3×3 网格、形状配方 | MC 的 `RecipeManager` → 我们数据驱动 + 加工机 |
| 挖/放、面剔除的行为 | MC 的单线程 tick → 我们四轨 |

**原则一句话：界面像 MC，里面是新的。**

**检验方法**：玩家玩 30 分钟后会怎么描述这个游戏 ——
"像 MC 但更流畅" = ❌ 整合包感；
"像 MC 但能造会飞的东西、机器真的会转" = ✅ 另一个游戏。

### 由此确定的 UI 决策（前面的讨论全部收敛到这里）

| 项 | 定案 |
|---|---|
| 快捷栏 | **9 格**，滚轮 + 数字键 1–9 |
| 背包 | **格子**（照 MC 的布局逻辑，靠 tab 分类，不拆左右） |
| 合成 | **3×3 + 输出格** |
| 副手 | **工具槽 1 格**，只有"使用"功能（左键破坏永远属于主手） |
| ~~5+5 双快捷栏 / 双手双选中态 / 目标驱动分派~~ | **作废** |

## 四、容易被误当成"砍掉"的三类

| 状态 | 系统 | 说明 |
|---|---|---|
| **后置**（不是砍） | 流体与气体、自动化、线信号、多群系、联机、风暴、铰链/弹簧、风场 W2/W3 | 留设计，1.0 后实装 |
| **原型**（1–3 天验证） | 线信号、自动化、流体、生物动画、风暴、铰链 | 1.0 前顺手验证"能否接进架构"，留结论、删代码 |
| **不做原型** | **联机** | 原型成本 = 重写 SPSC 范式；做一半比重做更贵 → 1.0 后一次性做 |

### 原型的"停止线"（写死，防止膨胀）

| 系统 | 做到这里就停 | 明确不做 |
|---|---|---|
| 线信号 | 一根线 + 一个开关 → 点亮一个灯 | 逻辑门、时序、穿墙、跨 chunk |
| 自动化 | 一条传送带 + 一个漏斗 → 方块从 A 到 B | 分拣、路由、缓冲、多物品 |
| 流体 | 一池水（几百格）能看出"会流" | 海、LOD、气体、压力、与建造交互 |
| 气体/压强 | 一个"压强值"接口 + 蒸汽机读它 | 真实气体扩散 |
| 生物动画 | 双足/四足：IK 腿 + 步态相位 + 身体正弦；脚用**向下射线**贴地（不加碰撞体） | 蜘蛛/蜈蚣/蛇、脚部 collider、动作混合 |
| 风暴 | 一个全局风倍率参数，能手动触发 | 视觉、云、音效 |
| 铰链/弹簧 | 一个铰链能摆动 | 限位、阻尼、断裂 |

### 原型四条纪律

1. **时间盒 1–3 天** —— 超了说明它在做功能，不是验证架构。
2. **不调参** —— 一旦调手感，就滑向"半成品"。
3. **必须留一句结论**（例："线信号能接进方块行为运行时，但跨 chunk 需要事件总线"）—— 结论比代码值钱。
4. **不留在主分支** —— 独立 tag / `experiments/`，完成后删代码，只把结论写进文档。

## 五、保留（1.0 必做）—— 一条 9 分的主干

| # | 系统 | 程度 |
|---|---|---|
| 1 | **结构物理化**（复合体 / 活建筑 / 飞行器） | 完整（唯一 9 分项） |
| 2 | **建造与破坏** | 完整，含刚体改造 |
| 3 | **风** | W1 解析风场（基场 + 采样 + 推力） |
| 4 | **存档** | 语义状态格式 v1 |
| 5 | **遗迹教学** | 1–2 个，"运转中的实物示范" |
| 6 | **动力（旋转）** | RPM / 应力 |
| 7 | **运动方块** | 旋转关节 + 直线执行器 |
| 8 | **基础方块** | 结构块 + 连接件 + 地基 |
| 9 | **材质维度** | 木 / 石 / 金属 / 轻金属 |
| 10 | **资源分层** | 越深/越危险 → 越好材料 |
| 11 | **生存** | 血量 + 坠落伤害 |
| 12 | **生物** | 3–5 种（2 氛围 + 1 威胁） |
| 13 | **全局时间控制** | 玩家可调"世界流速"（暂停 / 慢放 / 加速）。**业务与物理共用同一个系数**，绝不分开 |

**新增一件**：**自带效果的原子方块** —— 浮力块（自带体积/浮力）、旋翼块（自带推力）。
不违反"不特化"（仍是原子方块），但把入门从 5 个方块压到 2 个，是"30 分钟"判据能否成立的关键。

> **关于第 13 条（全局时间控制）的重要约束**：
> 这是"整个世界一起快慢"，**不是**"某艘船慢下来"。
> 实现上：`TimeManager` 的 `business_` / `physics_` 恒为 1，只有 `global_` 变化 ——
> 两个域永远同值，所以只有一条时间线。
> 当前状态：`setGlobalScale()` 的 API 已有，但**还没有任何入口调用它**（UI/按键/命令都未接）。

## 六、减法后的官方包最小内容

```
系统：结构物理(Jolt) + 风(W1) + 建造/破坏 + 存档 + 遗迹引导
方块：建造材料 4–6 种 + 浮力块 + 旋翼块 + 动力块 + 连接件 + 旋转关节
世界：1 个大陆群系 + 海 + 1 个教学遗迹
生物：2 氛围 + 1 威胁
生存：血量 + 坠落伤害
```

**目标体验**：30–60 分钟内，用一个气球、一个旋翼、一个动力块，造出能飞的东西，然后发现远处有个"已经在飞"的遗迹。

## 七、减法效果对照

| 维度 | 减之前 | 减之后 |
|---|---|---|
| 能源体系 | 3 套（旋转/线信号/无线电） | **1 套**（旋转） |
| 方块类别 | 6 类 | **3 类**（基础/运动/动力） |
| 生物 | ~12 种 + 程序化动画 | **3–5 种** |
| 生存 | 饥饿 + 血量 + 威胁 | **血量 + 坠落** |
| 群系 | 多群系 | **1 个** |
| 高端系统 | 流体/气体/自动化 | **全部后置** |
| 联机 | 文档"必做" | **1.0 之后** |

> **砍掉的是"广度"，保住的是"那一条 9 分"。**
> 被砍掉的系统将来由模组补齐 —— 这正是"半引擎"的兑现方式。

## 八、官方 vs 模组：职责分工（2026-11-16 定案）

> **官方的任务只有三件**：
> ① **做好基础**（引擎原语）；② **给模组准备地基**（API / 工具 / 示例）；③ **把自己的东西写好**（官方包 = 参考实现）。
> 玩法内容的广度交给模组，官方不靠"内容量"取胜。

| 层 | 谁做 | 内容 |
|---|---|---|
| **引擎原语** | 官方 | 结构物理 · 风场 · 流体场 · 浮力/气室 · 方块行为运行时 · 存档 · 模组 API |
| **官方包** | 官方 | 水车 / 水闸 / 一个能浮起来的东西 / 1 个教学遗迹 —— **最小、可玩、可抄** |
| **玩法内容** | 模组 | 潜艇、战舰、自动化、生物、群系、装饰系统…… |

### "把自己的东西写好"的三条标准

| 标准 | 含义 |
|---|---|
| **官方包 = 最好的样例** | 模组作者读官方包的源码，就能学会"怎么正确用平台"；它不依赖任何未公开接口 |
| **API 有文档 + 示例 + 版本纪律** | 追加式演进（v3→v5 已有纪律）；旧模组不重编不会崩 |
| **原语不做特化** | 引擎只提供"能力"（浮力/风/旋转），不提供"潜艇"；一旦特化，模组的路就被挡死 |

> **检验方法**：任何一个"官方要不要做"的内容，问一句 ——
> **"这是能力，还是某一类玩法的实现？"** 能力归官方，实现归模组。
