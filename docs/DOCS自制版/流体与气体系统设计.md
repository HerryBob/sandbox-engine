## 0. 决策摘要（一行读懂）

**三层混合模型**：隐式海洋（规则推导）+ 显式浅水区（加载区内模拟）+ 事件驱动边界（连通/钳制/吸收）。气体 = 同一模拟器的参数化变体（浮力反号 + 扩散项）。

核心决策清单：

| # | 决策 | 理由 |
|---|---|---|
| 1 | 流体范式 = 网格流体（MC 式状态机 + 浅水延伸） | 体素世界可改方块，3A 渲染式方案无玩法 |
| 2 | 海洋用隐式（h_sea 全局标量 + 连通规则），不做全模拟 | 海洋 99% 时间静态；全模拟（TFC 式）CPU 账单巨大 |
| 3 | 加载区内海洋和河流统一用浅水模型 | 消除海河分界边界规则，物理连续 |
| 4 | 未加载区块只保留视觉效果（海面平面 + LOD） | 规模锁死，模拟圈 12-32 chunks 足够 |
| 5 | 流体模拟放业务线程（不单开线程、不上 GPU） | 数据归属决定：流体要改方块；GPU 回读是致命伤 |
| 6 | 物理线程只消费"力"（ApplyForce） | 格子化的归业务，力学的归物理 |
| 7 | 气体 = 参数化格子模拟器（同族方程） | 数学同构：水/岩浆/蒸汽/毒气/烟雾一套代码 |
| 8 | 水的语义 = 全部无限（2026-10-28 定案） | 水不是资源不作生存内容；连通海与封闭池都排不干，架构最简 |

## 1. 总体架构：三层混合模型

```
┌────────────────────────────────────────────────┐
│  层 1 · 隐式海洋（implicit ocean）              │
│    状态：h_sea 全局标量 + 连通域标注             │
│    规则：y < h_sea 且非实心且连通 → 有水         │
│    成本：查询 O(1)，模拟 0                     │
│    覆盖：海洋本体、海平面下连通空间              │
├────────────────────────────────────────────────┤
│  层 2 · 显式流体区（格子流体 + 活跃集）          │
│    状态：h + (u,v) 显式存储                     │
│    模拟：浅水模型（每 tick 活跃格）              │
│    覆盖：河流、引水渠、泵区、玩家活跃水体        │
│    成本：活跃集账单（12 chunks 全海 ≈ 2% 单核）  │
├────────────────────────────────────────────────┤
│  层 3 · 边界与事件                              │
│    海洋↔显式区：水位钳制 / 出流                  │
│    挖掘/填充：连通重标 + 灌水动画 + 增量重建      │
│    洪水/潮汐：h_sea 变化 + 受影响 chunk 重建     │
└────────────────────────────────────────────────┘
```

### 1.1 关键规则

```
isWater(p) = (p.y < h_sea) AND !isSolid(p) AND connectedToSea(p)
  连通域不逐格存：默认"海平面下非实心 = 水"，封闭空间（洞穴/干坑）显式标"干"
  事件（挖/填）→ 局部 BFS 重标连通域（低频事件重算，不进 tick）

边界三条规则：
  ① 出流：河流入海口 = 显式区出流边界（水流进海即"消失"）
  ② 水位钳制：与海连通的出水口 < h_sea → 水位自动钳制到海平面
  ③ 显式优先：一格永远只属于一个系统（显式 > 隐式）

"有水"是连通性问题，不是高度问题 —— 顺带修复 MC 的"水下空气洞穴"bug
```

### 1.2 爆炸/大扰动场景（波的命运）

```
爆炸 = 方块变化事件（Water→Air）→ 增量重建队列
  ① 坑边缘涌入（浅水模型真实模拟）
  ② 回流波以 c=√(gh) 向外扩散（加载区内真实）
  ③ 波到加载边缘 → 海绵吸收层（阻尼衰减，不反弹）
  ④ 未加载区 shader 涟漪（视觉兜底，同步渐隐）
h_sea 常数边界 = 无限水库：坑永远填得满，水位永远正确
```

## 2. 范式对比（为什么是这套）

### 2.1 三种流体范式

| 范式 | 代表 | 本质 | 代价 |
|---|---|---|---|
| A. 网格流体（方块流体） | MC 原版水 | 方块状态机（source/flowing + level） | 简单、无真物理 |
| B. 管道/节点流体 | 机械动力 Create | 网络节点间传输 | 工业逻辑，非连续介质 |
| C. 粒子/求解器流体 | SPH/LBM | 数千粒子/网格点真实流场 | 物理对、性能重 |

**选型：A 为主 + B 按需（工业模组），C 不做**。水 = A；泵/管道 = B；两者对接 = "泵把 A 的水抽进 B 的管道"。

### 2.2 与业界对比

| 维度 | vs MC（静态状态机） | vs TFC（全模拟） | vs 3A（纯渲染） |
|---|---|---|---|
| 成本 | 略高（有模拟） | 低得多（只模拟加载区，海洋 O(1)） | 相当 |
| 玩法 | 同量级 + 真 current 推实体 | 同量级 | 碾压（3A 水不可改） |
| 视觉 | 强（真实波/回流） | 同量级 | 需调（物理 vs shader） |
| 扩展 | 海洋会崩（全量） | 海洋会崩（全模拟） | 不能扩展玩法 |

3A 佐证（已核证）：盗贼之海 = Gerstner/FFT 视觉波，水体不模拟；塞尔达王国之泪 = 入水阻力（投影面积），水不流；Teardown = 静态水位 + 飞溅。**行业共识：大海洋不模拟水体，只渲染**。

## 3. 浅水模型（数学基础）

### 3.1 从纳维-斯托克斯到浅水方程

```
假设：水深 h << 水平尺度 → 垂直加速度可忽略 → 压强 = 静水压
深度积分 → 二维变量：水深 h(x,y) + 水平流速 (u,v)

① 质量守恒：∂h/∂t + ∂(hu)/∂x + ∂(hv)/∂y = 0
② 动量守恒：∂u/∂t + u·∂u/∂x + v·∂u/∂y = -g·∂(h+z_b)/∂x
   （重力是恢复力：水永远在"被拉平"的路上）

波速：c = √(gh)（浅水波速随水深平方根增长）
```

### 3.2 离散化（每 tick 更新链）

```
每格存：h（水深）、u/v（流速）、z_b（底高程，从方块坐标读）

显式欧拉（lisyarus 风格）：
  ① 算相邻格水面梯度 → 加速度 a = g·∇(h+z_b)
  ② u += a·Δt
  ③ 算 4 边通量（flux = h × u × 边宽）
  ④ h -= 流出通量 × Δt
  ⑤ 边界处理（出流/入流/固壁）

偷懒版（无动量）：按高度差直接分水——流不出 current，推不动实体（不推荐做主方案）
```

### 3.3 稳定性：CFL 条件

```
Δt ≤ Δx / c_max = Δx / √(g·h_max)

引擎验证：业务线程 Δt = 40ms、Δx = 1 格
  h=16 → c≈12.5 格/s → Δt_max = 80ms ✓（40ms 刚好一半）
→ 水模拟直接跑业务线程 25 TPS，天然满足 CFL，无需独立调度
```

## 4. 性能方案（分层防御）

### 4.1 四个性能问题 → 四个防御层

```
架构层（决定"要不要算"）：chunk 加载/卸载 + 隐式海洋 → 规模锁死
算法层（决定"算哪些"）：活跃集（砍 80%）+ 事件驱动 + 增量重建 + 降频
数值层（决定"每步怎么算稳"）：CFL 天然满足 + 海绵吸收层 + 稳态初始化
数据层（决定"存多少"）：稀疏分配（只有加载区）+ 显式持久化（只存非稳态）
```

### 4.2 性能预算（曼哈顿口径，单核按 ~10 亿 op/s）

| 模拟距离 | 水列数 | 全模拟 | 活跃集后 |
|---|---|---|---|
| 12 chunks（默认） | 80,128 列 | 1.0 亿 op/s ≈ 10% | 2000 万 op/s ≈ **2%** |
| 32 chunks（上限） | 540,928 列 | 6.76 亿 op/s ≈ 68%（饱和） | 1.35 亿 op/s ≈ **13.5%** |

```
内存：浅水数据 ≈ 4B/列 → 12:320KB / 32:2.2MB（无压力）
岛屿场景 ≈ 全海（决定成本的是水列数，不是陆地比例）
验收线：12 全海活跃集后每 tick < 1ms；32 < 5ms
```

### 4.3 优化梯度（从便宜到贵）

```
活跃集（只模拟邻空气 + 有流速格）→ 限速配额 → 远处冻结 → 降频（4-8 tick 一次）→ 分区并行（最后）
MC 基岩版模拟距离封顶 12 chunks 的真相 = 预算纪律（12 任何设备兜得住）
```

## 5. 渲染方案

### 5.1 管线结构（半透明不需要新 render pass）

```
1 render pass + 2 pipelines：
  pipeline_opaque    ：深度写 on、无混合 → 先画固体
  pipeline_translucent：深度写 OFF、blend ON → 后画流体（远→近排序）

半透明的全部秘密 = 两个状态：depthWriteEnable=FALSE + alpha blend
新 render pass 只在"后处理"（折射/焦散/体积雾）时引入
```

### 5.2 面剔除（水剔水，与固体镜像）

```
固体：邻固体 → 剔面（已做 faceMask）
水  ：邻水   → 剔面（水体内部零面 = 水的"一层皮"红利）
      邻空气 → 生成水面（level 0-7 决定水面高度）
      邻空气垂直面 → 生成（岸边水墙）
网格：mesh_solid 与 mesh_fluid 分离（各自增量重建，各自 draw）
```

### 5.3 海面平面（隐式海洋视觉）

```
一张大平面（LOD 细分）+ 顶点着色器 Gerstner 波叠加
  LOD：近密远疏；相机位置吸附（防海面抖动）
  加载边缘水面 = h_sea = 海面平面高度 → 方块水与海面无缝
分层：未加载区只有海面平面；加载区 = 方块水（模拟）+ 海面平面（表面）
```

### 5.4 着色优先级（从便宜到贵）

| 技术 | 成本 | 时机 |
|---|---|---|
| 深度雾（颜色随深度指数衰减） | 极低 | **现在** |
| 半透明混合 | 低 | **现在** |
| 泡沫（岸边/入水） | 中 | 后置 |
| 折射/焦散（后处理） | 高 | 后置 |

### 5.5 性能（优化后 ≈ 固体）

```
水/气体面数 = 表面面积级（水剔水/气剔气）
draw call = 每流体 chunk 1 个（视野内几十上百个）
overdraw 因子 2-3（水面层 1-2 次混合）
海面平面 1-4 万顶点固定（与海洋大小无关）
```

## 6. 气体系统（同构延伸）

### 6.1 映射（气体的隐式部分已免费）

```
隐式海洋（h_sea）→ 隐式大气 = Air 方块（世界本来就有，0 成本）
显式浅水区 → 显式气体区（蒸汽/毒气/烟雾：浓度 + 流速）
连通规则 → 同构（有气 = 连通到源头）
吸收层 → 扩散边界（气体出界自然消散）
```

### 6.2 参数化模拟器（一套代码，N 种流体）

```
动量方程同构：
  水  ：∂u/∂t = -g·∇(h+z_b)          （重力向下）
  气体：∂u/∂t = +g_eff·∇ρ − κ∇ρ      （浮力向上 + 扩散项）

class FluidField { float h, u, v; FluidType type; }

| 类型 | 密度 | 重力方向 | 扩散 | 消散 | 玩法 |
|---|---|---|---|---|---|
| Water | 高 | 下 | ≈0 | 否 | 灌溉/水车/运输 |
| Lava | 高 | 下 | ≈0 | 否 | 燃烧/地形 |
| Steam | 低 | 上 | 中 | 缓慢 | 蒸汽机核心 |
| Gas | 低 | 上 | 强 | 快 | 浓度阈值引爆 |
| Smoke | 低 | 上 | 强 | 快 | 遮蔽视野 |
```

### 6.3 气体的独有玩具

```
扩散（水≈0，气强）→ 需要扩散项
消散（水不消失，气缓慢消失）→ 蒸汽/毒气有时效
压强（封闭空间气体量 → 压强）→ 蒸汽机核心参数：
  区域统计（连通空间内气体总量 → 压强 → 动力/爆炸）——与连通域标注同结构
```

## 7. 线程与架构映射

```
业务线程（BusinessWorld）：一切水/气状态机
  浅水模拟（活跃集）、连通重标、灌水动画、事件产生（BlockChangeEvent）
物理线程（PhysicsWorld）：只消费力
  浮力（查 isWater）、水流推力（current）、压强（ApplyForce）
  → 新增 PhysicsCommand：ApplyForce
渲染线程：增量重建（BlockChangeEvent 消费）+ 半透明 pass + 海面平面

不单开流体线程、不上 GPU 计算（理由见决策 #5）：
  流体要改方块 → 数据真源在业务线程 → 必须在业务线程
  GPU 回读（每 tick GPU→CPU）→ 渲染流水线停顿，致命伤
  GPU 只做视觉：海面 Gerstner 顶点动画（渲染层天然在 GPU）
```

## 8. 渲染距离规划（视觉层，与流体独立）

```
模拟圈：默认 12 chunks，上限 32（预算见 §4.2）
渲染圈：默认 128 chunks，最高 2048 chunks（LOD）

LOD 环带模型：
  每级覆盖距离环 [D, 2D]，分辨率减半 → 每级面数恒定 → 总面数 = 级数 × 每级预算（线性）
  级数 = log(最远/最近) ÷ log(级间比) = log₂(2048/32) = 6 级（或 3-6 级按 popping 容忍选）

三道前置：
  ① 远处必须有数据：1678 万 chunk 逐格 = 68.75GB → 必须 LOD 表示 + 无限世界生成器
  ② draw call 合批：每级 1 个大批次 mesh（不能每 chunk 一个 draw）
  ③ 远处不参与任何模拟（与模拟圈天然分离）

级间过渡（popping 隐藏税）：几何过渡（geomorphing）或淡入淡出（dither）
```

## 12. 2026-10-28 架构修订：合并版（浅水 + 活跃集 + 边界源）

> ⚠ **已过时**：本节基于"湖泊级海洋 + 封闭水体有限"假设，已被 **§14 最终定案**
> （三层原方案 + 全部无限）取代。保留作历史。

> 修订动因：玩法定案（大陆海洋型、海洋=湖泊级、水=原版档不作生存内容）后，
> 将原"隐式海洋 + 显式浅水"两层分离合并为**一套表示**，同时满足"简单流体物理 + 大面积水域"。

### 12.1 核心架构（一层，不是三层）

```
水位场（每列存 h；流速 u/v 仅活跃格）
  ├─ 稳态区（大面积水域）：不活跃 → 零计算（"是不是水"规则判定，等价隐式）
  ├─ 活跃区（边界/河流/扰动处）：浅水方程 → 算流动
  └─ 事件（挖/填/爆炸）：局部激活 → 模拟 → 收敛 → 自动回稳态
```

### 12.2 关键机制

```
① 浅水方程（SWE）：h + u/v + z_b，显式欧拉，CFL 天然满足（沿用 §3）
② 活跃集：只算"邻空气 + 有流速"格 → 大面积稳态自动零算（沿用 §4）
③ 收敛：扰动 → 重力拉平（"水永远在被拉平的路上"）→ 退出活跃集
   —— 大面积静态水域 = 已收敛稳态 = 成本≈0，这就是原"隐式"的能力，被浅水自带
④ 边界源：与海连通的模拟域边缘格 = 恒定水位源（h_sea 钳制）
   —— 复刻"无限水库"：坑灌水时边界自动补给，海面不下降、水不耗竭，加载区外零模拟
⑤ 事件驱动：挖/填/爆炸 → 局部激活 + 连通域重标（低频，不进 tick）
```

### 12.3 水的语义（定案）

```
存档级：无限（海洋 = 边界源，水位恒 h_sea）
封闭水体（玩家隔离，不与海连通）：有限（局部守恒，抽走就少）
玩法定位：水 = 原版档，不作生存内容，只作材料（水车/灌溉/运输）
可选旋钮：边界源补给率（限速）→ 灌坑/水位恢复有过程，最终仍无限
```

### 12.4 与原方案差异

| 维度 | 原两层 | 合并版 |
|---|---|---|
| 数据 | 隐式不存 + 显式存 | 全水域存 h（约 4B/列，12 chunks ≈ 320KB，无压力） |
| 计算 | 隐式 0 + 显式活跃集 | 活跃集（稳态自动零算） |
| 面积能力 | 无限（规则推导） | 大面积（稳态零算） |
| 流动物理 | 仅显式区 | 同一套全水域 |
| 边界规则 | 显式优先/水位钳制/出流 多条 | 边界源一条 |
| 代码 | 两套系统 | 一套系统 |

### 12.5 保留不变

```
渲染：半透明 pass（depthWrite OFF + blend）+ 海面平面 Gerstner/LOD（§5）
线程：业务线程（状态机/改方块）、物理只消费力、GPU 只视觉（§7）
气体：同构参数化（水/蒸汽/毒气/烟雾一套代码）（§6）
模拟圈 12/32、渲染圈 128/2048、LOD 3-6 级（§8）
落地路线：沿用 §9 阶段 0-4（增量重建 → 水状态机 → 浅水 → 边界源）
```

### 12.6 待定/后置

```
边界源补给率（限速旋钮）要不要：待定
湖泊级海洋的"本地水位" vs 全局 h_sea：随地形生成细节定（每水域连通器水位）
```

## 13. 行业先例与教训（2026-10-28 调研）

> 调研动因：验证"隐式大水体 + 活跃集"架构在成熟商业游戏中的可行性，并吸收
> flowing_fluids 模组（MC 物理水）的性能教训。结论：本架构各块均有成熟先例，
> "大面积全模拟"路线已被商业游戏证明必然卡。

### 13.1 正面样本（"隐式/静态零算 + 局部活跃"的行业实现）

| 游戏 | 实现机制 | 对应我们架构 |
|---|---|---|
| 深海迷航 Subnautica | 海洋本体非网格流体：海面渲染级（FFT/表面水），水下全局水体；建造/排水 = 局部水位事件 | 隐式海 + 视觉海面 + 局部模拟（最接近的组合） |
| 缺氧 Oxygen Not Included | 格子 element 模拟：每格存 mass，流动 = 邻格质量转移（水平扩散=(右mass−本mass)/4、垂直=重力、扩散趋平）；大片液体池仅边界/转移格计算，内部静止零算；cells/updatedCells 双数组 | 活跃集（最典型商业实现） |
| 矮人要塞 Dwarf Fortress | 流体三种移动规则：重力（下方不满 7/7 落）、扩散（邻格水位平均化）、压力（满水格上落水 → 追踪路径"传送"远距离非满格）；满水湖/海静态不计算，仅边缘/压力差格活跃；DFHack 有 make static 标记 | 静态水体零算 + 压力/边缘活跃格（"平均化找平"亦有） |
| 异星工厂 Factorio | 流体箱网络：连接管道/储罐视为单一容器（single vessel），网络内 level 均衡（=压力均衡），仅产/消设施推拉，内部零逐格模拟 | 连通器/隐式网络（"连通海水位齐平"的管道版） |
| 我的世界 / 泰拉瑞亚 | 方块状态 + 边缘 tick：大片 source 方块静态，仅边缘流动格更新 | 隐式大水体（方块版） |

### 13.2 反例：河狸计划 Timberborn

```
全模拟网格流体：每 tile 持续算速度/飞溅/水位/方向，无隐式、无活跃集。
代价：地图 65% 覆盖水即不可玩；300 人口掉到个位数 FPS；
     高落差瀑布每 tile 单独算，比整个工业区还吃 CPU。
结论：大面积全模拟在商业游戏里必然卡（与 flowing_fluids 同因）。
```

### 13.3 flowing_fluids 模组性能教训（mspt 原版 10 → 30，3 倍）

调研对象：github.com/Traben-0/flowing_fluids（MC 物理水，方块状态机 + 启发式流动，
本地源码 E:\MinecraftGame2\Allmd\开源参考\flowing_fluids-master）

```
① 每次流动 = 2 次 setBlock(flags=3)：源+目标各写一次，触发邻居更新/光照/网络同步全链
② deep spread search：平地最坏 160 侧向 + 40 向下 = 200 次检查/源格/tick（源码注释自认）
③ 随机 tick 全开：isRandomlyTicking() 恒 true → 每格水每 tick 概率检查 + 32 格随机找平搜索
④ "简单压力算法"实际是 BFS（深度 40/80）：每 tick new ArrayList/HashSet，GC 压力
⑤ tick 内附加查询：getFluidTicks().count() / getBiome() / getBrightness(SKY) / 监听器 Map
⑥ cascade 雪崩：大面积水体扰动 → 连锁更新（README 自认"快速排干海洋必然卡"）

单格流动成本 5-10 倍于原版 + 水体格本来就多 → mspt 3 倍。
```

### 13.4 教训 → 对策（我们的架构怎么避开）

```
模组的坑             →  我们的对策
tick 里深搜/BFS      →  浅水 = 固定 O(1) 邻居更新，不搜索
每格持续 tick        →  稳态冻结 + 活跃集，不活跃零计算
每流动 2 次方块写入  →  水位场 = 内存写入（~4B/列），不触发方块更新链
随机 tick 全开       →  事件驱动激活，无随机 tick
cascade 雪崩         →  隐式海零模拟，大面积水体根本不进模拟
```

### 13.5 结论

```
"隐式大水体 + 活跃集 + 局部浅水 + 视觉海面"各块均有成熟商业先例；
行业共识：大面积水体不做全模拟——要么静态零算（隐式）、要么局部活跃（活跃集）、
要么渲染级（海面）。本架构站在成熟实践肩膀上，性能验收线
（12 chunks 全海 <1ms/tick、32 <5ms）有据可依。
```

## 14. 最终定案（2026-10-28 拍板）

> 三个决策：① 基础流体 = 三层原方案（隐式海 + 显式浅水 + 边界源）
> ② 水的语义 = **全部无限** ③ 现实级海洋具体形态 = 先记方向、后置。
> 本节为当前唯一有效定案，取代 §12（合并版，已过时）。

### 14.1 架构：三层原方案（与 §0-§11 一致，确认）

```
层1 隐式海洋：h_sea + 连通规则，零数据零模拟（现实级海洋的必然）
层2 显式浅水区：水位场 h+u/v + 活跃集，河流/灌水/扰动
层3 事件边界：连通重标 + 边界源钳制 + 海绵吸收层
```

### 14.2 水的语义：全部无限（新定案，取代 §12.3 的"连通无限/封闭有限"）

```
所有水都无限：
  连通海的水域 → 边界源补平，排不干
  封闭水体（玩家隔离的池子）→ 也排不干（水不守恒为资源）
→ 水不是资源，不作生存内容（水=原版档），舀水/泵水/引水永不枯竭
→ "封闭=有限"的守恒逻辑不需要 → 架构更简单
（注：河流仍有流速/流向物理，只是"水量不会用完"）

海河永存（2026-10-28 补充，照搬 MC 无限水源思想）：
  海洋 = 隐式 h_sea（规则无限，永存）
  河流 = 源头源（生成标记恒水位，永不枯竭）
  设计意图：保证河流和海洋永远存在——玩家的引水/泵水/堵河/填海
  永远无法消灭一条河或一片海（水操作只改变局部，不消灭源头）
```

### 14.3 隐式海 ↔ 浅水交互（确认）

```
边界源：与海连通的模拟域边界格 = 恒定水位源（h_sea 钳制）
  双向自动：坑低→入流补满；坑高→出流排走；波动→吸收不回弹
加载区外水不模拟（边界源代表 = 无限水库）
封闭水池静态时用方块状态（不进浅水场），扰动才局部激活
```

### 14.4 河流（确认，机制全复用）

```
[源头源（生成标记恒水位）] — 浅水河道（梯度驱动流向/流速） — [入海口钳 h_sea]
稳态河流冻结（预计算水位/流速场），玩家扰动（堵/挖/改道）局部激活

高度差河流/瀑布（2026-10-28 确认，无需新机制）：
  高度差 = 浅水天然输入（z_b 底高程梯度驱动，缓坡/阶梯/山涧直接支持）
  瀑布 = 高处→低处质量转移（浅水边缘流）+ 落体视觉（粒子/泡沫，后置）
        + 底部冲击激活下游浅水（事件）
  持续瀑布 = 源头无限 + 底部流走 = 稳态冻结（高处流出 = 底部流出）
  实现注意（记方向）：落差点流速限幅防数值爆炸；落体视觉后置
```

### 14.5 海洋形态（方向已记，具体后置）

```
现实级海洋（不止湖泊级）：隐式海 + 海面平面视觉（Gerstner/LOD）+ 局部浅水
规模/深度/岛链/远海内容：随世界生成细节再定（§12.6 待定项一并后置）
```

```
§14 为唯一有效定案；§0 决策摘要同步更新
```
