## 0. 决策摘要

| # | 决策 | 理由 |
|---|---|---|
| 1 | 流体范式 = 网格流体（MC 式状态机 + 三态离散） | 体素世界要能改方块；粒子/求解器流体不做 |
| 2 | 海洋 = 规则水位（h_sea 标量 + 连通），不存数据不模拟 | 海洋 99% 时间静态；全模拟 CPU 账单巨大 |
| 3 | 加载区内 = 三态水位场，静水冻结零算 | 只算前沿，不算面积 |
| 4 | 未加载区 = 视觉（海面平面 + LOD） | 规模锁死，模拟圈 12–32 chunks |
| 5 | 模拟放业务线程，不单开线程、不上 GPU | 流体要改方块，数据真源在业务线程；GPU 回读致命 |
| 6 | 物理线程只消费"力"（ApplyForce） | 格子化归业务，力学归物理 |
| 7 | 气体 = 同构参数化（水/岩浆/蒸汽/毒气/烟雾一套代码） | 数学同构：重力反号 + 扩散项 |
| 8 | 水语义 = 源头无限、显式水体守恒、流动水永不转源 | 取之不尽 ≠ 自我复制，这是数值安全的分界 |
| 9 | 渲染 = 轮廓方、表面平滑；水深靠光/音判断 | 贴合方块世界，同时去掉台阶感 |
| 10 | 性能验收线：12 chunks 全海 < 1ms/tick，32 < 5ms | 活跃集后约 2% / 13.5% 单核 |

## 1. 水：三态离散

### 1.1 三态是调度属性，不是方块类型

```
整个世界只有"水"这一种方块，不存在"流动水方块 / 静态水方块"两种物品。
三态描述的是"这块水当前在做什么"，不是"它是哪种水"。

struct WaterCell {
    float depth;        // 水深，0..d_max
    bool  isSource;     // 是否恒定水位
    // 以下不存盘，仅运行时：
    bool  inFlowSet;    // 是否在调度队列里
}
```

| 状态 | depth | isSource | inFlowSet | 含义 |
|---|---|---|---|---|
| Source 源 | 恒定 | true | false | 水位由外部决定，不参与守恒 |
| Still 静水 | 固定 | false | **false** | 已不动，不进队列 |
| Flow 流水 | 变化中 | false | true | 正在被 tick |

```
"流动变静态" = inFlowSet 置 false，不改任何数据
"静态变源"   = isSource 置 true，只能由外部事件设置（生成/放置/实例化）

存档只存 depth + isSource；Still / Flow 是加载后按"地形 + 高差"重算的推论
收敛判定用滞回（hysteresis）：入队阈值 > 出队阈值，避免临界值抖动
```

### 1.2 源的三条来源

```
① 世界生成：海平面以下（h_sea 规则）、河流源头标记
② 玩家放置：水源方块（容器搬运，等同 MC 的桶）
③ 规则水实例化：h_sea 以下挖出空气时，边界格临时转源（见 §1.5，填满后撤销）

流水永不自动转源。MC 的"3×3 内两个源生新源"明确取消。
区分要点：③ 的源身份来自"它本来就是海"，不是由流水派生——数量有界。
代价：失去"两桶水造无限水"；收益：彻底关闭自动增殖入口。
```

### 1.3 流动判据：水位找平

```
η = z_b + d          （水面高程 = 底高程 + 水深）

每 tick 只处理 Flow：
  ① 向下：下格有余量 → 转移（垂直下落不衰减），量受下格剩余容量限制
  ② 水平：向 η 最低的邻居转移，量 ∝ 高差，受容量与单 tick 上限双重钳制
  ③ 收敛：所有邻居 η 不低于本格，或本格已满 → 转 Still，退出队列
  ④ 任何邻居变化（方块增删 / 上游来水变化）→ 重新入队
```

```
"灌满即停"是 ③ 的自然结果，不需要额外机制：
  池子填到 η = η_source → 高差为零 → 转移为零 → Still
```

### 1.4 耗散：薄水层统一（不做渗透性材质）

```
d < d_min → 不进 Flow，不水平扩散，按 k_seep 递减直至消失
```

```
为什么必须有：
  守恒系统没有摩擦，单个源在平地上会一直摊薄到铺满整个平面（数值无界）。
  MC 的"水平 7 格上限"本质就是这个耗散项的粗糙替代。

为什么不挂材质：
  决定性条件是水深，不是材质。深水（河/湖/池）d 远大于 d_min，永不渗漏；
  薄水层已经流不动，剩下的只有蒸发/渗入，统一速率即可。
  代价：失去"沙地漏水、石头存水"的材质差异。
  扩展口：将来需要时 k_local = k_seep × material_factor(block)，查方块类型，不新增数据。

耗散中的薄水层仍在变化，不能冻结 → 进"耗散集"，降频处理（每 4 tick 一次）。
活跃列爆预算时降级：薄到 d_min 直接删除（一次性），用粒子掩盖突兀。
```

### 1.5 规则水 ↔ 显式水的转换

> 触发场景：海底炸坑、海岸边挖坑（坑底低于 h_sea）、挖穿海堤，以及任何让
> "按规则有水"的格变成空气、并给水提供了新去处的操作。

```
① 判定：新空气格满足 y < h_sea 且与海连通 → 标为"待灌水"
   （h_sea 以上的封闭洞穴不触发，坑保持干燥）
② 边界实例化：坑/洞边缘原本属于规则水的格，转为显式 Source（临时）
   源的身份来自"它本来就是海"，不是由流水派生
③ 注水：每个临时源按 Q_source 转移，坑内是 Flow，按找平填充
   海底坑从上方灌；海岸坑从侧壁灌，机制相同
④ 填满：坑内水位 = h_sea 且与邻居齐平 → 撤销显式数据，整片交回规则水
```

```
与"流水永不转源"不冲突：
  禁止 = 由流动水派生新源（会无限增殖）
  允许 = 原本就是海的格被实例化（数量 = 边界格数，有界）

数值安全：
  单次实例化水量 ≤ 坑容量（有界）；总量上界 = Σ 显式水体容量
  炸穿到虚空的坑 → 需要"深渊吸收"边界（流出加载区即消失）

速度：填满时间 = 坑容量 / (边界源数 × Q_source)
      边界很长（几百格）时，用"每连通水体总流量预算"，防止一 tick 灌爆
```

### 1.6 "无限"的准确语义

```
① 海是规则水位，不是一池水：舀走一桶，下一帧查询仍是水（h 是推出来的，不存储）
   → 零成本，也舀不干
② 显式水体严格守恒：河/池/玩家倒出的水只互相转移，不凭空增减
③ 唯一的"总量增长"路径：玩家从规则海取水 → 倒进显式区
   受玩家操作速度限制，不是每 tick 自动增长
④ "水源无限" = 取之不尽，≠ 自我复制。两者必须分开
```

### 1.7 数值上界

| 上界 | 作用 |
|---|---|
| d_max 单格水深上限 | 源只补到这个高度，不无限堆 |
| 单格单 tick 转移上限 | 渠道再陡也有流量上限 |
| 活跃列上限 | 超预算 → 降频 / 冻结 / 平均水位近似 |

```
W ≤ Σ(源格 d_max·Δx²) + W_显式水体
源数有界 + 水深有界 → 总水量有界
```

### 1.8 渲染：轮廓方、表面平滑

| 面 | 做法 |
|---|---|
| 顶面（水面） | 每格一个 quad；顶点高度取周围水格 h 均值 → 格间连成斜面 |
| 与水岸交界 | 顶点取本格 h，不参与平均 → 贴住方块，不穿墙 |
| 侧面 | 保持方块边缘；岸边水墙、落差水帘 |
| 大水体远景 | LOD 平滑网格 + Gerstner 波 |
| 瀑布 | 单独竖直面 + 流动纹理 + 粒子，不参与插值 |
| 极浅水 | 单独处理，防 z-fighting（深度冲突） |

```
"平滑"描述的是高度场，不是轮廓。外轮廓跟方块走，因为地形是方的。
稳态水面是平的；斜面只出现在流动/未平衡状态。
水深不靠视觉台阶判断：靠水下光照衰减 + 水下音效（低频/气泡）+ 屏幕水痕。
管线：1 render pass + 2 pipeline（opaque 先画，translucent 后画、远→近）。
```

### 1.9 物理接口：只出三种力

| 作用 | 实现 |
|---|---|
| 浮力 | 体积排水查表 → 在浮心施力 |
| 水阻 | 阻力系数 × 速度² |
| 推力 | 某格有流速 → 对接触 body 施力 |

```
水永不进入物理求解器。
气室 = 独立标量 waterVolume + 事件驱动 flood fill（见 §2），与水位场解耦。
巨体入水：浮力查表 + 一次性排水结算；底面积 > 128×128 必须降级为事件。
```

### 1.10 河流：永久 Flow

```
源（Source 恒水位）— 河床梯度（地形凹槽）— 入海口（钳制 h_sea）
河道不是画出来的，是地形给出来的：平地会摊开成片，不该有窄河。
```

| 对比 | 静水 | 河流 |
|---|---|---|
| 高差 | 零 | 恒存 |
| 状态 | Still，零算 | 永久 Flow |
| 成本 | 0 | 河道长度 × 宽度 |
| 能否冻结 | 能 | 只能冻水位，不能停流量 |

```
成本：一条横穿 12 chunks 的河（长 384、宽 4）≈ 1,536 格，
      相对约 1.6 万活跃列预算 ≈ 9%；三条河加分支 ≈ 30%，仍在预算内。
      需要"河道活跃带上限"，不允许无限分支同时算。

三个补丁：
① 源头单 tick 最大输出 → 流量有上界
② 稳态水位预计算：生成时按"源头水位 + 地形"解一次，运行时只跑流量平移
③ 河床默认不透水（石/黏土），避免河流被耗散吃掉

水车与推实体不需要 u/v：
  流量 = 每 tick 转移量；方向 = 最低邻居方向；近似流速 = 流量 / 截面积
→ 落差或流量驱动水车、按方向施力推实体都够用。
u/v（动量）只在需要惯性/漩涡/回流时才升级（可选，非必须）。
```

### 1.11 性能

```
海洋：规则水，模拟 0，只进查询与渲染
静水：零计算
流水：活跃格 ≈ 流动前沿长度（不是水体面积）
河流：河道带（永久付费）
内存：约 4B/列；12 chunks ≈ 320KB，32 chunks ≈ 2.2MB
12 chunks 全海活跃集 ≈ 2% 单核；32 chunks ≈ 13.5%
现实级海洋只影响渲染视距，不影响模拟量
渲染圈：默认 128 chunks，最高 2048；LOD 3–6 级环带
```

### 1.12 待定参数

| 参数 | 含义 | 建议起点 |
|---|---|---|
| d_max | 单格水深上限 | 8/8（对齐方块尺度） |
| d_min | 最小流动水深 | 1/8 |

| Q_source | 源单 tick 最大输出 | 按"池子 10–30 秒灌满"反推 |

### 1.13 水体分组与加载生命周期

> chunk 是存储单位，**水体（group）才是逻辑单位**：连通性跨 chunk，
> 找平必须在组的边界上判，不能只在 chunk 边界上判。

```
WaterBody { id, kind, levelHint, bounds, active }
kind：Sea / River / Closed / Temp
```

| kind | 成员来源 | 存储 |
|---|---|---|
| Sea 海 | **规则函数**：y < h_sea 且连通且已加载 | 无成员列表，零存储 |
| River / Closed / Temp | 显式列段列表 | 9 B/段 + 8 B/成员引用 |

```
海也是 group，但不是"有成员列表的 group"：
  统一在虚函数分派（contains / level / tick），差异在成员来源。
  若给海建成员表：12 chunks 内 80,128 列 × ~17B ≈ 1.4MB 冗余，
  且 yTo 恒等于 h_sea —— 等于把规则抄一遍，还要维护一致性。

SeaBody::contains 必须带 loaded(x, z)：
  海是全局的，模拟圈只覆盖一部分；不判断加载会访问无数据的列。
  "按范围加载"对所有 group 统一生效，不是给海的特殊分支。
```

```
四个生命周期事件：
  创建：挖坑灌水 / 玩家倒水                  O(新段数)
  合并：打通隔墙                            O(1)（只比对破口两侧 bodyId → union）
  分裂：填死水体中的一段（玩家低频）          O(局部 BFS)
  销毁：抽干 / 蒸发完                        O(成员数)

合并 O(1) 是关键：每次挖穿只查破口两侧的 id，不做全局 BFS。
```

```
加载：chunk 读入 → 与四邻的相邻段做局部连通检测 → union 到已有 body 或新建
卸载：从 members 移除该 chunk 的段；段数据落盘
      （yFrom / yTo 是绝对坐标，重载即恢复）
      body 空了 → 销毁（Sea 永不销毁）
水位不需要额外快照：段的绝对 yTo 本身就是持久化水位
```

```
按范围加载（模拟圈 12 / 32 chunks）：
  圈内：body.active = true，参与 tick
  圈外：active = false，只保留渲染水位
  跨界：圈内部分正常模拟，圈边界按 kind 处理
       Sea    → 边界钳制 h_sea（规则水无限，不参与守恒）
       Closed → 边界视为固壁（冻结，不解算）
  重新进入模拟圈：做一次局部平衡（事件），水位可能小幅跳变
```

```
局部改造海（实例化的反向）：
  海底封死一片 → 不再满足连通 → 从 Sea 判定中切出 → 新建 VolumeBody
  天然支持，不需要给海写额外分支。
```

## 2. 气室与浮力（后置设计）

> 定位：船/潜艇是**模组内容**，但"能不能浮、密封怎么判、进水怎么算"是**引擎原语**。
> 状态：设计记录，**不实现**（流体整体后置到 1.0 之后）。

### 2.1 格模型表达不了气室，禁止 3D 流体

```
每列只有一个 depth，而气室要求"同一列上舱内水位与舱外水位不同"。
这不是精度问题，是维度问题。

禁止为此引入 3D 体素流体（维度爆炸），理由三条：
  性能：O(N³)，比 2D 高度场高一个维度，只换来"舱内水位"一件事
  玩法：3D 流体行为不可预判（涌流/漩涡/气泡），违反"局部化、可预判、直接结算"
  受众：复杂度是受众的除数，每多一个"必须理解才能玩"的概念就少一批人
降维原则：能降维就降维（3D 体积 → 2D 高度场 → 标量）；降不了的那件事就不做。
```

### 2.2 密封判定：flood fill（推荐）

| 方案 | 做法 | 成本 | 自由度 |
|---|---|---|---|
| A 显式气密方块 | 只看方块类型 | ≈0 | 低（造型受限） |
| **B flood fill** | 破口处 BFS：能否走到外界？到不了 = 密封 | O(舱体积)，**仅方块变更时触发** | 高 |
| C 3D 流体 | 共用 3D 流体场 | 极高 | 最高 |

```
推荐 B：事件驱动、局部 BFS 到外界即停，且天然产出"破口位置"，正好喂给 2.4 进水。
```

### 2.3 浮力：精度不是关键，"浮心 ≠ 质心"才是

| 档 | 做法 | 代价 |
|---|---|---|
| 粗 | body AABB × 水位 → 淹没比例 | 最便宜，异形船会怪 |
| 中 | 逐方块判水下 → 累加体积 | 每 body 每 tick 遍历方块 |
| 精 | 逐方块 + 部分淹没（水面切过方块） | 最贵，吃水线精确 |

```
巨物不能用"逐方块"：构建时预计算排水体积曲线 V(d) 与浮心，运行时 O(1) 查表；
方块破坏 → 标记脏，增量重算受影响层。

关键：浮力作用点在浮心（体积中心），不是质心。两者不重合产生力矩——
这才是船会扶正、会侧倾的原因。只在质心施力 → 船永远不翻也不扶正，一眼假。
Jolt 侧用"在世界点施加力/冲量"的接口（ApplyImpulseAtPosition 一类）。
```

### 2.4 进水：标量涌水量，与水位场解耦

```
每个气室 = 一个标量 waterVolume
进水速率 = 破口面积 × 压差 × 系数
每 tick：waterVolume += 进水速率 × dt
浮力 = (气室体积 − waterVolume) + 实心方块排水
waterVolume 满 → 该舱失效（浮力归零、质量增加）

成本 O(气室数)，与水位场完全解耦；视觉：破口冒泡 + 逐渐下沉（不需要真水体）。
与 From the Depths 同款做法。
⚠️ 这是"维度爆炸"的唯一入口：一旦让水位场参与舱内水位，就等于做 3D 流体。明确不做。
```

### 2.5 职责分工

| 层 | 谁做 | 内容 |
|---|---|---|
| 引擎原语 | 官方 | 浮力（体积/密度/浮心）、气室（密封判定）、水位场（三态离散，§1） |
| 官方包 | 官方 | 水车、水闸、一个"能浮起来的东西"（不必是潜艇） |

### 2.6 船 = 物理船（2026-11-25 定案）

```
结论：物理船，不为船单独实现实体类型。
船 = 普通结构刚体 + 浮力原语，与"结构物理化"共用同一套原语；
省掉原版船那套专用逻辑（坐上后 WASD 直接控速度、自动漂浮、专用碰撞）。

连带约束：
- 船体 = 复合刚体（方块集合 → compound shape），与其它结构无差别
- 运动 = 浮力 + 推进力（业务侧发 ApplyForce），玩家控制"力与舵角"，不是"速度"
- 气室/进水原语保留，但只在船真正落地时才实现（仍在 1.0 之后）
- 两个难点（记方向，不实现）：
  ① 玩家站船上要随船移动——玩家是 kinematic 体，吃不到船的接触力，需要附着/父子变换
  ② WASD → 推进力的映射与手感需单独调
```

## 3. 气体：同构参数化

```
隐式海洋（h_sea）→ 隐式大气 = Air 方块（世界本来就有，0 成本）
显式水位场 → 显式气体区（浓度 + 流速）
连通规则 → 同构（有气 = 连通到源头）
吸收层 → 扩散边界（气体出界自然消散）
```

```
动量方程同构：
  水  ：∂u/∂t = -g·∇(h+z_b)          （重力向下）
  气体：∂u/∂t = +g_eff·∇ρ − κ∇ρ      （浮力向上 + 扩散项）

| 类型 | 密度 | 重力方向 | 扩散 | 消散 | 玩法 |
|---|---|---|---|---|---|
| Water | 高 | 下 | ≈0 | 否 | 灌溉/水车/运输 |
| Lava  | 高 | 下 | ≈0 | 否 | 燃烧/地形 |
| Steam | 低 | 上 | 中 | 缓慢 | 蒸汽机核心 |
| Gas   | 低 | 上 | 强 | 快 | 浓度阈值引爆 |
| Smoke | 低 | 上 | 强 | 快 | 遮蔽视野 |
```

```
压强 = 气体玩法核心：连通空间内气体总量 → 压强 → 动力/爆炸。
用与连通域标注同结构实现（区域统计，不是逐格压力）。
```

## 4. 行业依据与教训

### 4.1 正面样本

| 游戏 | 实现 | 对应我们的做法 |
|---|---|---|
| 深海迷航 | 海洋本体非网格：海面渲染级 + 全局水体；建造/排水 = 局部水位事件 | 规则海 + 视觉海面 + 局部模拟 |
| 缺氧 | 格子 element：每格 mass，流动 = 邻格转移；静止池内部零算，cells/updatedCells 双数组 | 活跃集 |
| 矮人要塞 | 满水湖/海静态不算，仅边缘与压力差格活跃 | 静水冻结 |
| 异星工厂 | 管道/储罐视为单一容器，网络内均衡 | 连通器、水位齐平 |
| MC / 泰拉瑞亚 | 方块状态 + 边缘 tick，大片 source 静态 | 隐式大水体（方块版） |

### 4.2 反例

```
Timberborn：全模拟网格，无隐式、无活跃集
→ 地图 65% 水覆盖即不可玩；300 人口掉到个位数 FPS；瀑布比整个工业区还吃 CPU。
```

```
flowing_fluids 模组：mspt 从 10 → 30（3 倍）
① 每次流动 2 次 setBlock（触发邻居更新/光照/网络同步全链）
② deep spread search：平地最坏 200 次检查/源格/tick
③ 随机 tick 全开
④ "简单压力算法"实际是 BFS（深度 40/80），每 tick 新建容器 → GC 压力
⑤ tick 内附加查询（getFluidTicks / getBiome / getBrightness）
⑥ cascade 雪崩（大水体扰动连锁更新）
```

| 模组踩的坑 | 我们的对策 |
|---|---|
| tick 里深搜/BFS | 固定 O(1) 邻居更新，不搜索 |
| 每格持续 tick | 静水冻结 + 活跃集 |
| 每次流动改方块 | 水位是独立内存场（约 4B/列），不触发方块更新链 |
| 随机 tick 全开 | 事件驱动激活 |
| cascade 雪崩 | 规则海零模拟，大面积水体根本不进模拟 |

## 6. 落地路线

> 流体整体后置到 **1.0 之后**。以下是实现顺序，不是当前任务。

```
前置（与流体无关，但要先有）：
  增量重建 → chunk 加载/卸载 + 世界生成器（流体、存档、LOD 的共同地基）

  规则海 + 三态 + 找平 + 薄水层耗散 + 半透明渲染 + 落差水车

阶段 1：规则水实例化
  海底/海岸挖坑自动灌水 + 填满撤销 + 深渊吸收
  验收：挖开海岸坑灌到海平面；封闭洞穴保持干燥

阶段 2：河流与流动性
  河流稳态预计算 + 流量 / 方向 / 近似流速 + 推实体

  flood fill 密封 + 排水体积查表 + 标量 waterVolume
  验收：一个能浮起来的东西（不必是潜艇）

阶段 4：扩展
  泵/管道、洪水/潮汐、蒸汽/气体、巨体入水
```
