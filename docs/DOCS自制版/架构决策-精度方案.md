日期：2026-10-26
关联：`流体与气体系统设计.md`（世界尺度规划）、`架构决策-面剔除与重构时机.md`

## 决策

**精度墙由渲染线程在底层直接解决（origin rebasing，相机原点重定位），不加新的层。**

```
实现位置：渲染线程，VulkanContext.cpp MVP 计算处（约 932 行附近）
  现在：worldOffset(int→float) + camPos(double→float) → 直接进 MVP（float 全程）
  改为：local = 方块世界坐标(double) − camPos(double) → float(local) → MVP
       （float 只吃"相对相机的偏移"，永远无损）

不加新层：不做 WorldProvider 包装、不加中间抽象（现在不需要）
  → 直接改渲染底层；将来世界类型分化时，再谈 provider/模组化
```

## 背景（三层坐标体系，保持不动）

| 层 | 类型 | 职责 |
|---|---|---|
| 逻辑方块 | int（BlockPos） | 离散寻址（现状已够 21.47 亿格） |
| 相机/实体 | double（CameraState） | 世界定位（已达标） |
| 渲染顶点 | float（局部坐标） | 吃相对相机的小量（待改 MVP 一处） |

## 依据（为什么这个方案成立）

```
float 相对精度 2^-23 ≈ 1.19e-7：
  |local| < 0.01 × 2^24 ≈ 16.7 万格 → 1 厘米精度无损
  可视距离 2048 格 → 余量 80 倍；每帧重算差值，误差不累积

判断：凡是 float 计算绝对大坐标处都要处理（渲染/物理/生成）；
      double/int64 绝对坐标处天然安全（逻辑/存档/协议）。
```

## 范围（本次只做渲染）

| 存档/协议 | ❌ | 永不动（绝对坐标天然正确） |

## 验收

```
1. 世界坐标任意大时，画面仍 1 厘米精度对齐（可用大偏移验证：临时把方块世界坐标 +1 亿，画面不变）
2. 相机移动/旋转无抖动、无漂移（误差不累积）
3. 现有行为不变（16×16 平台、面剔除验收值不变）
```
