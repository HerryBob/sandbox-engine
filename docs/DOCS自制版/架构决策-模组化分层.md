# 架构决策 · 模组化分层

> **状态**：设计定案（2026-11-16），未实现。
> **定位**：本文回答三个问题——**引擎保留什么 / 内容怎么外置 / API 分几层**。
> 上游：《模组自由度与责任边界.md》《架构决策-注册表机制.md》《玩法-减法清单.md》§八。

---

## 0. 决策摘要

```
① 机制内置，内容全外置；中间态 = 机制内置 + 参数外置
② 物品实例走"引擎当宿主、模组当定义者"（A：不透明数据 + C：行为钩子）
③ UI 分五层，1.0 只做 L0（纹理）+ L1（数据）
④ API 分两层：公开（长期维护）+ 特权（不保证）；第三层"野生 hook：不承认、不阻止"
⑤ 特权 ≠ 无约束：仍受线程与单一写者纪律约束
```

---

## 1. 总原则：机制 vs 内容

### 三追问判据

| 追问 | 归引擎 | 归模组 |
|---|---|---|
| ① 它是"怎么运作"还是"做什么"？ | 怎么运作（机制） | 做什么（内容） |
| ② 它需要每帧 / 每方块执行吗？ | 是（热点） | 否（低频） |
| ③ 没有它，其它模组还能工作吗？ | 不能（基础设施） | 能（可选内容） |

三条都过 → 内置；有一条不过 → 外置。

## 2. 引擎保留清单（13 项，三类）

### A. 机制

| # | 内容 |

| 7 | 数据加载（JSON / 资源索引 / 模型烘焙） |
| 8 | 存档（格式 / IO / 迁移） |

## 4. 中间态：机制内置 + 参数外置

| 系统 | 内置的机制 | 外置的参数 |
|---|---|---|
| 风场 | 采样、插值、脏区重算 | 主风线方向、强度曲线、噪声频率 |
| 流体 | 浅水求解、活跃集 | 黏度、蒸发率、水位上限 |
| 旋转网络 | 拓扑遍历、传播、过载判定 | RPM 上限、应力数值、传动比 |
| 生物 AI | 行为树执行器、寻路 | 行为节点组合、参数、触发条件 |
| **生物动画（步态）** | IK 求解、相位传播、脚目标规划（状态机/阈值）、K 帧播放器 | 腿数、骨骼映射、相位差、波速、步幅、抬脚高度、扭转阈值 |

> 玩家看到的"引擎能力"= 机制 + 数据。模组换数据就能做出完全不同的风/流体/机械。

## 5. 物品实例的模组化

### 核心分工

| 引擎负责 | 模组负责 |
|---|---|
| 存储实例数据（一包 bytes） | 决定 bytes 里是什么 |
| 序列化 / 反序列化 | 格式版本、迁移逻辑 |
| 跨线程 / 跨机同步 | 哪些字段要同步 |
| 在 UI 上占一格 | 图标、名字、tooltip 文本 |
| 触发事件（使用/攻击/合成/破坏） | 事件发生时做什么 |

### 四个档位

| 档 | 引擎提供 | 成本 | 建议 |
|---|---|---|---|
| **A. 不透明数据** | `{type, count, blob}`，引擎不解析 | 低 | **1.x 起步** |
| **B. 组件化** | 注册组件类型 + schema，按 key 存取 | 中 | **2.0**（跨模组协作前提） |
| **C. 行为钩子** | `onUse / onAttack / onCraft / onTick` | 中 | **1.x 与 A 同做** |
| **D. 脚本 VM** | 内嵌 Lua/JS | 极高 | ❌ 不做 |

### 三条边界

| 边界 | 规定 |
|---|---|
| **命名空间** | 只能写自己 namespace 的 key（`mymod:charge`） |
| **大小上限** | 每实例 blob ≤ **256 bytes**（无上限 = NBT 膨胀 + 同步卡顿） |
| **数据不可执行** | blob 只是数据，行为只能来自注册回调；**绝不从数据读函数指针** |

### 两个必然代价

- **dupe 风险回归**：实例 + 位置 + 同步 → 需服务端权威 + 原子转移
- **同步带宽**：只在 blob 变化时同步（dirty 标记）

## 6. UI 的模组化（五层）

| 层 | 模组能做 | 成本 | 何时 |
|---|---|---|---|
| **L0 纹理替换** | 图标、边框、九宫格 | 低 | **1.0** |
| **L1 数据驱动** | 配方、tooltip、分类 | 低 | **1.0** |
| **L2 自定义面板** | `registerScreen` + 原语 | 中 | 1.x |
| **L3 主题/皮肤** | 换色板、换九宫格、换字体 | 中 | 1.x |
| **L4 重排官方 UI** | 布局描述文件 | 高 | 2.0 或不做 |

### 关键原则

> **官方 UI 必须跑在同一套 `ui_*` 原语上。**
> 如果官方用私有接口、模组用另一套，模组永远做不出同等质量 —— 也就验证不了 API 够不够用。

### 三个坑

| 坑 | 对策 |
|---|---|
| 模组 UI 崩溃带走进程 | ABI 边界加 SEH，出错禁用该 screen |
| 输入焦点混乱 | 显式"模态栈"：最上层独占输入 |
| 版本兼容 | 结构体末尾追加 + 传 `size` |

## 7. API 分两层（+ 第三层）

### 逐项对比

| 维度 | 公开 API | 特权 API |
|---|---|---|
| 版本 | 追加式演进（v3→v5），**长期维护** | 每版可能变，**不承诺** |
| ABI | 结构体带 `size`、函数表版本化 | 可直接暴露内部结构体/指针 |
| 安全性 | 崩溃隔离、线程约束强制 | **不保证** |
| 文档 | 完整 + 示例 | "能看源码就能用" |
| 适用 | 99% 的模组 | 深度改造、移植、实验 |
| 失败后果 | 模组被禁用，游戏继续 | **可能带走整个进程** |

### 特权 API 的四个决定

| # | 决定 | 建议 |
|---|---|---|
| ① | 暴露什么 | **函数表**（`EngineInternal_v1*`），不是头文件 |
| ② | 怎么标记 | manifest `"requires": ["privileged"]` + **启动日志警告** |
| ③ | 版本不匹配 | **警告后加载**（严格拒绝会断一片模组） |
| ④ | 安全边界 | **仍守线程与单一写者** —— 特权 ≠ 无约束 |

### 第三层：野生 hook

| 层 | 态度 | 文档措辞 |
|---|---|---|
| L1 公开 API | 支持 | "保证兼容，出问题算我们的" |
| L2 特权 API | 容忍 | "能做但不保证；崩了算你的" |
| **L3 野生 hook** | **不承认、不阻止、不帮助** | "你可以 hook，但我们不为它改设计，也不接受相关 bug 报告" |

> 明确写下 L3，能减少绝大多数扯皮。

### 联机冲突（必须提前定）

> **特权 API 能改内存 = 能作弊。**

| 场景 | 规定 |
|---|---|
| 单机 | 允许 L2 |
| 联机 | **禁用 L2**，或由服务器校验模组白名单 |

因为联机计划在后（1.0 之后），这个开关**从设计第一天就要在**（一个 `isMultiplayer` 决定是否暴露 L2），后加会很痛。

## 8. 为什么不能只靠 hook（C++ 的 mixin 等价物）

DLL **能**实现 mixin 等价物（运行时 hook）：

| 方式 | 用途 |
|---|---|
| IAT hook | 改导入表（ReShade 式） |
| Inline hook | 函数头写 `jmp`（Detours 式） |
| Vtable hook | 替换虚表项 |
| 数据段补丁 | 改全局变量 |

**但不可依赖**：

| 问题 | 表现 |
|---|---|
| 符号不稳定 | 内联 / 头文件实现 / LTCG 会把函数消掉 |
| 偏移不稳定 | 每次重编都变 |
| 优化等级相关 | Debug 能 hook，Release 被优化掉 |
| 时序相关 | 多线程下可能错过调用窗口 |
| UB | 出问题无法归因 |
| 杀软/反作弊 | IAT/inline hook 是典型恶意特征 |

> **hook 是"能跑一次"，不是"能维护"。**

**一个重要的既成事实**：MC 生态本来就是两层结构 —— 公开 API（有兼容承诺）+ Mixin/AccessTransformer（不保证）。本设计只是**把这个不成文的默契显式化**。

## 9. 参考清单

### 值得学（NeoForge / Fabric → 落法）

| 概念 | 学什么 | 落法 |
|---|---|---|
| 事件总线分层（mod bus / game bus） | 生命周期 vs 运行期事件分开 | 两组事件表 |
| 可取消事件 | 规则能拦截意图 | 显式返回值 / out 参数 |
| 能力/组件查找（`Capabilities`） | 按**接口名**跨模组查找 | 命名接口 + 提供者注册 |
| `DeferredRegister` | 注册分"收集期/冻结期" | 复用 `Registry::frozen_` |
| DataPack 目录结构 | `data/<ns>/...` 约定 | 已有 `data/`，写进模组文档 |
| `StreamCodec` / payload 注册 | 协议包显式注册 + 版本 | 协议包结构 + 版本校验 |
| `ModConfigSpec` | 每次读都走接口（支持重载） | `getConfig(ns, key)`，禁止全局变量 |
| DataGen | 从代码生成数据文件 | 后置，预留 |

### 明确跳过

| 跳过 | 原因 |
|---|---|
| Mixin / ASM / 字节码转换 | C++ 无等价物 + 安全隐患 |
| AccessTransformer | Java 可见性机制特有 |
| ClassLoader 隔离 | C++ 用 DLL 隔离，机制不同 |
| 注解扫描 / 反射注册 | C++ 无反射，注册必须显式调用 |

### C ABI 的补充参考（比 NeoForge 更贴近你）

| 参考 | 学什么 |
|---|---|
| **Vulkan loader** | 函数指针表 + `apiVersion` + `sType/pNext`（追加式 ABI 教科书） |
| ImGui | immediate mode context + 绘制原语 |
| Lua C API / SQLite | 栈式接口 / `size` 参数传入结构体 |

> 建议把 v3→v5 的"末尾追加"升级成 **`sType/pNext` 模式**，兼容性更强。

## 10. API 设计检查清单（review 用）

| # | 问题 | 不过关的后果 |
|---|---|---|
| 1 | 每个扩展点都有事件，还是只有"注册"？ | 模组只能加内容，不能改行为 |
| 2 | 事件有优先级和可取消吗？ | 规则模组没法拦截 |
| 3 | 跨模组交互走名字还是具体类型？ | 两个模组互相不认 |
| 4 | 结构体都有 `size` 字段吗？ | 加字段就断兼容 |
| 5 | 有崩溃隔离（SEH）吗？ | 一个模组崩带走全游戏 |
| 6 | 官方包是否只用公开 API？ | 第三方永远追不上 |
| 7 | 有数据生成路径吗？ | 模组作者手写 JSON 易错 |

第 1、3 条最容易漏，也最伤生态。
