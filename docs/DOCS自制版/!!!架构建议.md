任务：新建一个集中式平台契约校验层，把项目对平台/编译器/标准库的硬性假设
收敛到单个头文件，所有 TU 编译时统一检查；同时把现有散落在各文件里的
static_assert 迁移进来，避免重复和不一致。

一、新建文件 core/PlatformContract.hpp

内容为一个纯头文件（#pragma once），只包含编译期校验，无运行时代码。至少包含：

  #pragma once
  #include <atomic>
  #include <cstddef>
  #include <cstdint>
  #include <limits>

  // ── C++ 标准 ──
  static_assert(__cplusplus >= 202002L, "requires C++20");

  // ── 位宽 ──
  static_assert(sizeof(void*) == 8, "requires 64-bit platform");
  static_assert(sizeof(std::size_t) == 8, "requires 64-bit size_t");

  // ── 浮点 ──
  static_assert(std::numeric_limits<double>::is_iec559, "requires IEEE 754 double");
  static_assert(sizeof(double) == 8, "requires 64-bit double");

  // ── 原子类型 lock-free ──
  static_assert(std::atomic<double>::is_always_lock_free,
                "atomic<double> must be lock-free (TimeManager/CameraState/PlayerControlState)");
  static_assert(std::atomic<std::uint64_t>::is_always_lock_free,
                "atomic<uint64_t> must be lock-free");

  // ── 平台标志 ──
  #if !defined(_WIN32) && !defined(__linux__) && !defined(__APPLE__)
  #  error "unsupported platform"
  #endif

用 namespace 可加可不加（纯 static_assert 放全局也行，但建议包一层
engine::core::platform 以免污染）。

二、保证被所有 TU 包含（关键，否则校验形同虚设）

按项目实际情况选一种：
  A) 若项目有预编译头（PCH）→ 把 PlatformContract.hpp 加进 PCH
  B) 若无 PCH → 新建或复用 core/Base.hpp，让它 #include "core/PlatformContract.hpp"，
     并要求所有 .cpp 的第一行 include core/Base.hpp（或通过某个所有模块都包含的
     基础头文件传递）
禁止“部分文件 include、部分不 include”的状态。

三、迁移现有 static_assert

  - TimeManager.hpp：删除类内的 static_assert(std::atomic<double>::is_always_lock_free, ...)，
    改为在类上方加一行注释：
    // 平台契约（atomic<double> lock-free 等）见 core/PlatformContract.hpp
  - CameraState.hpp / PlayerControlState.hpp：本来没有 static_assert，
    只在结构体上方加同样的注释指引即可。
  - 其余文件若出现同类平台假设（atomic<int> lock-free、64 位指针宽度等），
    一并迁移，不在使用点重复写。

四、不迁移的项（明确排除）

  - atomic<std::shared_ptr<T>>（Log.cpp 的 g_logger）：该特化没有 is_always_lock_free 成员，
    无法 static_assert。保持原样（运行时 is_lock_free() 检查 + 降级，或直接接受）。
    可在 PlatformContract 里加注释说明“shared_ptr 原子特化不在编译期校验范围”。

!!! 注意: 需要根据引擎项目内现有的来改造 不要写入引擎没有的内容
五、验证

  1. 临时把任意一条 static_assert 改成 false，编译整个项目——
     确认每一个 .cpp 都报错（不是只有部分）。若有 TU 不报错，说明该 TU 没 include，
     回头补包含链。
  2. 改回 true，编译通过。
  3. 全项目搜索 "is_always_lock_free"，确认只剩 PlatformContract.hpp 一处
     （使用点只留注释指引）。
  4. 若项目有测试，跑一遍确认无回归。

六、输出

  - 新增文件路径与内容
  - 改动的文件列表（TimeManager / CameraState / PlayerControlState 的注释替换）
  - 包含链如何保证（PCH 或 Base.hpp 的具体做法）
  - 验证结果（真·全 TU 报错？搜索剩几处？）
