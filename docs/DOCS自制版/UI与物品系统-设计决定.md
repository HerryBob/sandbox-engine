# UI 与物品系统 · 设计决定（2026-11-27 夜）

## 1. UI 美术：整张图 + 程序高亮

| 决定 | 理由 |
|---|---|
| 每个界面**一张 PNG**（整图），不做九宫格拆件 | 替换界面时只换文件 → 模组化最省事 |
| 高亮 / 命中 / 槽位**全部由程序画** | 美术图不必画选中态，换皮不用重画 |
| 每张图**单独一份布局表**（`business/ui/UiLayouts.hpp`）| "单独为每张图专门做处理"；换图只改表里的数字 |

已实测（Python 逐像素量）：

| 图 | 主网格 | 副网格 | 底部条 | 单格 | 输出格 |
|---|---|---|---|---|---|
| `hotbar.png` | 9 格条 x37..218 / pitch 20 / 槽 16 | — | — | x5..23 | — |
| `backpack.png` | 9×6 @ (53,67) / pitch 17 / 槽 15 | — | 9 格 @ y180 | (19,180) | — |
| `crafting.png` | 6×6 @ (15,9) / pitchX17 pitchY18 | 3×3 @ (140,9) | 9 格 @ y180 | (19,180) | (226,26) |

## 2. 打包（方块 → 刚体）

- **只支持单个方块**（旧 F9 的规则），因为后续要做"强力胶"这类**选区物品**。
- 入口由快捷栏物品承担，不再用功能键。

## 3. 解包（刚体 → 方块）

- 姿态**吸附到最近的 90° 倍数**（24 种），差太多就不允许。
- 目标区域**全部可放置**才执行；否则整体沿 +Y 抬升搜索，仍失败则不动。
- 参考"航空学"类游戏的直接放置处理（用户原话：不复杂）。

## 4. 焊接合并（刚体 ↔ 刚体）

- 用一个**胶水类物品**实现（参考 Space Engineers 的粘液球 / TotK 的胶水）。
- 第一版：**焊接合并成一个刚体**（方块表合并 + 重算质心 + 重建形状），不做铰链。

## 5. 约束（Fixed/Hinge/Distance）

- **暂不做**（用户：内容太少，不适合）。规则草案仍留在
  `docs\DOCS自制版\多刚体与约束-规则草案.md`，等多刚体需求出现再上。

## 6. 硬前置（做玩法前必须完成）

1. **结构持久化**：存档目前不含刚体，退出即丢。
2. **刚体网格增量重建**：现在每次全量重建，合并出大结构会卡（记 P15）。

## 7. 落地顺序

```
第 1 步  UiRenderer（渲染线程只管把指令变顶点）+ 三张图上传为纹理槽 1/2/3
         → 屏幕上先画出快捷栏 / 背包 / 工作台（整图 + 程序高亮）
第 2 步  物品系统骨架（ItemDef / ItemStack / Inventory）+ 方块物品图标复用方块纹理
第 3 步  结构持久化 + 解包落地
第 4 步  胶水物品（焊接合并）
```
