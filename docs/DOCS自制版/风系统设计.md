# 风系统设计（开发依据）

> 定位：把《玩法决策.md》里的"风"从一句原则落成可实现的系统方案。
> 状态：**设计定案（2026-11-16）**，未实现。
> 上游：`玩法决策.md` §风（四源头：温差 / 地形 / 高度 / 湍流）。

---

## 0. 决策摘要（一行读懂）

> 风场**不做全局实时重算**；拆成三层——**基场解析（永不重算）/ 修正场事件驱动（局部重算）/ 采样每帧**。
> 风场只被**静态方块**改变；**移动刚体只受风、不改风**。

---

## 1. 问题：所谓"实时风场"其实是三件事

大部分争论源于把三件不同频率的事混成一个词：

| 层 | 内容 | 该多久变一次 | 成本 | 本方案 |
|---|---|---|---|---|
| **① 基场** | 主风线方向、高度函数、噪声阵风 | **永不重算**（参数化，随 t 演化） | 免费（解析式） | 全程保留 |
| **② 修正场** | 地形系数、**建筑挡风**、热源处上升气流 | 只在**世界变了**时重算 | 中等（可局部化） | 局部事件驱动 |
| **③ 采样** | 实体推力、风车输出、云/鸟表现 | **每帧 / 每 tick** | 极便宜（查表 + 插值） | 必须做 |

"隔一段时间检测一次再改风场"对应的是 **②**；而 ② 的**正确触发方式不是定时器，是事件**。

---

## 2. 定案：不做全局实时重算

| 方案 | 判断 |
|---|---|
| **完全实时**（每帧重算全场） | ❌ 不需要，也做不起；风本来变化就慢，实时毫无收益 |
| **全局周期性重算**（每 N 秒扫全世界） | ❌ 代价随世界增长，而真正关心的只有玩家附近 |
| **局部事件驱动**（世界哪里变了就重算哪块） | ✅ **定案** |

### 为什么不能用定时器

定时器重算与"世界是否变化"无关：玩家不建造时也在白白重算，建造后又要等下一个周期才生效。
**事件驱动**则天然对齐：建/拆方块 → 立刻知道要重算哪一块。

---

## 3. 成本拆解：贵在哪、便宜在哪

| 做法 | 代价 | 判断 |
|---|---|---|
| 3D 全局体素风场，每格算 4 个源 | 全世界 `N³` × 每格多次射线 | ❌ 不可行 |
| 全局高度图（2D）+ 解析式 | 一次 `O(W×H)` 扫描 | ✅ 建世界时一次，之后不碰 |
| **局部体素缓存**（玩家周围） | 半径 64、格 4³ → `16³ = 4096` 格 | ✅ 单块重建约 1ms 量级（估算） |
| 采样（每帧查表/插值） | `O(实体数 + 风车数)` | ✅ 免费 |

**核心原则：精度只该花在玩家附近。** 远处的风只需要"看上去对"（云走向、鸟飞行），解析式足够。

---

## 4. 分层方案

### ① 远场（解析，无缓存）

```
windFar(x, y, z, t)
  = 主风线方向
  × 高度函数(y)          // 越高风越大（脱离地面摩擦）
  × 噪声阵风(t)          // 伪湍流
  × 地形粗系数           // 峡谷/山脊的粗粒度修正
```

用于：云、鸟、远景氛围、远处风车的近似值。
**永不查近场缓存**（否则玩家走远一点，远景的风会突然变样）。

### ② 近场（局部缓存，覆盖玩家周围约 64 格）

- 格大小 `4×4×4`（`16³ = 4096` 格），每格存一个 3D 风速向量。
- 构建单格时：
  1. 取该格中心，叠加基场 + 距离衰减；
  2. **遮挡判定**（沿风向路径步进几次，遇到实心方块则衰减）；
  3. 叠加地形加速系数（峡谷收窄 → 加速）。
- 每格同时存 `current` 与 `target` 两个向量（见 §6 时间平滑）。

### ③ 采样

- 查询点落在哪一格 → 取该格向量 + **三线性插值**（避免格子边界跳变）。
- 采样频率 = 每 tick / 每帧，成本可忽略。

---

## 5. 更新机制：复用现有的"脏 chunk"事件

近场缓存的重建**不需要新造世界变更通知机制**，直接挂在已有事件上：

```
World::dirtyChunksThisTick_      // 已存在，当前驱动渲染 mesh 重建
   ↓ 风场系统作为"第二个消费者"订阅同一份脏集合
把脏 chunk 覆盖的风格标记为"需重算"
   ↓
每 tick 最多重算 N 个风格（与 ChunkStreamer::kMaxApplyPerTick 同思路）
```

**工程含义**：风场系统是一个新的"脏数据消费者"，和渲染端并列；世界侧无需改动。

---

## 6. 三条硬边界

### ① 移动刚体不改变风场

只有**静态方块**（`contraptionId == -1`）参与遮挡计算。飞船只**受**风，不改风。

否则：一艘飞船飞过 → 沿途风格全脏 → 每帧重算一片 → 性能崩，且玩家看不出区别。

### ② 重算必须时间平滑，不能突变

一格风速从 `5 格/秒` 瞬间变 `0`（玩家正好在它前面放了墙），玩家会看成 bug。
做法：每格存 `current / target`，每 tick 向 target 插值，约 **0.5–1 秒**收敛。

### ③ 远场不追求精度、不查缓存

远景只用解析式。近场缓存只服务"玩家附近"。

---

## 7. 落地三步（都能单独验证）

| 步 | 内容 | 验收标准 |
|---|---|---|
| **W1** | 纯解析风场（无遮挡）+ 采样 + 实体推力 + 风车输出 | 风车转速随风速变；玩家在高处被明显推挤 |
| **W2** | 近场局部缓存 + 简化遮挡（先做"垂直遮挡近似"：看该格正上方有无方块、水平最近实心距离） | 在墙后测到风速明显下降 |
| **W3** | 脏 chunk 驱动重算 + 时间平滑 | 建墙后风场在约 1 秒内平滑改变 |

> **W1 现在就能做**：不需要 Jolt、不需要存档，只需一个解析函数 + 采样点。
> 它还有独立价值——**提前验证"风好不好玩"**：如果"风车转速随风变"都没有手感，W2/W3 就是浪费。

## 8. 与既有定案的关系

| 既有定案 | 关系 |
|---|---|
| 四源头（温差/地形/高度/湍流） | 全部保留，作为 §4 的**基场 + 修正项来源** |
| 垂直气流（不单独编写，是 3D 风场的自然成分） | 一致：近场缓存的 3D 向量天然含垂直分量 |
| 风车输出 = f(风速) | 一致，但**措辞改为"场驱动"**：输出 = 采样到的风速，不是"真物理 CFD" |
| 风影响实体（`F = ½ρC_dA v²`，三门槛） | 一致：采样点取实体位置，`v` 来自风场 |
| "全部静态规则、无实时模拟" | ⚠️ **本条修订**，见 §10 |

## 9. 待定

1. **风是否可被玩家改造？** —— 决定风车是"选址游戏"还是"工程游戏"。
   - 否 → 风车只能选位置（实现简单，工程性弱）
   - 是 → 建筑挡风 / 峡谷改造 → 风车成为设计对象（复杂，但贴合核心受众）
   - 本方案的近场遮挡**已经支持**"是"，只差把"建墙 → 改风"纳入玩法叙事。
2. 近场缓存的半径与格大小（64 / 4³ 是初值，待性能实测）。
3. 每 tick 重算的风格上限 `N`（初值建议 8–16）。
4. 风暴事件（天边风暴云 → 全域风增强）的触发与表现。
