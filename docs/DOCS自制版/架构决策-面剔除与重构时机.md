# 架构决策：面剔除实现与重构时机

日期：2026-10-25
关联代码：`src/render/optimization/meshing/FaceCulling.hpp`、`src/render/VulkanMesh`、`src/render/VulkanContext.cpp`

## 决策

1. 面剔除采用**内联 + 小函数**，不建独立"检验层"（对照 Sodium：mesher 内联剔除 + ShapeComparisonCache 缓存昂贵比较）
2. 新增 `optimization/meshing/` 目录，作为渲染优化的总入口（未来 AO、增量重建、顶点压缩、多线程各占子目录）
3. 面掩码 = `uint8_t` 位图，bit0..5 = {+X,-X,+Y,-Y,+Z,-Z}，与 `kFaceN[6]` 顺序对齐
4. 越界 = 空气：邻居查询用集合 `contains`，世界外坐标天然不在集合 → 视为空气（无需边界特判）

## 职责划分（决策与执行分离）

| 角色 | 模块 | 职责 |
|---|---|---|
| 编排者 | `VulkanContext::rebuildMeshFromBlocks` | 建 solid 集合 → 遍历方块 → 调判定/生成 → 拼接顶点索引 → 上传 GPU |
| 判定者 | `computeFaceMask` | 查 6 邻居 → 输出可见面掩码（决策，不生成几何） |
| 生成者 | `buildCubeVertices` | 按掩码生成对应面的 4 顶点（纯几何，不查世界） |

## 已知架构问题（按严重性）

1. **上帝函数**：`rebuildMeshFromBlocks` 集数据整理/调度/判定/装配/上传于一身，未来优化都会塞进来
2. **全量重建 + 临时集合**：solid 每帧从零建、blocks 传全量快照；协议已有 `BlockChangeEvent` 增量通道但未使用
3. **接口耦合容器**：`computeFaceMask` 签名写死 `unordered_set<BlockPos>`，世界存储换 chunk 数组直查时需改接口
4. **多线程未预留**：并行 meshing 需要只读快照或分区块所有权（尚远，只记）

## 重构触发时机

| 触发点 | 动作 |
|---|---|
| **增量重建落地（下一里程碑）** | mesher 独立成类（持有世界只读引用 + 顶点装配），一次解决 ①②；接入增量事件流 |
| 世界存储 chunk 化稳定后 | FaceCulling 改"查询接口"（解决 ③） |
| 世界变大、meshing 成瓶颈 | 多线程分区块并行（解决 ④） |

原则：不提前重构（YAGNI），等第一个触发器（增量重建）到来时统一拆解。
