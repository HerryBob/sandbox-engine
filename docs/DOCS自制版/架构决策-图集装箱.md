## 决策

**图集走真装箱（bin packing，按矩形排布），支持任意尺寸的贴图。**

否决两条低成本替代路线：

| 路线 | 否决理由 |
|---|---|
| A 全局升 `kAtlasTile`（如 32） | 把分辨率变成全局约束，所有模组贴图必须同步升；模组不能自带高清贴图，等于白做模组化 |
| B 多格 span（占 2×2 格） | 只允许 16 的整数倍，24×24 / 40×40 这类进不来；16 与 32 混排的碎空间要靠人肉分组 |

选 C 的动机：模组化游戏内容的前提是贴图分辨率不受引擎限制，由模组作者自己决定。

## 现状（固定网格）

```
kAtlasTile = 16（每格边长）
grid_ = 从 1 往上找第一个平方 ≥ need（need = 1 + 声明条目数）
size_ = kAtlasTile × grid_
slot = { row: slotIndex / grid_, col: slotIndex % grid_ }
UV  = { col/grid, row/grid, (col+1)/grid, (row+1)/grid }
```

8 项声明 + default → 9 格 → 3×3 → 48²。
（2026-11-25 起声明文件 `assets/atlases/blocks.json` 已删，改为「方块 id 升序 + 模型槽字典序」自动收集；条目数不变，仍是 8 + default。）

`addFromFile` 强制 `w == h == 16`，不符直接拒绝，格子留透明黑。

## 依据（为什么固定网格撑不住模组化）

```
固定网格能成立的前提是"所有格子等大"：
  每格尺寸相同 → 一维下标顺序排即可，天然无碎空间
  格子数已知 → grid_ 一次算完，不会溢出

一旦允许尺寸不一，这个前提就没了：
  1×1 与 2×2 混排时，一维顺序排会把 2×2 的块切碎
  图集边长不能再按"格子数"算，要按"实际像素占用"算
  → 必须换成矩形装箱 + 二维占位标记
```

## 影响面（实现时要动的地方）

| 位置 | 现状 | 改成 |
|---|---|---|
| `TextureAtlas.hpp` `AtlasSlot` | `{ uint8 row, col }` 格坐标 | `{ uint16 x, y, w, h }` 像素矩形 |
| `slotUV` | `col/grid, row/grid` | `x/size, y/size, (x+w)/size, (y+h)/size` |
| `addFromFile` | 校验 `== 16`，偏移按 16 算 | 校验任意尺寸，偏移按矩形左上角算 |
| `build()` 第 ⑥ 步 | `slotIndex / grid_`、`% grid_` 顺序排 | Region 树装箱（试装 → 失败扩边） |
| 图集边长 | `kAtlasTile * grid_` | 2 的幂，受 `maxTextureSize` 限制 |
| `fallbackUV()` | 固定第 0 格 | 指向 missing sprite 自己的矩形 |

**时序也要改**：现在是「边读边铺」，装箱必须先知道所有贴图的尺寸才能排布。

```
现状：声明 → 算 grid → 逐张 stbi_load → 写入格
装箱：声明 → 逐张 stbi_info 只读尺寸 → 装箱排布 → 逐张 stbi_load 按矩形写入
```

`stbi_info` 只解析文件头拿宽高，不解码像素，成本很低。

## 约束（不能丢的现有语义）

1. **missing sprite 必须有**：现在的第 0 格 `default.png`，装箱后没有「第 0 格」这个概念，改成独立的 missing 矩形；缺失时仍只 WARN，不崩（与 MC 的 `IllegalStateException` 相反，取舍不变）。
2. **声明文件仍是唯一真源**：`assets/atlases/blocks.json` 的 `textures` 数组决定铺哪些、按什么顺序。
3. **不缩放**：原图尺寸 = 格子尺寸，一比一写入，不做插值。
4. **采样器不变**：`NEAREST`（放大/缩小都是最近邻）+ `CLAMP_TO_EDGE`（边缘钳制）。
5. **失败不崩**：单张贴图缺失/尺寸非法只影响那一格，不影响整张图集。

## 参考（MC 实现）

`E:\MinecraftGame2\Allmd\开源参考\MC-1.21.1-src\net\minecraft\client\renderer\texture\Stitcher.java`

要点：

```
排序      : -height → -width → name（高的先、宽的先，先放大的成功率高）
试装      : 遍历已有 Region，能放就放；全放不下才 expand()
分裂      : Region 占掉左上 i×j 后，把剩余切成 2 块（横切或竖切），
            按「让较大那块更方正」选切法（i1 >= j1 那处分支）
扩边      : 边长取 2 的幂（smallestEncompassingPowerOfTwo），横纵选代价小的那侧
上限      : maxSupportedTextureSize（GPU 上报），超了抛 StitcherException → 崩溃报告
mip 对齐  : smallestFittingMinTexel(w, mip) 把格子宽高向上取整到 2^mip 的倍数
mip 降级  : 全局 mip 由「最弱的那张 sprite」决定，不够就 WARN + 降级
```
