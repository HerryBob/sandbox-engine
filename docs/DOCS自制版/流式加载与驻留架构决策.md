# 架构决策：流式加载与驻留架构（WorldManager 复合体）

> 日期：2026-10-31 · 状态：设计定案（讨论产出，未实现）
> 关联：玩法决策（引擎通用原语=流式加载）、流体与气体系统设计（chunk 是流体/存档/LOD 共同地基）、业务线程拆分（World 数据真源）

## 1. 背景与动机

MC 的区块模型把三件事焊死：**加载状态 = 数据在场 = 是否 tick = 是否渲染**（区块等级 ticket 三合一）。后果：

- 玩家走远 → 区块卸载 → 机器停转、实体冻结（除非手动放 chunk loader 钉住）；
- 模拟范围被玩家位置绑架，自由度低；
- 后台世界无法独立演化。

**目标**：让"玩家不在场也正常运行"成为**租约的自然结果**而非特例——驻留（presence）、活跃（activity）、渲染（visibility）三轴独立决策。

## 2. 三轴独立模型

| 轴 | 管什么 | 谁决定 |
|---|---|---|
| 驻留（presence，数据在内存） | 数据在场性 | 加载管理器：**租约引用计数** |
| 活跃（activity，参与 tick） | 谁参与模拟 | 模拟调度器：活动集合 + 频率 |
| 渲染（visibility，被画） | 画什么 | 渲染管理器：独立窗口 |

### 2.1 依赖反转（关键支点）

```
MC（耦合）:   加载状态 ──决定──> 是否 tick
我们（解耦）: 模拟调度器决定 tick 范围 ──请求──> 加载管理器保证数据在场
```

物理事实：**数据必须在场才能访问**——"解耦"不是"在无数据处也能 tick"，而是**决策权反转**：活跃 ⊂ 驻留，活跃范围自动拉数据。

## 3. 核心机制：租约三原语

| 原语 | 含义 | 说明 |
|---|---|---|
| **租约（lease）** | 对象对区域声明"我需要它" | 引用计数；卸载唯一判据 = **无人需要才卸**；玩家窗口只是默认租约之一 |
| **Pin / Owned region** | 实体、结构动态持有区域 | 走到哪钉到哪；玩家窗口本质也是 Owned region |
| **Persistent（持久标志）** | 关键方块声明"所在区域必须驻留" | MC 的 chunk loader **通式化**：从手动特例升级为方块属性 |

## 4. 对象驻留规则

| 对象 | 驻留来源 | 活跃来源 | 玩家离开后 |
|---|---|---|---|
| 普通区块 | 玩家窗口（默认租约） | 调度器活动集合 | 无租约 → 存档 → 卸载 |
| 实体 | 实体管理器（独立生命周期） | 实体独立调度 | 实体钉住区域，照常跑 |
| 物理结构（contraption） | 结构自身容器（bodyBlocks，D4 已自足） | 结构独立 tick，不查 chunk 表 | **天然独立** |
| 关键方块（机器/信号源） | persistent 标志自动钉住 | 需演化 → 区域被活跃 | 挂机自动化继续转 |

## 5. 后台演化三档（玩法配置，非架构）

| 档位 | 语义 | 成本 |
|---|---|---|
| 驻留冻结 | 数据在，不 tick | 中（内存） |
| 降频演化 | 数据在，低频 tick（如 1/4 频率） | 中高 |
| 完全演化 | 数据在，正常 tick | 高 |

"玩家不在场也正常运行"要哪档由**玩法**决定（自动化挂机=完全演化；生物群落演化可后置）。

## 6. 硬约束

1. **数据必须在场才能访问**——活跃自动拉数据（活跃 ⊂ 驻留），无需手动保证；
2. **后台演化 = 降频的同一时间线，不做并行世界**——多区域一致性/存档原子性是最大技术成本，用"共享时钟、不同更新率"回避（Factorio 全局单时间线 / MC 冻结，我们取降频同时间线）；
3. **驻留预算**：无限钉住 = 内存无限涨 → 上限 + 优先级踢出（最低优先级 = 纯玩家窗口远区块）；
4. 被钉区域**照样定期存档**（防崩溃丢挂机进度）。

## 7. 市面对照（四派，各取其一）

| 派系 | 驻留策略 | 活跃策略 | 玩家离开后 | 代价 |
|---|---|---|---|---|
| Factorio | 生成后永驻 | 睡眠/唤醒（事件驱动） | 全图照跑 | 内存无限涨 |
| MC / Valheim | 流式卸载 | 耦合加载等级 | 冻结/卸载 | 玩家被窗口绑架 |
| Terraria | 全驻留（世界固定） | 玩家矩形活性圈（504×283.5 格） | 冻结 | 世界规模锁死 |
| DSP / SE | 对象级常驻（物流/网格） | 对象独立调度 | 关键对象照跑 | 对象要自管数据 |

**我们的组合**：流式卸载骨架（MC）+ 租约解耦（chunk loader 通式化）+ 事件驱动活性（Factorio 睡眠思想，保留卸载省内存）+ 结构/物流对象级常驻（DSP/SE）+ 确定性生成只存 diff（NMS）。

**为什么市面没有全做**：①解耦工程贵（两系统正确性+协议）；②工厂类重要对象密度=全图→租约退化全驻留（而我们的重要对象**稀疏**，恰好适合）；③对象自足难（脱离区块=不再需要世界数据，DSP 物流因不查地形才能全局跑）；④商业上隐形收益+灾难性失败；⑤沙盒都是玩法先跑架构后补（我们是地基期设计，红利）；⑥多区域一致性（见硬约束 2）。

## 8. 执行架构：WorldManager 复合体（业务线程）

**结构**：不是三个平级控制器，也不是全管单体——**一个数据所有者 + 两个策略视图**。

```
WorldManager（世界管理器，复合体，业务线程 25 TPS）
├─ 驻留控制：租约计数 / 卸载判定 / 加载请求发起    ← 数据生命周期唯一决策者
├─ 活跃调度：活动集合 / tick 频率分配              ← 策略视图 1
└─ 需求接口：对外"我需要这块"声明入口（SPSC 队列）  ← 给渲染/实体/结构用

渲染线程（60Hz，第 4 轨观众）：
└─ 渲染视图：画什么 / 网格资源（自己维护）          ← 策略视图 2

后台工作线程：
├─ 世界生成（噪声/地形/光照，纯计算不碰共享数据）
└─ 存档 IO（磁盘不阻塞 25 TPS）
```

### 8.1 线程归属与理由

| 职责 | 放哪 | 为什么 |
|---|---|---|
| 驻留决策（租约/卸载判定） | 业务线程 | 决策轻（计数），但数据生命周期在业务侧；跨线程管生命周期=竞争。与方块写入同源 |
| 活跃调度（谁 tick） | 业务线程 | tick 本就在业务线程跑（25 TPS），调度器只是内部集合 |
| 世界生成 | 后台工作线程 | 重 CPU 计算、不碰共享数据，天然可并行（MC 流水线同款） |
| 存档 IO | 后台工作线程 | 磁盘 IO 不阻塞业务节奏；异步读进缓冲、业务接手 |
| 渲染视图（画什么） | 渲染线程 | 独立观众轨，只消费 + 反向提需求 |

### 8.2 通信：需求声明，不是渲染自己决策

```
渲染线程（想画 128 圈）──需求请求──> SPSC 队列 ──> WorldManager（业务侧）更新租约计数
WorldManager：保证数据在场 ──> 渲染线程网格化
```

渲染线程不拥有驻留状态（那是业务侧的事），只是"需要者"之一；SPSC（单生产者单消费者）现成机制，无需锁。

### 8.3 小线程边界判断

| 想开线程的东西 | 值不值得 |
|---|---|
| 世界生成 / 存档 IO | ✅ 纯计算/纯 IO，不碰共享状态 |
| 驻留/租约决策 | ❌ 决策轻但要读共享租约表，开线程=给共享状态加锁，纯亏 |
| GPU 资源卸载执行 | 销毁动作放渲染线程安全点（destroyChunkMesh 已有） |

### 8.4 判断准则（可复用）

> **线程跟着"数据是否共享"走**：
> 纯计算（生成）/ 纯 IO（存档）→ 后台线程；
> 动共享状态（租约、方块数据、生命周期）→ 业务线程，无锁单写者；
> 只消费 + 反向提需求（渲染）→ 独立线程 + SPSC 队列。
> **谁拥有数据，谁决定数据的生命周期。**

## 9. 落地顺序（对应代码）

| 步骤 | 内容 | 依赖 |
|---|---|---|
| ① | 世界生成器（确定性、种子、单 chunk 生成） | 新 |
| ② | 加载管理器：租约表 + Pin/Owned region + 驻留预算 | 依赖 ① |
| ③ | 模拟调度器：活动集合（独立于加载状态） | 依赖 ② |
| ④ | 存档：只存改动 diff，被钉区域定期保存 | 依赖 ② |
| ⑤ | LOD 远景（渲染圈 128→2048，环带级数 log₂(2048/32)=6） | 后置 |

**已就绪**：chunk 稀疏映射（D3）、增量重建（Renderer/VulkanContext）、destroyChunkMesh、contraption 独立容器（D4，天然自足）、物理只消费力（ApplyForce）。

## 10. 风险与未决

- **最大技术风险：多区域一致性/存档原子性**——对策已定案（降频同一时间线），实现时需验证：降频区域与正常区域边界衔接、崩溃恢复（租约表丢失）；
- 实体管理器的生命周期细节（实体驻留规则、跟随区域 vs 独立存在）未展开，等实体系统立项；
- 驻留预算具体数值（上限、优先级策略）是玩法/性能配置，实现时定；
- 渲染线程网格资源与"数据卸载"的时序（卸载前确认渲染不再引用）需在 ② 实现时给协议。
