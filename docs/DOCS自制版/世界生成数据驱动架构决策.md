# 世界生成数据驱动架构决策

>状态：定案 2026-10-31　·　1a 落地回填 2026-11-04　·　关联：《流式加载与驻留架构决策.md》《模型格式决策.md》《模组架构决策.md》
>决策背景：自研 C++20/Vulkan 体素沙盒引擎，世界生成器（1a 噪声地形 + 1b chunk 加载/卸载）开工前，确定地形生成的三层职责划分与数据驱动解耦契约

## 决策目标（三标准）

>配方可换：换地形 = 改数据文件，引擎代码零改动
>模组可扩：模组以代码注册新噪声/阶段，以数据文件编排组合
>确定性：同 seed + 同 preset = 同一世界（流式命脉，卸载后重建 = 重新生成）

## 三层职责划分（MC 同构）

| 层 | 写入者 | 贡献 | 粒度 |
|---|---|---|---|
| 模组（代码） | 模组作者 | 注册新 NoiseSource 类型（C++ 实现 + 注册名） | 原子：一种噪声算法 |
| 数据文件（JSON） | 数据包作者（含本引擎作者） | 编排噪声图：`{"type":"perlin",...}` 嵌套组合 fBm、配参数 | 组合：配方 |
| 引擎（管线） | 引擎作者，写一次 | 确定性种子、求值调度、阶段执行、方块填充、preset 加载 | 骨架：不动 |

>对应 MC：模组注册密度函数（DensityFunction 代码）/ 数据包编排噪声网络（JSON）/ Mojang 引擎只跑生成管线

## 咬合点：注册名 ↔ JSON type 字段

>模组代码注册：`registerNoiseType("my_mod_xyz", factory)`
>数据文件引用：`{"type": "my_mod_xyz", "scale": 0.004, ...}`
>引擎行为：解析 JSON → 按 type 查注册表 → 工厂实例化 → 求值
>引擎内置原子：value / perlin / fbm（fbm 本身是组合子，内置为"基础配方"）；模组加新原子，JSON 结构零改动

## 资源双目录（对齐 MC）

>assets/ —— 表现层（渲染线程只读）：textures/block/*.png、models/block/*.json、blockstates/（将来）、lang/（将来）
>data/ —— 逻辑层（业务线程只读）：worldgen/noise/*.json（噪声源配方）、worldgen/presets/*.json（世界类型）、recipes/loot_tables/tags（将来）
>原则：资源包管"长什么样"，数据包管"怎么运作"；渲染只读 assets、业务只读 data —— "线程跟着数据共享走"在资源层落地
>反直觉点：方块模型归表现层（assets），世界生成归逻辑层（data）——与 MC 一致
>边界：BlockInfo 数值属性保留代码注册（对标 MC 代码注册表）；namespace（minecraft:xxx）后置，模组化时再加，目录已天然预留（assets/<ns>/、data/<ns>/）

## 目录与类布局（新建 src/worldgen/）

```
src/worldgen/
├── noise/                          # 噪声：接口 + 实现 + 注册表（三类分目录）
│   ├── NoiseSource.hpp             # 抽象接口：sample(x,z,seed) + NoiseParams 信封
│   ├── NoiseHash.hpp               # detail:: 格点哈希三函数（splitmix64 风格，三实现共用）
│   ├── ValueNoise.hpp / .cpp       # value 噪声（格点随机值 + 双线性，fade 3t²-2t³）
│   ├── PerlinNoise.hpp / .cpp      # Perlin（四角梯度 + 点积，fade 6t⁵-15t⁴+10t³）
│   ├── FbmNoise.hpp / .cpp         # fBm 组合子（octaves/lacunarity/gain，持 base 噪声）
│   ├── NoiseRegistry.hpp / .cpp    # type 名 ↔ 工厂（模组口子；freeze 后免锁读）
│   └── BuiltinNoiseTypes.hpp / .cpp # 内置三类型注册 + 自检（确定性/未注册/fbm 链路）
├── preset/                         # 世界预设（数据 → 结构体）
│   ├── WorldPreset.hpp             # 纯数据 struct：seed/heightmap/baseHeight/amplitude/strata
│   └── PresetLoader.hpp / .cpp     # data/worldgen/presets/*.json → WorldPreset（八步校验）
└── generator/                      # 生成管线
    └── WorldGenerator.hpp / .cpp   # seed → 逐列采样 → 地层 → World::generateBlocks
```

>命名对齐现有风格：接口 class / 纯数据 struct（WorldPreset）/ 加载器 Loader 后缀（PresetLoader ↔ ModelLoader）/ 注册表 Registry 后缀（NoiseRegistry）
>放置理由：线程归属（业务侧，非渲染）；子系统自洽（未来膨胀：加载/卸载/存档/装饰都归此）；注册表机制随领域内容走（registry/ 保持纯通用模板）
>与规划的差异（2026-11-04）：①未引入 `WorldGenStage` / `Terraformer`——1a 只有一个阶段，内联在 WorldGenerator 里（出现第二个阶段再抽，触发器纪律）；②噪声注册表并入 `noise/`，未单开文件；③按"文件分类"要求已重组为 noise/ + preset/ + generator/ 三个子目录。

## 解耦契约（实现先简，接口钉死）

>现在只有三个内置算法 → 实现放 src/worldgen/ 可以朴素；但"数据驱动"从第一天起不可妥协

| 层 | 目前可以怎么做 | 必须解耦的点（不可妥协） |
|---|---|---|
| 噪声实现 | 三实现内部朴素 | 必须继承 NoiseSource 抽象接口，只暴露 sample() |
| 注册 | 内置三个直接注册 | type 名 ↔ 工厂函数机制必须存在（模组口子） |
| 编排 | JSON 就写这三个的配方 | 引擎不认识任何具体 type 字符串，一律查注册表 |
| 管线 | 阶段序列先只有一个 Terraformer | WorldGenerator 只依赖接口/注册表/preset，零具体类引用 |

### 反例（禁止）与正例（解耦）

## 噪声选型结论

>自研 Perlin + fBm（教学价值：梯度/插值/八度全理解；需求落在自研舒适区：2D 高度图、离线生成量级小，性能不构成选库理由）
>教学路线：先 value noise 跑通管线 → 再 Perlin 升级
>业界现状：Perlin（1985/2002 改进）仍是行业事实标准，MC 底层即 Perlin 变种 FBN 八度；质量来源是组合不是算法（MC 1.18 噪声路由器：final_density 密度函数、三种洞穴独立噪声、erosion 参数化）；现代工程替代 OpenSimplex2S（2018 去网格伪影）；AI 替代（Terrain Diffusion，arXiv 2025-12）纯研究阶段
>关键：把"噪声函数"与"地形组装"解耦 —— 将来换 OpenSimplex2S 只换核心实现，接口不变

## 明确不做（防范围蔓延）

>生物群系参数化（biome → 高度/温度/湿度改噪声路由）——后置
>完整噪声节点图（MC noise router 的节点网络 JSON）——嵌套 JSON 够用
>洞穴/装饰/流体生成阶段 —— 只留 WorldGenStage 接口，内容后置
>DLL 模组加载器 —— 无真实模组需求，注册表口子先通

## 1a 落地实况（2026-11-04 回填）

### 生成管线五步（WorldGenerator::generate）

1. **预设前置校验**：`heightmap` 已实例化、`strata` 非空；
2. **地层解析**：`Stratum.block` 字符串 → `findBlockIdByName()` → BlockType（未注册即失败，报未注册方块名）；
3. **覆盖连续性校验**：按 depthMin 排序后，首层 depthMin 必须为 0，后续逐层 `depthMin == 前层 depthMax + 1`（防空气夹层）；
4. **逐列采样**：`n = heightmap->sample(x, z, seed)`（x/z 未缩放的**世界坐标**，seed 显式传入）→ `surfaceY = baseHeight + round(n × amplitude)` → clamp 到 `[0, min(63, maxDepth)]` → y 从 0 到 surfaceY 按 `depth = surfaceY - y` 线性查层；
5. **批量写入**：`World::generateBlocks(blocks)`——一次锁、直写各 chunk 的 blocks 数组、逐 chunk 标脏（**不走 base 裁决、不发逐块变更事件**）。

### 三个已拍板的设计决策

| # | 决策点 | 结论 |
|---|---|---|
| 1 | strata 深度语义 | **相对地表深度**（depth 0 = 地表，地层随地表起伏整体平移）；否决"绝对高度区间"——会导致山顶露石头、山谷草皮悬空 |
| 2 | baseHeight / amplitude | **放数据文件**（`heightmap.baseHeight/amplitude`），生成器零写死 |
| 3 | 地形写入方式 | **生成专用批量入口** `World::generateBlocks`；否决逐块 `placeBlock`——①生成是权威写入，base 裁决多余；②约 7.6 万次变更事件会打乱渲染 chunk 重建；③1b 异步生成时逐块加锁锁竞争 |

### 已知缺口（登记，不在 1a 修）

- 地表起伏偏平：`scale=0.004` 在 48×48 范围内噪声变化太小（实测仅 ±4 格）——调数据即可，代码零改；
- 阶段接口未抽：1b 出现第二个阶段（装饰/洞穴）时再引入 `WorldGenStage`；
- 嵌套噪声（base 递归为 `unique_ptr<NoiseParams>`）保持现状，登记为升级点；
- 异步生成（后台线程 + SPSC 双队列）为 1b 内容；
- 模组注册新噪声类型的真实链路要等 DLL 加载器（#41）才有消费者，`registerType` 已 public。
