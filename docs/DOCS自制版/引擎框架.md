# 我的世界类型的沙盒游戏引擎 
>自带物理线程: 取代MC原版的固定方块, 物理化方块给予游戏更多玩法
>业务线程设计: 游戏引擎的最高权力, 所有东西都需要经过业务线程
>渲染线程: 依赖VULKAN_API, 只读线程, 游戏图形化显示
>输入线程: 负责获取玩家输入, 未来包括手柄API

## 区块存储体系（2026-10-26）

### 双层存储：同一个区块的两份存法

```
业务层（世界真相）ChunkData：16³ 密集数组，每方块 1 字节（BlockType）
  —— 紧凑（4096B/区块=1 页内存），存"是什么"，业务线程改方块的地方

渲染层（GPU 画稿）ChunkMesh：每区块一份 vertexBuffer/indexBuffer
  —— 冗余（每方块数百字节），存"怎么画"，渲染线程只读

桥梁：业务层变更 → dirtyChunks 事件流（SPSC 队列）→ 渲染端重建 ChunkMesh
```

### 业务层三层结构

```
第 1 层：容器
  BusinessWorld::chunks_ = std::unordered_map<ChunkPos, ChunkData>
  稀疏：只有有方块的区块才有条目（空 chunk 不占内存）
  定位 O(1)：chunkOf(坐标) → find → 整个区块

第 2 层：区块单元 ChunkData（Block.hpp 63-80）
  blocks = std::array<uint8_t, 4096>{}：值初始化全 0 = 全 Air
  索引公式：(z&15)*256 + (y&15)*16 + (x&15)
    （z 层×256 / y 行×16 / x 列×1；&15 负坐标取模，与 >>4 配对）
  dirty = 32 位位掩码（变更病历，持久留档）
  atWorld：4 重载（const/非const × int/BlockPos），
    非 const 版返回引用可写（placeBlock 用），const 版返回拷贝只读（findBlock 用）

第 3 层：方块单元
  blocks[i] = uint8_t = BlockType 枚举值（0=Air, 1=Stone...）
  只存类型：位置隐含在索引、刚体 ID 恒 -1 不存、附加数据暂无（未来扩展）
```

### dirty 双通道（重要：事件流不走 dirty）

```
通道 A：dirty 位掩码（持久留档）
  标记：0x01=初始装载 / 0x08=放置 / 0x10=破坏（只增不清）
  读取：chunkDirtyFlags(cp) 查变更史（诊断/审计/未来细分重建用）

通道 B：dirtyChunksThisTick_（unordered_set<ChunkPos>）
  placeBlock/removeBlock 里 insert(cp) → 本 tick 待办清单
  tick 末 flushChanges()：非空 → 打包成 dirtyChunks 事件 → SPSC → 清空
  —— 真正驱动渲染重建的是这条通道

（修正记录：早前以为"渲染端重建完 clearDirty"，实际无此调用，dirty 只增不清）
```

## 增量重建机制（2026-10-26 闭环）

### 请求-执行分离

```
业务线程：变更 → dirtyChunksThisTick_ → tick 末发事件（只通知"哪些区块脏了"）
渲染线程：drawFrame 里 waitForFences 后消费事件（exchange(false) 读并清零）
        → requestChunkRebuild(快照, 脏列表) → 置标志
        → 合适时机调 rebuildChunkMeshes 执行重建
—— 请求方不知道何时执行，执行方自己找安全点（解耦）
```

### 重建范围：脏 ∪ 6 邻居（第一版保守策略）

```
rebuildChunkMeshes：
  ① vkDeviceWaitIdle —— GPU 安全点（修复 VUID-00922 的关键：
     双缓冲下 fence 只同步同槽，另一槽帧可能仍在飞，
     真正的安全点 = 等 GPU 全部干完）
  ② 脏 chunk ∪ 6 邻居 → 只处理存在方块的（solid 集合）
  ③ 逐 chunk：收块→生成顶点/索引→空 chunk 删旧 erase→有网格先 destroy 旧再建新
  ④ 每 chunk 一条重建日志（面/顶点数）

代价：破坏内部方块也白重建最多 6 个邻居（正确性优先，先求对再优化）
```

### 边界触发优化（待办，明日）

```
业务端：placeBlock/removeBlock 插完自身后，按块内位置 (&15) 判断：
  ix==0 → 插西邻居；ix==15 → 插东邻居；iz 同理
渲染端：重建列表改用事件内容（去掉无条件"∪6 邻居"展开），
  solid 集合保留"读邻居边界 1 格"（只读，不重建）
