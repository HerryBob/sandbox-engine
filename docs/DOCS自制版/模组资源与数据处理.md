# 模组资源与数据处理

对应 MC 的 resource pack（资源包）/ data pack（数据包）两段式：`assets/` 只放外观，`data/` 只放逻辑；两边都是「先统一收集路径，再由各子系统分域解码」。

## 一、目录约定

| 归属 | assets | data |
|---|---|---|
| 引擎 | `assets/` | `data/` |
| 模组 | `mods/<模组名>/assets/` | `mods/<模组名>/data/` |

模组源目录 `mods_src/<模组名>/` 下放同名两个子目录，构建时整体拷到 exe 同级的 `mods/<模组名>/`。

目录内部按 registry（注册表）分域，路径本身即语义：

```
assets/textures/block/<name>.png    方块贴图
assets/textures/font/<name>.png     字体图
assets/models/block/<name>.json     方块模型

data/worldgen/presets/<name>.json   世界预设
data/worldgen/noise/<name>.json     噪声定义
```

## 二、MC 是怎么分的

### assets：外观，没有逻辑

`assets/<namespace>/` 下是一棵扁平树：`blockstates/`、`models/block/`、`textures/block/`、`lang/`、`sounds.json`、`fonts/`。资源用 `ResourceLocation`（`namespace:path`）标识。

- 收集层只做虚拟文件系统合并：把每个 resource pack 的 `assets/` 挂进来，同名路径按包优先级遮蔽。这层不解析任何内容。
- 取用层各子系统在 reload 时各读各的：`ModelManager` 读 blockstates + models 并烘焙（解父模型继承、`#texture` 变量、display 变换），`TextureManager` 按需懒加载，`LanguageManager` 合并所有 lang。
- 结论：assets 里只有「长什么样」，同一个模型可以被任意方块复用，改外观不影响逻辑。

### data：逻辑，全量注册

`data/<namespace>/<registry>/*.json`，例如 `data/minecraft/loot_tables/blocks/*.json`、`data/<ns>/worldgen/noise_settings/*.json`。

- `RegistryDataLoader` 在 reload 时对**每个 registry 扫整个目录、全量解码、注册进对应 Registry**。
- 注册完成后取用只查内存表，不再碰文件。
- 结论：data 是「有什么、怎么算」，同名 id 冲突在这里暴露，且必须能枚举出全部条目。

这个引擎照这个分工定资源归属：模型、贴图、字体归 assets，世界生成归 data。两侧都用同一套全量注册器 `DataRegistry<T>`，差别只在传进去的 `ResourceKind`；唯一的例外是预设本身按名字精确取一个。

## 三、本引擎的两段式

### 第一段：统一收集

`resource::ResourceIndex` 把引擎和所有加载成功的模组的根目录合并成一张表。这一层只认路径，不解析内容 —— 对应 MC 的 `ResourceManager`。

- 键 = 含扩展名的完整相对路径，如 `worldgen/noise/flat.json`
- 值 = 绝对路径 + 提供者 owner（`engine` 或模组名）
- 接口：`addRoot` / `find` / `ownerOf` / `list` / `count` / `clear`

登记时机：`main.cpp` 在 `ModLoader::loadAll()` 之前登记引擎两根；`ModLoader` 在「加载成功」之后登记该模组的 `assets` 与 `data`。目录不存在直接跳过，不告警。

`list(kind, relDir, ext)` 只列本层（不进子目录）、按字典序、**返回完整相对路径**（含 `relDir/` 前缀），可直接拿去 `find`。把它当裸文件名再拼一次目录会得到双重路径。

### 第二段：分域取用

各子系统按自己的 registry 目录去取、各自解码。索引不知道 JSON 长什么样 —— 对应 MC 的 `RegistryDataLoader`。

| registry | 消费方 | 取用形态 |
|---|---|---|
| `worldgen/presets/*.json` | `PresetLoader` | 按名字精确取一个，解析成 `WorldPreset` |
| `worldgen/noise/*.json` | `DataRegistry<NoiseDef>` | 全量扫目录解码注册；preset 的 `heightmap.noise` 写字符串时按名字查表，写对象则内联解码 |
| `textures/block/*.png` | `TextureAtlas` | 按方块纹理名取，解码后拷进图集 |
| `models/block/*.json` | `DataRegistry<ModelDef>` | 全量扫目录解码注册；模型留在 assets 侧，与 MC 一致 |

### 统一注册器：`DataRegistry<T>`

`src/resource/DataRegistry.hpp`，纯头文件模板，按 registry 实例化一份。assets 与 data 两侧共用，归哪一侧由调用方传的 `ResourceKind` 决定。

```cpp
template <typename T>
using DataDecoder = bool (*)(const rapidjson::Value&, T&, const std::string& rel);

template <typename T> struct DataEntry { T value; std::string owner; };

template <typename T> class DataRegistry {
    void load(ResourceKind kind, const std::string& relDir,
              const std::string& ext, DataDecoder<T> decode, const char* tag);
    const T* find(const std::string& name) const;   // 未注册返回 nullptr
    std::string ownerOf(const std::string& name) const;
    std::size_t size() const;
    std::vector<std::string> names() const;         // 字典序
    void clear();
    const_iterator begin() / end();                 // 键 = 名字，值 = DataEntry<T>
};
```

`load()` 的流程固定：

1. `g_resourceIndex.list(kind, relDir, ext)` 列出全部条目；为空则 warn 后返回
2. 逐条 `find` 取绝对路径、`ownerOf` 取来源
3. 读文件 → RapidJSON 解析（源文本用具名 `std::string`，字符串值会引用它的缓冲）
4. 调 `decode(doc, value, rel)`；返回 false 则计数并跳过。`rel` 只给解码器打日志用，内联来源传一个说明串
5. 名字取 `std::filesystem::path(rel).stem()`，同名冲突 warn 并忽略后到者
6. 结尾一条汇总：`注册 N 条（<dir>），失败 M 条`

内部用 `std::map<std::string, DataEntry<T>>`，保证日志与 `names()` 顺序稳定。

当前两个实例：

- `engine::worldgen::g_noiseDefs`（`src/worldgen/noise/NoiseDefTable.cpp`，kind = Data）—— 在 `NoiseRegistry::freeze()` 之后、预设加载之前调 `loadNoiseDefs()`。顺序是硬约束：`PresetLoader` 只查这张表，表空了预设必然失败。
- `engine::assets::g_modelRegistry`（`src/render/assets/ModelRegistry.hpp`，kind = Assets）—— 由 `loadBlockModels()` 在 `VulkanContext::init` 之前加载；图集和网格生成通过它取模型，`find` 未命中返回 `nullptr`。

## 四、冲突规则

MC 靠命名空间隔离 + 包优先级覆盖，这里都没有，靠登记顺序：

1. 引擎先登记，所以引擎优先
2. 模组之间先到先得，后到的记 `LOG_WARN` 后忽略
3. `ownerOf` 用来判归属：失败日志带「由 X 提供」、贴图跨模组引用告警

`DataRegistry` 的同名冲突按「先注册先得」处理，与索引的语义一致。

**迁移时旧副本必须删干净**，否则引擎那份永远遮住模组那份。这条踩过三次：

- 纹理从引擎 `assets/textures/block/` 搬到 `mods_src/blocks/assets/`，引擎侧同名 8 张必须删
- 噪声从引擎 `data/worldgen/noise/` 搬到 `mods_src/noise/data/`，引擎侧同 2 份必须删
- 模型从引擎 `assets/models/block/` 搬到 `mods_src/blocks/assets/`，引擎侧 `assets/models/` 整个目录必须删

## 五、构建同步规则

模组与引擎的 assets/data 都用独立 ALL 目标同步：

```cmake
foreach(mod_dir blocks noise)
    foreach(res_kind assets data)
        set(res_src "${CMAKE_CURRENT_SOURCE_DIR}/mods_src/${mod_dir}/${res_kind}")
        if(EXISTS "${res_src}")
            add_custom_target(copy_${mod_dir}_${res_kind} ALL
                COMMAND ${CMAKE_COMMAND} -E remove_directory
                    "$<TARGET_FILE_DIR:sandbox_engine>/mods/${mod_dir}/${res_kind}"
                COMMAND ${CMAKE_COMMAND} -E copy_directory
                    "${res_src}"
                    "$<TARGET_FILE_DIR:sandbox_engine>/mods/${mod_dir}/${res_kind}"
            )
        endif()
    endforeach()
endforeach()
```

四条硬约束：

1. **不能用 POST_BUILD**。POST_BUILD 只在被依赖的目标重新链接时执行；只改 JSON 或贴图不动代码，资源根本不同步。
2. **必须先 remove_directory 再 copy_directory**。`copy_directory` 只增不删，源里删掉的资源会残留在输出目录，索引照样能找到它 —— 表现为「删了但没生效」。
3. **`if(EXISTS)` 在配置期求值**。新增或删除某模组的 `assets`/`data` 目录后，要显式重新配置一次（`cmake -S . -B build/Debug`），否则对应目标不会出现或消失。
4. **构建要带 `VSLANG=1033`**。中文版 MSVC 的 `/showIncludes` 输出「注意: 包含文件:」，Ninja 只认英文 `Note: including file:`，结果头文件依赖一条都没记录 —— 改 `.hpp` 不会触发任何重编，改完跑起来还是旧逻辑。设 `$env:VSLANG = "1033"` 让 cl 输出英文，并在设置后 `--clean-first` 重建一次，把已有的依赖记录补对。

`windows.h` 与 rapidjson 同时出现时还需要 `NOMINMAX`：`windows.h` 会定义 `min`/`max` 宏，只要某个头文件先把 windows.h 拉进来（如 `ModLoader.hpp`），之后包含 rapidjson 就会在 `std::max(...)` 处炸掉。工程级在 `CMakeLists.txt` 给 `sandbox_engine` 加 `target_compile_definitions(... PRIVATE NOMINMAX)`。

## 六、与 MC 的差距

| MC | 这里 | 影响 |
|---|---|---|
| namespace 隔离 + 包优先级遮蔽 | 先到先得 + warn | 同名冲突只能靠日志发现 |
| tags（`data/<ns>/tags/<registry>/*.json`） | 无 | — |
| reload 可整体重载（F3+T / `/reload`） | 只在启动期收集一次 | 改资源必须重启 |
| 注册项带完整 id 与 codec 校验 | 名字取文件名 stem，无 schema 版本 | 文件改名即换 id，格式错只报一条 warn |

## 七、后续按同一规则扩展

| 目标 | 源 | 落点 | 归类理由 |
|---|---|---|---|
| 方块定义 | `BuiltinBlocksMod.cpp` 里的硬编码 6 个方块 | `mods_src/blocks/data/blocks/*.json` | 属性是逻辑数据；名义上归 data，但 MC 的方块本体是代码注册，搬之前得先定 schema 与 id 分配规则 |
| 字体 | `VulkanContext.cpp` 里硬编码的 `assets/textures/font/ascii.png` | 走索引 `textures/font/ascii.png` | 引擎基础设施，留引擎侧 |

每一步的验收方式固定：先看 `[Resource] ... 新增 N 个文件`，再看消费方日志没有「未找到」，最后跑两个预设比对基准（default 81 列 / 82944 方块 / 地表 3..3 / 81 chunk；noise 695641 方块 / 地表 26..38 / 220 chunk）。
