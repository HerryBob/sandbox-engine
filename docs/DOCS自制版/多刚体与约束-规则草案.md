# 多刚体与约束 —— 规则草案（A：拆分 / 关节 / 原点）

> **状态**：草案，待评审。**本文件只定规则，不含实现**。
> **范围**：一个"结构"（structure）如何拆成 N 个物理部件（part）、部件之间如何生成关节（joint）。
> **非目标**：模组结算（07 kinetics 的转速/扭矩）、渲染 LOD、流体。
>
> 关联：`docs\七大维度与一大底座设计\09-模组化边界.md` §九（多刚体+约束表的决策）、
> `physics\PhysicsState.hpp`（`PhysicsBody` / `PhysicsConstraint` 已按多体建好）。

---

## 0. 一句话方案

**拆分由「方块类型的关节属性」决定，不由模组代码直接指定**：

```
结构 → ① 按"关节方块"切开 → N 个部件
     ② 相邻部件之间，按关节方块的类型/轴 → 1 个约束
     ③ 每个部件的原点 = 其方块包围盒中心（与现在单刚体一致）
```

这样 **存档只需存方块**，加载时用同一套规则就能**确定性重建**出部件与约束 —— 这是"不把物理细节写进存档"的前提（见 `存档系统设计.md` §1）。

---

## 1. 术语

| 词 | 含义 |
|---|---|
| **结构 structure** | 用户打包出来的一组方块（协议里的 `contraptionId`，语义改为结构 id）|
| **部件 part** | 结构拆出来的一个刚体（Jolt `BodyID` + `PhysicsBody`，`bodyId` 唯一）|
| **关节 joint** | 两个部件之间的约束（`PhysicsConstraint` + Jolt `Constraint`）|
| **关节方块** | 类型上带关节属性（`jointKind != None`）的方块，是"切分位置"与"约束类型"的唯一来源 |
| **接触面** | 两个不同部件的方块之间的 6 邻接边（一对相邻坐标）|

## 2. A① 拆分规则

### 2.1 输入 / 输出

```
输入： blocks   —— 结构内的方块（世界坐标，打包前）
      registry —— 方块注册表（查 jointKind / jointAxis）
输出： parts    —— [ { origin(取整), blocks(局部坐标) } ... ]      至少 1 个
      joints   —— [ { partA, partB, kind, axis, anchorA, anchorB, ... } ... ]  可为空
```

### 2.2 算法（分三步）

**步骤 1：标记关节方块**
对每个方块查注册表：`jointKind` ∈ {None, Hinge, Slider, Fixed, Point}。
`None` = 普通方块（不切分）。

**步骤 2：按关节方块切分（6 邻接连通分量）**

```
把"关节方块"从普通方块的图里暂时摘除；
对剩余普通方块做 6 邻接连通分量 → 每个分量 = 一个候选部件；
再决定关节方块自己归谁（见 2.3）；
若连通分量只有 1 个 → 该结构就是 1 个部件（= 1.0 的行为）
```

**为什么用连通分量而不是"按关节方块切开就完事"**：
一个结构可能有多个关节方块连在一起（例：一根轴上串 3 个铰链），
连通分量保证"切开后每块仍然是连通的刚性体"，不会出现悬空碎片。

**步骤 3：定原点 + 局部坐标**（见 §4）

### 2.3 关节方块归属规则（**二选一，需要拍板**）

| 方案 | 规则 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）** | 关节方块**归它在步骤 2 里接触到的第一个部件**（按坐标字典序最小者）| 实现简单、必有一解 | 关节方块自身的质量归到某一侧，物理上略偏 |
| B | 关节方块**不参与任何部件**（只作为约束的锚点）| 质量分配干净 | 结构里出现"空洞"，掉落物/碰撞会漏一格 |

**推荐 A**：关节方块是"结构的一部分"（用户看得见、能挖），不能凭空消失。

### 2.4 不变量（实现后必须自检）

```
I1 覆盖：输入每个方块恰好属于一个部件（不重不漏）
I2 确定性：同输入（同方块集合 + 同注册表）→ 同输出（部件数、顺序、原点、关节全同）
I3 连通：每个部件内部按 6 邻接连通
I4 单块退化：只有 1 个部件时，原点/局部坐标与现有单刚体实现**逐字节一致**
I5 关节有界：关节数 ≤ 部件数 - 1（连通结构的生成树上界）
```

### 2.5 边界情况

| 情况 | 规则 |
|---|---|
| 结构全是关节方块（没有普通方块） | 不是合法结构 → 打包失败（返回错误，让业务层提示"结构必须至少含一个非关节方块"）|
| 两个部件不接触（被关节方块隔开） | 关节锚点由该关节方块位置给出（见 §3.3）|
| 关节方块连着 3 个以上部件 | **不切**：只有"恰好两侧"的接触才算关节；三侧以上按普通方块处理（避免歧义）|
| 部件方块数 > 上限（例如 4096）| 打包失败（防止一个 body 太大导致 Jolt 复合形状构建超时）|

## 3. A② 关节推导

### 3.1 触发条件

两个不同部件之间存在**接触边**（方块 A ∈ part1，方块 B ∈ part2，且 A、B 6 邻接）。
接触边两侧必须至少有一侧是**关节方块**（否则它们本就属于同一部件，不会跨部件）。

### 3.2 类型与轴从哪来（**关键约束**）

现状：`Block = {type, pos, contraptionId}` —— **没有 per-instance 朝向/状态**；
`BlockInfo` 只有 hardness/renderType/texture/model/mass/friction。

因此 1.0/07 最小可行方案：**把关节属性放在方块类型上**（注册表字段，不是实例字段）：

```cpp
// BlockInfo 新增（草案）
enum class JointKind : std::uint8_t { None = 0, Hinge, Slider, Fixed, Point };
enum class JointAxis : std::uint8_t { X = 0, Y, Z };   // 只在 Hinge/Slider 有意义

JointKind jointKind = JointKind::None;
JointAxis jointAxis = JointAxis::Y;   // 默认绕 Y（竖直轴，最常见的转子）
```

模组注册"铰链方块"时声明 `jointKind=Hinge, jointAxis=X` 即可。

**为什么不做 per-instance 朝向**：那需要方块状态系统（block state / 4-bit 方向位），
是独立的大改动（存档格式、网格 UV、挖放逻辑都要动）。**本轮明确不做**，等 block state 落地后再让
"关节轴向"从类型级升级到实例级。

### 3.3 锚点与轴

设接触的两个方块为 A（part1）和 B（part2），两者中心为 cA、cB：

```
锚点（世界）= (cA + cB) / 2            // 接触面中心，天然在两块之间
     anchorA = 锚点 - origin1          // part1 的局部坐标
     anchorB = 锚点 - origin2          // part2 的局部坐标
轴    = 注册表 jointAxis 对应的单位向量（世界坐标；B 的初始旋转为单位阵，故局部=世界）
限角  = BlockInfo 可选字段 minAngle/maxAngle（默认 -π..π = 不限制），阻尼默认 0
```

**注意**：若两侧关节方块类型不一致（一侧 Hinge、一侧 Slider），**取字典序较小的部件那一侧的类型**并记一条 WARN —— 规则必须确定，不能依赖遍历顺序。

### 3.4 合并规则

同一对部件之间**最多一个约束**：多处接触（例如两块之间有两个接触面）
→ 只取**第一个**（按接触边排序），其余忽略并计数（用于诊断）。

**理由**：多约束同一对刚体在 Jolt 里会过约束（相互打架），表现是抖动/爆开。

### 3.5 没有关节方块的结构

→ 1 个部件、0 个约束 —— **这就是 1.0 的默认路径**，行为与今天完全一致。

## 4. A③ 原点与坐标系约定

| 项 | 约定 | 理由 |
|---|---|---|
| 部件原点 | 该部件方块**包围盒中心取整**：`origin = ((min+max)/2)`（整数除法，与现有代码一致）| 与单刚体现有实现逐字节一致（I4）|
| 部件内方块坐标 | `block.pos - origin`（整数）| 渲染 mesh 用这套局部坐标（`BodyMeshStore` 现在就是这么做的）|
| 部件位姿 | 世界坐标位置 = **原点当前的世界位置**（Jolt body 的位置即原点位置）| 与现有 `body.x/y/z = origin` 一致 |
| 关节锚点 | 各自**局部坐标**（相对本部件原点）| Jolt `HingeConstraint` 的 `SetPoint1/2` 用局部点 |
| 初始旋转 | 单位四元数 | 打包时结构摆正（与现在一致）|

**影响**：多部件时每个部件有自己的原点；"结构级世界坐标"不再有单一值 →
协议与渲染都要按部件传（见前置缺口 §7）。

## 5. A④ 约束类型集合与 Jolt 映射

| 类型 | Jolt 类 | 本轮 | 参数 |
|---|---|---|---|
| **Fixed** | `FixedConstraint` | ✅ 先做 | 无（完全刚性连接）|
| **Hinge** | `HingeConstraint` | ✅ 先做 | 轴 + (可选)限角 + 阻尼 |
| Slider | `SliderConstraint` | ⏸ 后置 | 轴 + 限位 |
| Point | `PointConstraint` | ⏸ 后置 | 锚点（球铰）|

**为什么先做这两个**：07 的最小可用形态是"转子绕轴转"（Hinge）+ "拼起来不散架"（Fixed）；
Slider/Point 等真有玩法需求再加（每个都是独立的参数集）。

## 6. A⑤ 稳定性目标（可测判据）

多体连接必然比单体难解。先定目标再调参数：

| 指标 | 目标 | 怎么测 |
|---|---|---|
| 锚点漂移 | 两部件锚点相对距离 100 步内变化 < 1 cm | Jolt 集成测试（固定步长，无外力）|
| 限角有效 | Hinge 在重力下摆动不超过 `[minAngle, maxAngle]` | 同上 |
| 部件不穿透 | 相邻部件方块最短距离 ≥ 0（不互相插入超过 0.1 格）| 同上 |
| 静止收敛 | 静止结构 200 步后速度 < 0.01 m/s | 同上 |

**solver 参数**（Jolt `PhysicsSettings`：`mNumVelocitySteps` / `mNumPositionSteps`）
先保持默认，达不到目标再调 —— 调整要记录"改了什么、指标从多少到多少"。

## 8. 需要你拍板的 6 个问题（带我的建议）

| # | 问题 | 建议 |
|---|---|---|
| 1 | 关节方块归属：A（归首个部件）还是 B（不参与部件）| **A**（不让方块凭空消失）|
| 2 | 关节属性放**类型级**（注册表）还是等 **per-instance 朝向** | **类型级**（per-instance 要 block state，是独立大件）|
| 3 | 首发的约束类型 | **Fixed + Hinge**；Slider/Point 后置 |
| 4 | 同一对部件多个接触 | **只保留 1 个**约束（多约束会过约束）|
| 5 | 关节方块连 3+ 部件 | **不切**（当普通方块），避免歧义 |
| 6 | 部件方块数上限 | **4096**（超过则打包失败并回报原因）|

## 9. 一个完整例子（用来验规则是否自洽）

```
结构：3×3×3 的石头，中间一层 y=1 的那一排 z=1 面上放 1 个"铰链方块"（jointAxis=Y）
      坐标 x∈[-1,1], y∈[-1,1], z∈[-1,1]，铰链在 (0,1,1)

步骤 1：铰链方块 = (0,1,1)
步骤 2：摘掉它后，剩余 26 块仍连通 → 只有 1 个连通分量
        ⇒ 按 2.3 方案 A，铰链方块归该部件
        ⇒ parts = 1，joints = 0      ← 注意：1 个铰链不切开任何东西
预期结论：单侧关节方块不产生部件切分（需要"两个不同部件之间"才有约束）
```

**第二例（真正切开）**：

```
3×3×3 石头，把 (0,1,0) 与 (0,1,1) 都换成铰链方块（同一轴 Y）
摘掉两个铰链后：z=-1 那层与 z=1 那层不再连通（z=0 被打断）
  → 2 个连通分量 = 2 个部件
  → 两部件唯一的接触边 = (0,1,0)-(0,1,1) 两个铰链相邻
  → 1 个 Hinge 约束，锚点 = 两块中心中点
预期：parts=2, joints=1, kind=Hinge, axis=Y
```

**这两例就是第 1 步 selftest 的用例**（纯 CPU，不需要 Jolt）。
