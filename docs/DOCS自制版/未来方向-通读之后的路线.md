# 未来方向 · 通读之后的路线

> **状态**：组织定案（2026-11-16），未动工。
> **前置**：`src/` 通读完成 + 缺陷分诊 + T1 headless 冒烟。
> **指导思想**：**先做出各种功能的原型，再各自优化**（作者定），本文补的是这条原则的边界与顺序。

---

## 一、定案顺序

```
通读收尾（分诊 + T1 冒烟 + 文档对齐）
   ↓
① block state 化
   ↓
② Jolt 物理迁移（S0 → S3）
   ↓
③ 存档机制
   ↓
④ 功能原型（P1–P5，可穿插）
   ↓
⑤ 各自优化（等 profile 数据）
```

### 为什么 state 在最前

- `PaletteEntry` 的语义要从"方块 id"扩成"state id"，而**存档直接存它** → 越晚改，迁移数据越多。
- Jolt 的质量属性要**按 state** 读（Sable 的 `sable:mass` 是按 block-state 定义的）→ 没有 state 就没法做质量映射。
- 所以：**state 是唯一"越晚做越贵"的地基。**

### 为什么 Jolt 在存档之前

存档要存的物理状态，正好是 Jolt 会重新定义的那部分：

| 现在（手搓） | Jolt 之后 |
|---|---|
| `RigidBody{ x,y,z, vx,vy,vz, blocks[] }` | `BodyID` + transform（**质心基准**）+ 线/角速度 |
| 基准点 = 打包时的世界原点（S13） | 基准点 = 质心 |
| 方块局部坐标 = 原世界坐标 | 局部坐标需平移到质心 |

先做存档 = 存旧语义，换 Jolt 后要**改第二遍格式**。且此时世界数据最少（6 方块 / 1 玩家 / 1 演示刚体），改格式几乎无痛。

---

## 二、"先原型后优化"的边界

这句话对**实现**正确，对**契约**危险。按"改起来多贵"三分：

| 类别 | 例子 | 政策 |
|---|---|---|
| **可逆**（实现 / 性能） | `reserve` 偏小、hash 强度、O(N) 查找、气动系数、渲染特性 | ✅ 原型先行，等数据再优化 |
| **半可逆**（改一处要连带改几处） | 刚体基准点、协议字段、线程边界 | ⚠️ 可以原型，但**改的时候一次改透** |
| **不可逆**（有数据后就锁死） | **存档格式**、`ChunkData` 存储格式、模组 API 版本 | ❌ **先冻结形状，后填实现** |

> "冻结形状"≠"先实现"：只写下字段清单、版本号、预留位；实现可以是最笨的全量 dump。

---

## 三、原型阶段的三条纪律（防接口漂移）

真正的风险不是性能，是**每个原型各自发明一套临时接口**：

1. **原型只允许新增，不修改已有契约** —— 比如方块选择器必须走 `World::placeBlock`，不能直接写 `chunks_`。
2. **原型必须走既有入口**（`World` / 两座桥 / `modapi`），哪怕绕路。
3. **每个原型结束写一行"临时妥协是什么"** —— 例如"选择器只支持 6 个内置方块，索引写死"。

---

## 四、存档：只存语义状态

Jolt 自带 `SaveState` / `RestoreState` 二进制快照，但**不建议当作存档格式**：

| 存什么 | 优点 | 代价 |
|---|---|---|
| Jolt 快照 | 一行调用、恢复即完整 | 绑死 Jolt 版本；旧档可能读不了；不可读、无法手改 |
| **语义状态（推荐）** | 跨版本可迁移、可调试、可手改 | 要自己写"重建 body" |

### 存档三样内容

```
① 已加载的 chunk 集合（含 palette）
② 复合体表：bodyId → { transform, 线速度, 角速度, 方块列表(局部坐标 + 类型) }
③ 玩家：位置、朝向、体态
```

**关键**：`chunk` **不存 `contraptionId`**（刚体内方块不进 chunk），所以复合体必须单独一张表，且加载顺序是"**先地形、再复合体**"。

---

## 五、缺陷处理：按"正确性 / 性能"二分，不按优先级

| 类型 | 例子 | 处理 |
|---|---|---|
| **性能类** | `reserve` 偏小、hash 强度、线性查找、`std::function` 开销 | **全部推迟**，等 profile。现在优化等于猜 |
| **正确性类** | seqlock 重排、`Registry` 异常安全、`erase` 线程安全、跨 DLL 双实例、空指针/悬垂 | **原型阶段就修** |

> 原则：**原型阶段允许慢，不允许错。**
