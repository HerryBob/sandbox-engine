# 架构决策：业务线程拆分（base/ + World + 桥 + 调度壳）

> 日期：2026-10-28 · 状态：已实现验证（commit c6d7530 = 数据域；桥拆分 commit 待补）

## 1. 背景与动机

原 `BusinessWorld` 是**五域聚合**：世界数据（chunks_+锁）、时间（simTime/tick）、三座桥（物理指令/回执、渲染变更）、基础动作（放置/破坏+边界标脏）、统计计数全塞一个类。

问题：心智模型装不下 → 掌控力下降 → 改一处牵五处。

## 2. 拆分结果：三层 + 桥

```
src/business/
├── BusinessWorld.hpp/.cpp   调度层（壳）
│     时间推进 · 三桥委托 · 玩家输入消费 · 业务统计
├── World.hpp/.cpp           状态层（数据真源 source of truth）
│     chunks_ + blocksMutex_ + 查询 + 动作入口 + 脏集合
├── base/BlockActions.*      规则层（功能函数）
│     tryPlace / tryRemove / markDirtyWithBoundary / DIRTY 常量
├── PhysicsBridge.hpp/.cpp   通信层（B1+B2）
│     物理指令队列 + 回执队列 + 指令状态机 + 回执解析
└── RenderBridge.hpp/.cpp    通信层（B3）
      变更事件队列 + flushChanges（peek→push→clear）
```

| 层 | 有状态？ | 有锁？ | 知道"何时改"？ | 知道"怎么改"？ |
|---|---|---|---|---|
| BusinessWorld（调度） | 是（时间） | 否 | **是** | 否（委托 World/桥） |
| World（状态） | 是（数据） | **是** | 否 | 否（委托 base） |
| base/（规则） | 否（纯函数） | 否 | 否 | **是** |
| PhysicsBridge / RenderBridge（桥） | 是（队列+待发状态） | 否（无锁队列） | 否 | 是（通信协议） |

职责一句话：**调度层决定何时动、状态层持有数据并保证安全、规则层定义动法、桥层定义怎么跨线程传**。

## 3. 一次放置/破坏的完整路径

```
玩家点击 → BusinessWorld::processPlayerInput（DDA 射线检测）
         → BusinessWorld::placeBlock/removeBlock（薄壳）
              ├─ world_.placeBlock/removeBlock      ← 加锁
              │     └─ base::tryPlace/tryRemove     ← 裁决+写入+标脏
              └─ 失败 → 拒绝计数；成功 → 排队指令（wantPlace_/wantRemove_）
下次 tick 边界 → syncToPhysics 发指令给物理线程
              → flushChanges 采集脏 chunk 发变更事件给渲染线程
```

关键：**所有方块修改只有一条合法路径**（World 加锁入口），规则只有一份实现（base 纯函数），调度只负责时机。

## 4. 关键设计决策

### 4.1 锁跟着数据走
- 全引擎**只有 World 加锁**（blocksMutex_ 保护 chunks_）。
- base 纯函数**无锁**，线程安全由调用方保证（业务线程经 World 调用 = 天然持锁）。
- 之前锁在 BusinessWorld，未来任何新调用方都要自己记着加锁 → 注定漏锁。

### 4.2 dirty 集合：peek/clear 一对（保住"push 成功才清空"语义）
- 原 `flushChanges`：push 变更事件**成功**才清空脏集合，失败下 tick 重试。
- 若设计成"取出即清空"（take），push 失败（队列满）会**丢事件 = 渲染端漏重建**。
- 最终：`peekDirtyChunks()`（拷贝查看，不消费）+ `clearDirtyChunks()`（成功后由调用方清）。
- dirty 只被业务线程触碰（动作写入/flushChanges 消费）→ 不加锁。

### 4.3 公开接口全保留 → 外部零改动
- main.cpp / Renderer / 物理线程调用点全部不动（验证：编译零错 + 行为等价）。
- 查询五个（blockCount/renderSnapshot/findBlock/chunkCount/forEachBlockInAABB/chunkDirtyFlags）→ 转发 `world_.xxx()`。
- 动作两个（placeBlock/removeBlock）→ 薄壳（裁决委托 World，计数+排队指令留壳）。

### 4.4 指令状态机搬入 PhysicsBridge
- wantSync_/wantPlace_/placePos_/placeType_/wantRemove_/removePos_ 已从 BusinessWorld 搬入 PhysicsBridge（桥拆分，2026-10-28）。
- 理由：它是"跨线程通信的发送端状态"，本就不属于调度逻辑——调度只负责"调用 syncToPhysics"，"下一条发什么"由桥决定。
- 桥由装配层（main）创建，业务线程构造注入引用；物理/渲染线程从桥拿队列端点引用。生命周期：main 栈对象早于四线程创建、晚于四线程停止，安全。

### 4.5 时间留 BusinessWorld
- simTime_/ticks_ 属于"调度节奏"，不属于"世界内容"，留壳。

## 6. 四线程桥盘点（全貌；B1-B3 已由独立桥类持有，2026-10-28 实现）

| 桥 | 方向 | 形态 | 归属 | 状态 |
|---|---|---|---|---|
| B1 物理指令 | 业务→物理 | 队列桥（SPSCQueue） | PhysicsBridge | 已实现 |
| B2 物理回执 | 物理→业务 | 队列桥 | PhysicsBridge | 已实现 |
| B3 变更事件 | 业务→渲染 | 队列桥 | RenderBridge | 已实现 |
| B4 玩家输入 | 输入→业务 | 状态桥（共享原子） | PlayerInput | 已存在 |
| B5 相机状态 | 输入→渲染 | 状态桥（共享原子） | CameraState | 已存在 |
| B6 实体位姿 | 物理→渲染 | 队列桥（未来） | RenderBridge（预留） | 未建 |

桥拆分要点：
- **PhysicsBridge（B1+B2）**：持两条 SPSC 队列（512）+ 指令状态机 + 回执解析（BlockMoved/BlockSetSize → 原子投影）。
  - 业务侧：queueSync/queuePlace/queueRemove（排队）、syncToPhysics(snapshot)（按优先级发一条）、receiveFromPhysics()（收光回执）。
  - 物理侧：commandQueue()/resultQueue() 引用（装配层分发；物理线程零改动）。
- **RenderBridge（B3）**：持变更事件队列（256）+ flushChanges(World&, tick)（peek→push→clear 语义归桥）。
  - 渲染侧：changeEventQueue() 引用（Renderer 零改动）。
- **main.cpp 装配**：删 3 个裸队列 → 建两个桥 → BusinessWorld 注入桥引用 → 物理/渲染线程从桥拿端点。
- **push 失败语义保留**：指令/事件 push 失败不清待发位/脏集合 → 下 tick 重试（可延迟，最终一致）。

**桥 = 跨线程数据唯一通道，桥外零共享** → 并发安全靠结构，不靠人记。

## 7. 其他线程的拆分策略（明确"不沿用同法"）

| 线程 | 策略 | 理由 |
|---|---|---|
| 物理 | 按阶段轻拆（桥端点+模拟核心） | 职责天然两段；未来再动 |
| 输入 | 几乎不拆 | 不会怎么涨（键盘鼠标+未来手柄） |
| 渲染 | 沿 render/utils/ + optimization/meshing/ 续拆 | 已有技术职责划分 |

## 9. 与注册表机制的关系

- World 只存 `uint8_t` 类型号，不解释含义 → 类型→行为 的映射在注册表（BlockInfo/PhysicsInfo）。
- base 动作规则只认类型号 → 未来模组加方块不需要改 World/base。
- 渲染面剔除消费 BlockInfo（opaque）→ 方块语义下沉到注册表，世界层保持"数字仓库"。
