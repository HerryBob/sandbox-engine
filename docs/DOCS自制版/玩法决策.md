# 玩法决策

# MC原版 
## 四种元素
   >生存: 应对威胁——天黑、怪物、饥饿；保命、建庇护所、回血
   >探索: 横向探索新地形——矿洞、下界/末地、遗迹、找BOSS
   >发展: 资源积累与成长——装备升级、基地扩大、红石自动化、农场牧场的复利
   >表达: 留下"我的痕迹"——建奇观、改地形、收集展示、红石炫技

# 项目目标
>在四种元素的基础上加一层物理化
>物理化不走群峦(MC模组)那种全面物理化 太过写实 玩法变窄
>各种元素之间要有联动 要形成循环
>MC四元素全保留 = 保留四种元素的框架，不是玩法复刻

# 设计原则（总纲）
>凡"把现实细化成时刻关注的变量" → 砍掉或简化（模组路线，不做）
>凡"局部化、可预判、直接结算" → 保留（MC原版路线）
>不做鞘翅式特化玩法——不为单一玩法造专门道具；玩法从系统自然延伸（2026-10-30）
>全功能方块化：游戏只提供最小功能方块集（基础/运动/动力/逻辑/传输/交互 6 类），玩家用积木自由组合出一切子系统（交通/物流/防御/采矿/火车等）——不单独开发系统级玩法（2026-10-30）
>引擎通用能力 = 玩法不特化的前提：结构运动约束/连续传输/批量处理/流式加载/动态渲染做进引擎层（通用原语），功能方块才能保持原子；MC 底层限制（离散方块状态/无结构抽象/区块加载限制/实体上限/静态渲染/单线程 tick）是 mod 特化的根因，自研引擎无此限制（2026-10-30）

# 世界骨架（定案）
>大陆海洋型（定案）；海洋 = 现实级（隐式海 + 海面视觉 + 局部浅水，规模/深度/岛链后置——2026-10-29 与流体定案 §14 对齐）
>上层悬浮空岛：不做（砍掉）
>物理化载体：暂不考虑（后置）
>风/温差源/怪物/物理化在大陆地形上标注，表现方式待地形细节讨论

# 风（环境元素 · 已纳入）
>参与玩法，不是纯氛围
>产生方式类似现实，但要简化、不能复杂

## 现实主干（影响最大的四个方面）
>温差：发动机——温差→气压差→风从冷吹向热，一切风的根本
>地形：整形器——峡谷收窄加速（狭管效应）、岛背风平静（绕流）
>高度：自由度——越高风越大（脱离地面摩擦）
>湍流/阵性：脾气——忽大忽小，用噪声模拟即可

## 简化模型（分层叠加，全部静态规则、无实时模拟）
>风场 = **3D 矢量场**（水平 + 垂直分量；垂直是计算的自然成分，不单独编写模块）
>骨架：静态温差源（热源/冷源标注）→ 主风线（冷→热，水平）
>修正：地形系数（峡谷×加速、背风×减弱）× 高度函数
>垂直分量（自然产生）：温差 → 热源区域空气上升（热气流柱）；地形 → 迎风面抬升/背风面下沉（山脊风）
>扰动：噪声阵风（伪湍流）
>后置：风暴事件（天边风暴云逼近→全域风增强，待定）

## 砍掉的
>科里奥利力/全球环流——不需要全球信风带
>温度模拟系统——不做，只标注温差源
>海陆风/昼夜周期——后置可选

## 垂直气流（风场自然成分 · 定案 2026-10-30 · 不单独编写）
>定位：垂直气流 = 风场 3D 矢量场的**自然成分**，不是独立模块——风场计算时自然产生，不需要单独编写
>产生：温差 → 热源区域空气上升（热气流柱）；地形 → 迎风面抬升/背风面下沉（山脊风）——见"简化模型"垂直分量行
>热气流柱特性：受热区域（暗色地表/沙漠/岩石，用温差源标注，不做温度模拟）+ 白天时段；区域化/脉冲式
>山脊风特性：持续稳定、地形相关
>可读性：玩家一眼读出——积云/热区 = 有热气流、山脊迎风面 = 有上升风（可预判、直接结算）
>用途：垂直探索工具（滑翔升空通道）——平原靠热气流、山地靠山脊风；不做专门滑翔道具（见"不特化"原则）

## 风与实体（已记，细节后议）
>风必须影响物理实体（玩家/动物等）——推挤，这是参与玩法的底线
>推力按现实公式：F = ½ρC_dAv²（风阻力），力∝风速平方
>受风条件：高度够高 × 风速够强 × 受风面积够大，三门槛都过才推
>实体属性：质量 + 受风系数 k = ½ρC_dA（一个数）
>手感分级：按 F/体重 比——有感觉 / 明显推挤 / 站不稳 / 吹飞
>性能：风场低频更新 + 区域门槛过滤 + 小型实体不参与；公式必要时可简化（线性/查表）

## 怪物来源方向（已记，不选具体生物）
>怪物来源要合理：现实原型（有现实根基）或奇幻自洽（世界观内说得通）
>方向：挂接世界独有逻辑——风/悬浮/垂直
>现实参考：滑翔捕食者（借风扑击）、热气流盘旋（上升气流指示物）、风媒传播（空岛间传种）、借风迁徙（顺风来袭）
>不选择具体生物（待定）

## 威胁设计（定案 2026-10-30）
>威胁驱动 = 环境遭遇 + 行为引发（混合）：危险区域/黑暗/特定地形刷怪（玩家自主决定去不去）；大规模自动化等行为可"吸引"威胁（玩家可决定是否触发）
>排除：定时波次式 raid（Factorio 式拆家）——会把玩家重心逼成"扩产+堆防御"，四元素塌成发展一个元素
>威胁对象随玩家重心转移：前期威胁本体（血量）→ 后期威胁造物（拆结构/干扰自动化），混合路线
>强度上限：敌人强度封顶，不随玩家科技无限螺旋（避免军备竞赛）；玩家科技超过上限后威胁退场，只在特定高危区维持
>飞行怪少而稀有：保住玩家"空中安全区"（空中基地/移动结构的躲避路径）；飞行怪只在特定危险区出现，不是常态
>玩家应对 = 躲 或 造安全区：躲（跑路/移动结构/空中基地脱离）；造安全区（庇护所/据点语义 = 把危险区变成安全区，不是硬抗波次）
>定位：遭遇 + 能跑（区别于 MC"遭遇+硬抗"、Factorio"波次+硬抗"）

# 生物设计框架（已记 2026-10-29）
>双层：基础生物 + 特色生物
>主题负责"生物是什么"（玩法概念），地形/群系/风/高度多维负责"生物在哪"（空间位置）
>基础全图分布 + 特色挂接系统——避免 MC 后期"每群系专属"的碎片化

## 基础生物（生态位设计 · 全图分布 · 现实原型）
>生态位 4 类：食草（食物+养殖）/食肉（威胁+材料）/无害小动物（氛围）/威胁怪物（夜间节奏）
>数量控制：全图分布上限 ~12 种（再多就碎片化）；特色生物另算
>已保留：猪 / 牛 / 羊 / 鸡（现实畜牧类）、狼（食肉 + 未来伙伴）
>氛围类：着重研究（挂接系统，不是装饰性小动物）
>敌对怪物：暂不讨论（后置）

## 氛围动物（系统代言 · 挂接风/天气/昼夜/地形）
>定位：世界"活着"的表达层——每只动物 = 多个系统的交汇点（风/天气/地形/视听/性能）
>设计拆解：先定"要表达的系统"→ 按系统配代言动物（每个系统 1-2 种）→ 逐动物细化
>首批定案（风系，2026-10-29）：
  燕子 —— 陆地代表（全图草地/平原/村庄），品种 = 家燕（Barn Swallow，2026-10-29 选定）
    群体捕食翻飞 · 顺风掠逆风扑 · 风大低飞贴地 · 雨前低飞预警（天气白送）
    配色基准：深蓝背/头 + 红棕喉 + 浅米腹 + 长叉尾（三色分区，32x32 像素友好）
  海鸥 —— 沿海/海洋代表（挂接现实级海洋），品种 = 银鸥（Herring Gull，2026-10-29 选定）
    气流滑翔几乎不扇翅 · 风大贴海面低飞/陆地停栖 · 沿海集群
    配色基准：灰背/翼（翼尖黑斑）+ 白身腹 + 黄喙红斑 + 粉腿（三色分区，32x32 像素友好）
>统一逻辑：风越大、飞得越低/越歪——玩家一眼读出风速
>其他系统代言（天气→蛙 / 昼夜→萤火虫 / 地形群系→蝴蝶松鼠等）：待定

## 动物伙伴（狼 · 陪伴系统核心载体 · 2026-10-29）
>定位：慰藉体系的核心——"陪伴"情感功能由动物伙伴专门承担
>分工：狼 = 陪伴；氛围动物 = 世界感；自动化 = 成就感；遗迹 = 教学/探索（实物示范机械构造，叙事留白——职责不重叠）
>**AI 着重设计**（陪伴效果全靠 AI 行为表现——伙伴的"活着感"是核心）
>基础（必做）：驯服（喂食收服）/ 跟随·召唤（始终在身边）/ 战斗协助（一起对抗怪物）/ 命名（情感锚点）
>互动深度：先做基础；指令（坐下/待命）/ 抚摸反馈 / 毛色变种 → 后置
>死亡：MC 模式（会死、死了就没了——失去也是情感的一部分）
>不做：忠诚度数值 / 情绪条 / 养成 RPG 化（违背"不过于复杂"）

## 生物动画（程序化动作生成 · 定案 2026-10-30）
>定位：生物动画技术路线 = **程序化动作生成**（动作生成器）——一次引擎能力，全部生物复用；不做手工 K 帧动画
>核心：动作 = 肢体数量 × 运动状态的**函数**（不是动画序列，是程序算出来的）——走路/转身/变相/停止/起步都是"脚与身体运动关系"的不同实例
>统一模型：**相位传播（phase propagation）**——步态相位沿身体轴传播，一个引擎覆盖所有形态：
  双足（相位差 π 交替）/ 四足（对角步态，左前+右后同组）/ 三足（三角轮换，游戏自由）/ 蜘蛛 8 腿（四足对角的 8 点版）/ 蜈蚣 N 腿（行波 metachronal wave，腿波浪依次抬）/ 蛇（连续波动 lateral undulation，身体正弦波向后传播推进）/ 单足（仅 idle，现实无移动单足）
>底层机制：脚目标点规划（foot placement）+ IK 求解（FABRIK）；运动状态机（idle/walk/turn/stop/start/变相）由 v（速度）/ω（角速度）/a（加速度）驱动——不存动画帧
>形态参数表：腿数 N / 相位差 / 波速 / 身体分段数（蛇=分段连续，蜈蚣=分段离散）——新生物 = 骨架拓扑 + 参数表，自动获得全套动作
>技术难点：转身/变相脚规划（防交叉腿）、状态过渡平滑（脚落地锁定、抬起才重新规划）、蛇形 3D 波动+地形贴合（最难）、多足性能（只对支撑脚 IK，空中脚简单轨迹）
>实现路线：先四足/双足闭环（畜牧+伙伴最大群体）→ 蜘蛛/多足 → 蛇形后置；飞行（翅膀频率程序化，正弦扇翅起步）后置
>先例验证：Spore（任意肢体数量自动动画）、Rain World（蜈蚣/蛇形程序动画）、Kenshi（程序化角色动画）

# 发展元素（已记 · 灵感来源：机械动力）
>灵感来源：机械动力（Create mod）及其附属航空学（Aeronautics）
>理由①：机械动力/航空学的动态结构（contraptions——super glue 粘方块群 + 底盘装配 + 滑轮/活塞驱动）本就适合物理化结构，"结构作为整体运动"是成熟范式
>理由②：机械动力动态化方块（可视化机械、动画式交互——轴/齿轮/皮带/加工动画）视觉与可玩性充足，是自动化玩法的体验核心

## 借鉴清单（机械动力的可提炼项）
>单一能源介质（所有机器吃同一套能量，玩家只学一套）
>可视化传输（轴/齿轮/皮带——能量流动看得见）
>应力预算（源提供容量、机器消耗，全局超载全停 = 设计约束）
>动力源升级线（水车 → 风车 → 蒸汽机，渐进复杂度）
>渐进自动化（传送带 → 机械臂 → 时序/红石集成）

## 我们的版本（结合物理化 + 风）
>可视化机械（动态方块：轴/齿轮/皮带/加工动画）
>物理化后果（结构承重/受风/塌方——宏大尺度结构物理，接回"物理化载体"）
>真物理动力源（差异化王牌）：
  水车 ← 河流流速（浅水模型）
  风车 ← 风场（风系统）
  蒸汽机 ← 气体压强（Steam，气体表）
>差异化：Create 的水车/风车是环境判定（旁边有水/风即可）；我们是真物理驱动（输出 = f(真实流速/风速/压强)）——能源与世界物理深度耦合

## 能源体系（定案 2026-10-29）：三种能量
>旋转（动力）/ 线信号（有线控制）/ 无线电波（无线控制）——三种能量，各司其职
>能源类型与 MC 同量级（MC：燃烧/红石 两种；我们：三种，比 MC 多一种无线）

### 旋转（动力）
>参数就两个（机械动力的少而精）：
  转速 RPM（转多快 → 设备工作速度 = 视觉语言）
  应力 SU（负载预算：源提供容量、设备消耗，超载全停 = 设计约束）
>源：水车 ← 流速 / 风车 ← 风速 / 蒸汽机 ← 压强 → 旋转
>传输：轴 / 齿轮 / 皮带（物理网络，可视化）
>消费：设备（钻/锯/泵/研磨——统一旋转动画语言）
>强度可视化：设备转速 = 能量仪表（弱→慢、强→快）
>齿轮比（大带小翻倍速等）：后置可选（初始设备定速）

### 线信号（有线控制 · 自动化内容 · 不耗能）
>原型：Redstone Pen 模组（线画在方块表面，不占空间）
>核心特性：
  表面轨道画线（笔工具绘制/擦除，线不占方块）
  选择性连接（轨道默认不激活所在方块，显式加连接器）
  多路共享空间（多条线同方块交叉共存、互不干扰）
  信号不耗能（电线只做信号，能量约束由旋转应力 SU 承担）
>基础元件 4 种（对标 MC 拉杆/线/火把/中继器，学习成本低）：
  ① 开关（拉杆/按钮/压力板）——信号源，**方块**（可操作面大）
  ② 画线——导线传输
  ③ 反相器 NOT（继电器原理：信号经过 → 吸合 → 输出反向）——**紧凑型线上件**
  ④ 延时器——**紧凑型线上件**
>元件放置：开关 = 方块；组件（反相/延时）= 小尺寸紧凑型，适配画线（落在轨道上）
>后置可选：比较器（阈值判定：信号强度/液位/风强检测）、时钟/脉冲器（周期信号）
>不做：逻辑控制器（文本编程，学习成本高）——逻辑门用线拓扑天然表达（并联汇聚 = OR，串联 + 反相 = AND）
>物理化耦合：线画在方块表面 → 方块破坏/结构断裂 → 线跟着断（结构物理化白送）

### 无线电波（无线控制 · 移动结构/远程）
>定位：不是红石替代（无实体路径，给不了"确定布线"）；是移动结构/遥控的特权（悬浮/航空结构无实体连线）
>保留 5 点：①频道 ②范围/衰减 ③穿墙削弱 ④雷暴干扰 ⑤天线等级
>砍掉：极化 / 反射 / 衍射 / 多径 / 调制细节 / 天线物理长度（体素世界用不到）
>开发优先级：后置（做航空/悬浮结构时启用）；是否承担"自由供电"届时再定

### 视觉语言（借机械动力的"运动语言"）
>能量通过运动表达——不是发光，是"动"：
  源动画（叶轮/叶片/活塞转）
  传输动画（轴/齿轮/皮带；画线信号 = 沿线脉冲流动）
  设备动画（工作机构转，节奏随强度）

# 表达元素（已记 2026-10-30）
>定位：表达 = 玩家把想法变成世界里能被看到的东西；四类载体 = 建造（形状）/ 装饰（个性化）/ 功能（机制）/ 展示（观众）
>差异化核心：会动的建筑（物理化结构）+ 可视化机械（三能量）——"活建筑"是 MC 没有的表达语言，是我们表达元素的主打
>装饰层（定案）：不做深——靠方块多样性 + 物理化结构撑起表达（不做 MC 式染色/旗帜/家具深体系）
>表达/发展边界（定案）：不划分、不引导——给玩家极大自由度，想做什么做什么；我们只提供游戏、不负责玩家行为（极端行为明确态度即可）
>展示观众（定案）：联机系统必做（架构已定：渲染层与引擎当前耦合 → 后续分离为服务端/客户端）；单人阶段观众 = 自己

# 探索元素（已记 2026-10-30）
>定位：探索 = 去没去过的地方发现新东西；**四元素的串联者**（串生存/发展/表达）——剧情/移动/见闻贯穿其中
>正反馈闭环：探索（范围↑）→ 发现资源/奇观 → 发展（技术↑）→ 造出更好工具（物理化）→ 探索范围更大
>三维度：平面（大陆海洋——现实级海洋探索是特色）/ 地下（洞穴矿洞，MC 式保留）/ 垂直（风+物理化，我们独有）
>移动（定案）：**不特化**——不做鞘翅式专用移动道具；移动能力 = 结构物理化自然延伸（造了什么结构就能怎么移动：船形结构下水、飞行结构上天）+ 风系统（风力/气流）；基础通用载具（船）MC 同款保留
>垂直载体（定案 2026-10-30）：山脊风 + 热气流柱（C 方案），集成在风系统内（见"风"小节·垂直气流）——高山悬崖提供目标，气流提供"怎么上去"；平原靠热气流、山地靠山脊风
>物理化结构与群系：垂直悬崖/峡谷/风蚀地貌/石柱群（自然地形奇观，与"上层空岛不做"协调；地形本身可互动——搭升降机/绕飞行器）
>资源分层：借鉴 MC 最强项——越深/越危险/越高 → 越好材料（垂直探索的回报）
>剧情（定案 2026-10-30）：世界背景 = **A 古文明陨落**（功能设定，故事留白）——作者只写"遗迹存在"，不写"谁/为何/结局"（玩家自己拼，作者影响压到最低）；任务系统/NPC 剧情不做（MC 弱叙事+轻引导路线）
>遗迹定位（定案 2026-10-30）：**教学载体为核心**——遗迹里的机械结构是实物示范（运转中），帮助玩家理解各种机械构造、降低搭建学习成本（相当于内置教程，探索本身即引导，无需独立新手教程系统）；结构不受剧情影响（教学与剧情解耦）；辅：稀有材料/遗物（资源分层）+ 守卫/机关（危险区）；难度梯度——浅遗迹教基础构造、深遗迹教复杂构造（与资源分层平行，越深知识+资源双重回报）
>见闻：氛围动物 + 风表现 + 自然奇观 + 天气（风暴云后置）——防跑图无聊的内容密度
>表达-探索联动：联机后玩家建筑 = 互相探索的景点（MC 弱点，我们机会点）
