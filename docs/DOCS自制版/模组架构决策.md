# 模组架构决策（加载器与开放面）

>2026-11-04 定稿（原记 10-31 系日期笔误，统一归档为 11-04） ・ 关联：架构决策-注册表机制、宪法层五类、DLL 底层机制教学

## 一、决策背景

1. 引擎追求**"非常高的模组自由度"**（用户核心偏好：扩展点密度 = 自由）。
2. 讨论线：DLL 模组机制（LoadLibraryW/GetProcAddress/FreeLibrary、C ABI、IAT）→ 全开放自由可行性 → 正式通道 vs 侵入式 → WASM 评估 → 维护负担评估 → 范围收敛。
3. 最终形成定案：**加载器做小（第一方内容加载器），开放面做大（引擎正式接口充足）**。

## 二、核心决策总表

| # | 决策 | 结论 |
|---|---|---|
| 1 | WASM 沙箱宿主 | **去除**（不建、不维护） |
| 2 | 模组通道 | **单一 DLL 通道**（原生动态库） |
| 3 | 加载器定位 | **第一方内容加载器**（不做全面加载器平台 / 多加载器市场） |
| 4 | 侵入式 | **保留、不限制**（引擎开源 + 物理不阻止 + 责任自负） |
| 5 | 正式接口 | **做厚**（充足 = 设计目标，即使第一方不全部使用） |
| 6 | 信任模型 | 来源信任 + 责任声明（正式接口内引擎负责，接口外模组自负） |
| 7 | 远期愿景 | 活力社区 / 多加载器 —— **保留在文档，不建平台，不提前投入** |
| 8 | 加载器源码 | **开源**（模组作者可参考/复用/自建加载器；开源 ≠ 建平台） |

## 三、通道定案：单一 DLL 通道（WASM 去除）

```
┌─ 模组层：DLL 格式统一（第一方内容）───────────────────┐
│   通过引擎正式接口（注册表×事件×数据驱动×系统接口）干活   │
└────────────────────────────────────────────────────┘
                    ↓ 加载
┌─ 加载器层：第一方 DLL 内容加载器（轻量）───────────────┐
│   发现 → 校验 → LoadLibraryW → CreateMod → 调度 → 卸载 │
└────────────────────────────────────────────────────┘
                    ↓ 调用
┌─ 引擎正式接口层（做厚，宿主无关）─────────────────────┐
│   注册表 × 事件总线 × 数据驱动 × 系统接口               │
└────────────────────────────────────────────────────┘
                    ↓
┌─ 引擎核心（宪法层，开源）────────────────────────────┐
│   线程模型 · 确定性 · GPU 生命周期 · 渲染管线骨架 · 存档版本 │
└────────────────────────────────────────────────────┘
```

- **WASM 去除理由**：① 受众不存在（第一方内容 DLL 性能最优且无兼容税）；② DLL 覆盖 WASM 全部功能且无性能损失（WASM 比原生慢 20-40%）；③ 唯一差别是沙箱——第一方内容不需要；④ 维护负担：三套（引擎+DLL+WASM 平台）→ 两套（引擎+DLL 原型）。
- **DLL 与 WASM 的功能对比**：功能 100% 覆盖（注册/行为介入/系统替换）；性能更好（原生零损失）；**唯缺沙箱隔离**——由信任模型（见第九节）补位。

## 四、加载器定位：第一方内容加载器

1. **只加载自己写的内容模组**（闭源友好、性能优先、自信任）。
2. **不做全面加载器平台**：不写《加载器接入规范》、不承诺接口版本化、不做社区 SDK 文档、不做多加载器市场。
3. **接口仍保持"宿主无关"设计原则**（顺手原则，非承诺）：将来若出现第三方社区，加适配器即可，不重做接口层。
4. **加载器源码开源**：modapi/IMod.hpp + host/main.cpp 公开——模组作者可参考、复用、自建加载器。**开源 ≠ 建平台**：不承诺支持、不运营社区、不写接入规范。这是"多加载器愿景"的零成本种子（代码自己要用，公开只是发布动作）。

## 五、侵入式策略（更新《架构决策-注册表机制.md》第三节"侵入式修改红线"）

>演进：注册表机制文档（2026-10-26）定"非受控侵入（禁止）+ 规范契约禁止 hook"；本决策（2026-11-04）更新为"**保留、不限制**"。

| 项 | 旧策略（10-26） | 新策略（11-04，本决策） |
|---|---|---|
| 非受控侵入（hook/改码/vtable 覆盖） | 规范禁止 | **保留、不限制** |
| 正式通道（注册表/事件/委托/回调） | 允许 | 允许，且做厚 |
| 约束方式 | 文档明令禁止 | 引擎开源 + 不物理阻止 + 责任声明 |
| 理由 | 可推理性优先 | 物理上防不住（C++ 同进程无隔离）；用户追求"尽可能自由"；责任划分代替禁令 |

- 逻辑不变项：引擎内部"正式接口内可推理"仍成立——模组走正式通道 = 引擎负责；模组侵入 = 自负。
- 引擎策略：**正式通道合法化程度有限；宪法层引擎对破坏不负责**。

## 六、正式接口做厚：接口充足标准（四通道）

**原则：接口充足是引擎的第一等设计目标，即使第一方内容不全部使用——开放面是自由的地基，一次做足，不等待。**（区别于"性能优化不提前"触发器模式：性能优化等瓶颈，接口不等待。）

| 通道 | 覆盖目标（做足） | 示例 |
|---|---|---|
| ① 注册表 | 所有"内容类型"全覆盖 | 方块/物品/实体/模型/纹理/噪声/世界预设/配方/生物群系/维度 |
| ② 事件总线 | 所有"语义时机"全覆盖 | 放置/破坏/交互/实体生成/死亡/tick/世界生成阶段/渲染阶段/存档事件 |
| ③ 数据驱动 | 所有"内容"可 JSON 化 | assets/（视觉）· data/（逻辑）· 模型/预设/配方/生成编排 |
| ④ 系统接口 | 每个子系统一个插槽 | 噪声（NoiseRegistry）/渲染策略（IMeshBuilder）/存档编解码器/物理事件/输入 |

## 七、开发纪律：三连问（顺势接口化）

```
每加一个行为点，先问三句：
① 这算一种"内容"吗？   → 注册表
② 这算一个"时机"吗？   → 事件总线
③ 这能被写成数据吗？   → JSON / data 驱动
三句都否，才留成引擎内部函数。
让开放面随引擎长大，而不是事后返工。
```

- 已实践样板：世界生成器 1a（NoiseRegistry = 注册表通道；data/worldgen/presets/*.json = 数据驱动通道；生成管线骨架本身不开放）。1a 阶段接口未抽（单阶段内联），"事件时机"通道等 1b 的生成阶段再落。

**内置 vs 模组的边界（2026-11-04 补充定案）**：内置三噪声（value / perlin / fbm）属引擎第一方内容，**永久内置、永不移植进 DLL**。三条理由：①**自举**——无任何模组时引擎也要有默认世界，`data/worldgen/presets/default.json` 直接引用 `"fbm"`；②**定位**——第一方内容加载器不做平台（第四节），内置内容没有"外置"的必要，外置反而增加启动依赖；③**基底材料**——内置三件套是模组写自己噪声的参考实现与组合基础（fbm 可直接包模组注册的新 base）。
判断口径：**"无模组时引擎能否独立跑"——能跑的内置，只为扩展而存在的走模组**。
接口状态：`NoiseRegistry::registerType` 自 1a 起就是 public——模组口子已开，只等 #41 的 DLL 加载器来调用。

## 八、落地形态

### 工程结构（第一方内容加载器原型）

```
modapi/IMod.hpp      引擎正式接口的唯一 C++ 封装（自用，可自由改）
host/main.cpp        加载器：LoadLibraryW → CreateMod → 注册 → FreeLibrary
mod/mymod.cpp        内容模组（闭源内容，性能优先，想碰核心就碰）
CMake：两个 target   引擎 exe + 模组 dll
```

### 加载器六阶段管线

| 阶段 | 动作 |
|---|---|
| ① 发现 | 扫描 mods/ 目录，*.dll 列表 |
| ② 校验 | 接口版本 / 元数据，不匹配则拒绝 |
| ③ 加载 | LoadLibraryW + GetProcAddress(CreateMod) |
| ④ 初始化 | 注册表登记（方块/模型/噪声/事件） |
| ⑤ 调度 | 事件总线分发（tick/放置/生成回调） |
| ⑥ 卸载 | 逆序清理 + FreeLibrary（谁创建谁销毁） |

## 九、信任与责任模型

1. **DLL 无沙箱 = 全信任**：第三方 DLL 能碰引擎一切内存。
2. **处理方式：来源信任**——谁提供的 DLL 谁负责（第一方自用无此问题）。
3. **责任声明**：正式接口内（注册表/事件/数据驱动/系统接口）= 引擎负责；接口外 = 模组自负。
4. **引擎开源**：是"侵入式可行"的前提，也是"责任可追溯"的基础（模组能读源码判断边界）。

## 十、远期愿景（保留，不建平台）

1. **活力四射的社区 + 多加载器并存** = 远期方向，写进本决策，不承诺、不投入。
2. 社区不是"建"出来的，是**内容吸引**来的——先做出值得模组的游戏，社区才会出现。
3. 架构已留位置：模组依赖**引擎 API**（而非加载器 API）→ 将来任何第三方可写自己的加载器；引擎 API 宿主无关原则保证 WASM 适配器等未来选项是"加适配器"而非"重建工程"。
4. **加载器开源**进一步为愿景铺路：第三方模组作者 fork 官方加载器即可起步，无需从零发明——多加载器生态的种子成本 = 0。
