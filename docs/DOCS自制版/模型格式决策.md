# 模型格式决策

>状态：定案 2026-10-29　·　关联：《玩法决策.md》美术资源规范
>决策背景：自研 C++20/Vulkan 体素沙盒引擎，需要确定生物/物体模型的统一数据格式

## 决策目标（三标准）
>功能足够：能表达体素模型 + 骨骼层级 + 关键帧动画
>版权免费：格式/工具链无专利许可问题（商用上架合规）
>替换修改方便：文本可编辑 / 工具支持好 / 换皮容易

## 格式选型对比

| 格式 | 模型+骨骼+动画 | 版权免费 | 修改替换方便 | 结论 |
|---|---|---|---|---|
| **.bbmodel**（Blockbench） | ✓ 立方体+骨骼+动画全支持 | ✓ Blockbench MIT 开源 | ✓ JSON 文本 + 免费工具 | **主选** |
| **glTF**（.gltf/.glb） | ✓ 网格+骨骼+动画（行业标准） | ✓ Khronos 开源免专利 | ✓ JSON 文本 + Blender 全生态 | 曲面通道 |
| FBX | ✓ 全功能 | ✗ Autodesk 专利许可 | ✗ 二进制不可文本改 | 排除 |
| OBJ | ✗ 无骨骼动画 | ✓ | ✓ | 功能不足 |
| .vox（MagicaVoxel） | ✗ 只有网格无动画 | △ 私有格式 | △ | 排除 |

## 定案架构（编辑端 / 导入端 / 运行时）

```
编辑端：Blockbench（.bbmodel）│ Blender（glTF）
导入端：.bbmodel 解析器 + glTF 解析器 → 转引擎运行时格式
运行时：自定精简 JSON（先 JSON 跑通，二进制后置）——引擎加载用
```

### 双通道规则（按模型语义分流）
>.bbmodel → 体素模型（方块语义：可落位 / 参与方块物理）——官方生物标准通道
>glTF → 曲面模型（实体语义：装饰 / 精细生物，不参与方块物理）——modder 可选通道

## .bbmodel 格式说明（主选格式）
>本质：基于 JSON 的文本格式（Blockbench 编辑器原生格式）
>面向"立方体拼装 + 骨骼层级 + 关键帧动画"
>结构概览：
  meta —— 元信息（标识符/格式版本）
  elements —— 几何体列表（立方体用 from/to 对角两点定义，挂骨骼 + UV 偏移）
  bones —— 骨骼层级（name/parent/pivot 枢轴点）
  animations —— 动画（每骨骼时间线关键帧：rotation/translation/scale）
  textures —— 贴图引用（UV 尺寸）
>匹配点：立方体语义天然对应体素世界；骨骼管旋转/平移；动画是骨骼关键帧（狼的行走/燕子的飞行够用）

## MC 对比结论
>MC 原生不支持 glTF：
  Java 版 —— 自定义 JSON 模型（方块/物品），实体专属格式
  基岩版 —— .geo（几何 JSON）+ .animation（动画 JSON），专属格式
  glTF 在 MC 生态只是 Blockbench 的"导出到其他引擎"通道，MC 加载不读 glTF
>我们 = 自定运行时格式 + 双导入通道（.bbmodel 体素 + glTF 曲面）→ 比 MC 开放
>modder 可选 glTF = 相对 MC 的开放优势（Blender 曲面模型可直接进游戏）

## 关联约束（来自美术资源规范）
>方块纹理：16x16（一面 = 16x16 像素）
>生物模型：半格（8px）单位构建（与 MC 同构）
>生物贴图：32x32 粒度（每格面 2x2 细节）
>视觉层次：方块 16 打底（环境粗）、生物 32 精细一档（焦点细）
>工具链：Blockbench（体素建模 + 骨骼动画 + 贴图绘制）/ Blender（曲面 glTF）
>AI 生成定位：概念蓝图 + 贴图辅助；体素建模与动画人工（Blockbench 为主工具）
