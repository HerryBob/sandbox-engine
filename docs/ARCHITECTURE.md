## 一、架构总览：四轨消息流

```
输入轨(125Hz 墙钟采样)     物理轨(25TPS accumulator)     业务轨(25TPS 固定节奏)      渲染轨(60Hz 只读观众)
┌────────────┐ 事件     ┌────────────┐ 回执 ┌────────────┐ 变更事件 ┌────────────┐
│ InputSampler│────→    │ PhysicsWorld │←───│ BusinessWorld │────→│ Renderer   │
└────────────┘          └────────────┘      └────────────┘          └────────────┘
                        ↑ 指令              │ 指令/快照
                        └──────────────────┘
```

- **队列**：`SPSCQueue`（单生产者-单消费者无锁环形队列），原型单机模式天然 SPSC，无需互斥锁。
- **职责分离**：输入只采样不裁决；物理只管积分/碰撞；业务拥有世界状态与裁决权威；渲染只读不写模拟。
- **渲染轨是"第 4 轨只读观众"**：消费变更事件流 + 位置插值 + 伪渲染帧；不向模拟发任何指令。

### 各轨节奏

| 轨 | 节奏 | 驱动方式 | 说明 |
|---|---|---|---|
| 输入 | ~125Hz | 墙钟采样（sleep 8ms） | 完全不受 time_scale 影响 |
| 物理 | 25TPS | accumulator 累积 wallDt×scale | 不硬绑定业务 tick 数 |
| 业务 | 25TPS | 固定 40ms 墙钟节奏 | 演示事件源（DemoDriver）在 tick 边界驱动 |
| 渲染 | ~60Hz | sleep 16ms | Vulkan drawFrame（FIFO vsync 对齐） |

## 二、核心决策

### D1 四轨消息流 + SPSC 无锁队列

- **背景**：单线程模拟无法同时做到"输入即时采样、物理高频积分、业务逻辑裁决、渲染不阻塞"；多线程需要跨线程通信。
- **方案**：四线程 + 三类队列（输入→物理事件、业务↔物理指令/回执、业务→渲染变更事件）；队列用 SPSC 无锁环形缓冲（atomic 头尾指针，memory_order acquire/release）。
- **权衡**：SPSC 只解决单生产者单消费者；未来多线程消费同一队列（如多物理 worker）需换 MPSC/加锁。原型阶段用"结构天然 SPSC"换零锁开销。
- **关键约束**：队列满时 push 返回 false，**调用方决定丢或重试**——慢放时物理消化变慢、指令堆积是"可观测水位现象"，不是 bug。

### D2 业务权威：指令/回执协议，裁决在业务

- **背景**：方块放置/破坏/打包/解包如果各线程各判各的，会出现"两侧状态不一致"（如物理认为方块存在、业务认为不存在）。
- **方案**：**业务侧是唯一权威**。玩家/演示请求先走业务裁决（存在性/占用/状态机检查），裁决通过才排队下发 `PhysicsCommand` 给物理；物理处理完发回执（位置快照/打包回执/碰撞事件），业务据此更新自己的世界。
- **权衡**：命令语义（指令/回执）比状态同步（直接共享表）多一跳延迟，但换来"裁决单一权威 + 天然可追踪（命令零丢失断言靠发送数==处理数）"。

### D3 chunk 区块化（16³ 稀疏映射）

- **背景**：方块表全量线性遍历在方块数增长后不可持续；初始版本是全局 map。
- **方案**：`chunks_[ChunkPos] → Chunk(16³ 密集数组)`，坐标→chunk 定位 O(1)；空 chunk 不占内存（稀疏）。
- **权衡**：换来了区域查询（跨 chunk 遍历）、修改跟踪（脏标记）、变更事件流（按 chunk 聚合）的落点。代价：跨 chunk 的查询要拆坐标（`chunkOf` 按位运算）。
- **延伸**：渲染端 LOD/网格重建天然以 chunk 为单位（Minetest retrieveBlocks 同思想）。

### D4 打包/解包刚体（Contraption，物理形态转移）

- **背景**：MC 的"结构/方块实体"概念——一组方块作为一个整体运动（飞船），而不是逐方块积分。
- **方案**：业务裁决"打包哪 27 块"→ 下发 `PackContraption` → 物理把对应静态碰撞体**转移**进 `RigidBody`（方块列表 + 基准位置 + 速度），业务侧 chunk 同步置空（防"幽灵飞船"双份）；解包时物理按"基准+局部坐标"回写世界坐标方块列表，业务据此重建 chunk（世界坐标对齐，飞船飞多远记多远）。
- **权衡**：打包=选择子集，主世界其他方块（障碍物）留在静态碰撞体集合。业务侧维护 `bodyBlocks_`（刚体域独立容器，局部坐标）与 chunk 空间独立、坐标可重叠。

### D5 增量最小碰撞箱（Sable 思想）

- **背景**：飞船 27 块如果每块一个碰撞体，碰撞检测 O(块数)；刚体内方块增删（改造）时碰撞箱要实时贴合。
- **方案**：单 AABB 最小包裹：半宽 = (max−min)/2 + 0.5、中心偏移 = (min+max)/2（相对基准）。刚体内方块增删时 `recomputeAABB` 增量重算（扩张/收缩实时贴合）。
- **权衡**：单 AABB 包裹精度低（凹形状包裹出多余空间）但 O(1) 检测——原型飞船是紧凑 3×3×3 方块，包裹≈精确。复杂形状未来换多 AABB/凸分解。
- **架构 2.8 精度设计**：位置用 double（复合体=基准+局部坐标），避免大坐标下 float 精度漂移。

### D6 接触语义（Rapier Started）

- **背景**：刚体顶着方块持续重叠时，若每帧上报碰撞事件，业务会收到重复"碰撞"。
- **方案**：`contactPairs_`（刚体 id → 接触中方块集合），只在"接触开始"（新加入集合）时发一次 `CollisionEvent`；持续重叠（Stay）不发；方块被删/离开后自然移除。
- **权衡**：只实现了 Started 语义，暂无 Stopped（业务无接触结束需求）。解包/全量同步时整体清空对应记录。

### D7 位置插值（渲染插值基座）

- **背景**：物理 25TPS 产生位置快照，渲染 60Hz 消费——两频率不整除，直接读最新快照会"一顿一顿"。
- **方案**：业务保留最近两个带模拟时间戳的快照，`sampleShipPos(simT)` 线性插值；窗口外钳制（晚于最新→最新，早于最旧→最旧，无未来数据）。
- **权衡**：插值消除跳变，代价是渲染位置滞后 ≤1 个物理 tick（可接受）。

### D8 变更事件流（脏 chunk → 渲染）

- **背景**：渲染端要重建"变过的方块"，全量同步每帧都做会浪费。
- **方案**：业务每 tick 聚合 `dirtyChunksThisTick_`（写操作插入、自动去重）为一条 `BlockChangeEvent`；渲染端消费后标记脏 chunk（增量重建依据）。刚体域变更不进此流（复合体=动态渲染单元，状态由 RigidBodyPos 驱动）。
- **权衡**：事件流"增量"语义 vs 位置快照"状态合并"语义——丢一个变更=渲染端漏重建，所以变更事件 push 失败**不清空**（下 tick 重试），位置快照 push 失败**丢弃**（中间态无意义）。

### D9 Vulkan：MSAA 8x 三附件

- **背景**：锯齿明显，MSAA 是性价比最高的抗锯齿（硬件多采样）。
- **方案**：RenderPass 3 附件——颜色 8x（MSAA 图，`finalLayout=COLOR_ATTACHMENT_OPTIMAL`）、深度 8x（**必须同采样数**，逐子样本深度测试）、resolve 1x（交换链画布，`finalLayout=PRESENT_SRC_KHR`）；`pResolveAttachments` 挂解析；`getMaxUsableSampleCount` 从 64→1 探测颜色∩深度交集（RX 6750 GRE 给到 8x）。
- **权衡**：显存×8；`finalLayout` 是"散场后布局"——MSAA 颜色图不能呈现（必须 resolve），深度不呈现（DONT_CARE 丢弃）。
- **附件顺序**：color/depth/resolve 是 renderPass↔framebuffer 的**全局契约**，可改顺序但需三处同步（description/reference/framebuffer 附件数组），不影响渲染结果与性能。

### D10 UBO 三矩阵拆分

- **背景**：学习代码是单 `mvp` 矩阵（相机矩阵烘焙在顶点侧）；引擎版要独立控制 model（方块位移）/view（相机）/proj（投影）。
- **方案**：`UniformBufferObject { mat4 model; mat4 view; mat4 proj; }`；着色器三个 uniform 分开乘。相机更新每帧填：model=单位矩阵、view=lookAt、proj=perspective（**含 `proj[1][1]*=-1` NDC 翻转**——Vulkan Y 轴向下，glm 按 OpenGL 设计）。
- **权衡**：多 2 个矩阵乘法/顶点，但换回"方块坐标直接放 model、相机独立操控"的语义清晰。

### D11 自动化绕序（面定义表 + 叉积保证）

- **背景**：手写 24 顶点绕序靠肉眼验证——实际 6 面中 5 面朝内（背面剔除后缺面/少三角形）。
- **方案**：面定义表 `kFaceN[6]`（法线 n）/`kFaceU[6]`（主轴 u）/`kFaceV[6]`（副轴 v），约束 `u×v=n`（右手系）；角点由公式 `面心 = 基准 + n·h`、`四角 = 面心 ± u·h ± v·h` 生成；索引恢复标准 `(0,1,2)(0,2,3)`。
- **数学保证**：`(p1−p0)×(p2−p0) = 4h²·n`——绕序**永不反**，加任何面（台阶/斜面）只需给 (n,u,v)。
- **深层易错点**：`proj[1][1]*=-1`（NDC y 翻转）会让屏幕空间绕序判定符号翻转——手写时容易据此写反。

### D12 resize 重建 + 动态 viewport

- **背景**：窗口尺寸变 → 交换链画布失效 → 画面拉伸/裁切。
- **方案**：GLFW framebuffer 回调置位标志 + acquire/present 返回码双路径触发 `recreateSwapchain()`：`vkDeviceWaitIdle → 销毁(帧缓冲→MSAA→深度→swapchain+视图) → 按 init 序重建`。管线 viewport/scissor 改**动态状态**（`VK_DYNAMIC_STATE_VIEWPORT|SCISSOR`），drawFrame 每帧 `vkCmdSetViewport` 用当前 extent——resize 只重建资源、**不重建管线**。
- **铁律**：重建清单必须与创建清单一一对应（漏一项=僵尸对象）；`vkDeviceWaitIdle` 必须在销毁前（防 GPU 还在用旧资源）。
- **0 尺寸防护**：最小化时 extent 0×0，**直接 return 等下一帧**——绝不能 while 阻塞等事件（渲染线程会卡死，主线程 join 也跟着卡死）。

### D13 utils 工具层目录化

- **背景**：VulkanContext.cpp 膨胀，查询/可复用构建逻辑与状态编排混在一起。
- **方案**：`src/render/utils/`：`DeviceUtils`（设备能力查询）、`SwapchainUtils`（表面能力/格式/呈现模式/尺寸选择）、`ResourcesUtils`（深度格式/内存类型/图像/缓冲）、`CommandUtils`（单次命令）、`ShaderUtils`（shader 加载）；`Utils.hpp` 聚合头。
- **边界**：utils 放**无状态、参数驱动的通用工具**；**状态编排**（recreateSwapchain 等操作私有成员的函数）**留在 VulkanContext**——搬出去要么传 8 个参数、要么破坏封装。未来多组同构资源时正确方向是**资源 RAII 化**（构造=创建、析构=销毁），而非"重建函数文件"。

### D14 time_scale / 域乘数 / accumulator / kMaxSteps

- **背景**：演示需要验证全局时间缩放（业务+物理同时）与单域缩放（只慢放物理）；固定 tick 率的模拟不能直接改 dt。
- **方案**：`TimeManager` 提供全局 scale 与域乘数；物理用 accumulator 累积 `wallDt×scale`，`while(acc>=0.04)` 补 tick；单帧最多补 `kMaxStepsPerFrame_=5` 个 tick（防 spiral of death，超限丢弃剩余累积）。
- **权衡**：慢放时物理消化变慢、指令堆积（水位可观测）；输入采样始终墙钟（不受缩放），保证"减速时操作仍流畅"。

### D15 "等事实成立"采样原则（软断言）

- **背景**：软断言在固定墙钟点采样异步事件的结果——减速阶段物理 sim 推进减半，改造事件（tick100）的处理时刻离采样点（6s）只差 ~1s，调度抖动时断言时好时坏（27 vs 28 块）。
- **方案**：采样前轮询 `waitForBodies(target, timeout)`——**等到物理刚体数达到目标再采样**（超时返回 false，此时才是真实逻辑错误）。
- **原则**：验证异步事件的结果，**等结果成立再断言，而不是等固定墙钟**。

## 四、验证基线

- **校验层 0**：冒烟 stderr 空（Validation Error 数 = 0）。
- **软断言全部 PASS**：四轨消息（命令零丢失/裁决闭环/打包解包）、物理（刚体/碰撞/接触语义/增量碰撞箱）、业务（区块化/区域查询/脏跟踪）、渲染（Vulkan 全链/方块呈现/变更事件流/位置插值）。
- **稳定性**：resize 连续重建无报错；改造断言"等事实成立"后连续多次运行全绿。
- **冒烟惯例**：Start-Process → 等 5-8s → Stop-Process；读 stderr（空=校验层 0）+ grep stdout 关键日志；**冷启动首跑可能 stdout 0 字节，需重跑一次**（进程启动竞态）。
