> 用途：为本项目功能方块体系提供外部参照，不照抄，只提炼可迁移的结构。

## 三、航空学功能方块

### 3.1 浮力（四种来源）

- **气囊**：白、灰、浅灰、黑四色体积块，靠排开空气产生浮力，浮力与体积成正比，与方块数量无关。
- **可调燃烧器**：给气囊加热，浮力随温度可调。
- **浮空石**：固定上升力，不占体积。
- **气囊封装轴**：把传动轴封装进气囊内部，不破坏浮力。

### 3.2 推进

- **安山螺旋桨**。
- **螺旋桨轴承**：螺旋桨的旋转驱动源。
- **对称帆**：风力推进，有颜色变体。

### 3.3 装配与结构

- **物理装配器**：把选中的结构组装成物理体，是显式装配器，不是自动检测。
- **万向轴承**：让结构绕任意轴自由旋转。
- **绳索连接器**：把多个子结构连起来，例如船体、气囊、吊舱。
- **铭牌**：结构命名。

### 3.4 驾驶控制

方向盘、油门杆、高度传感器、模拟传动（把控制杆的连续信号传给推进器）、铁把手。

### 3.5 其他

蒸汽排放口（视觉与推进表现）；另有越野模块分支，面向陆地载具。

## 五、六个可迁移的设计决策

### 5.1 应力是全局预算，不是能量条

动力源提供容量，机器消耗，超载全停。玩家不需要管燃料和电量，只需要回答一个问题："我这个设计够不够。"

这套机制的价值在于它是**设计约束**，不是资源管理。它逼玩家思考"少装一台机器还是加一个动力源"，而不是"去挖煤"。

### 5.2 转速与应力是两个正交维度

转速决定多快，应力决定能带动多少。齿轮比改转速不改应力总量，加动力源改应力不改转速。两个正交维度，才让"设计"有解空间；只剩一个功率值，优化目标会退化成一条直线。

### 5.3 面接口决定朝向，朝向是玩法

轴只能从特定面进、特定面出，而方块朝向由玩家放置决定。于是"这个动力怎么绕过去"变成谜题，而不是数值问题。

### 5.4 显式装配划定边界

机械动力的装置靠强力胶或底盘显式划定；航空学靠物理装配器显式选定区域。两者都不是"邻接自动成体"。

这条直接回答组装语义问题：不需要在"邻接即连接"和"必须连接件"之间二选一，**有一个显式的装配动作，由它划定边界**。

### 5.5 控制链必须有模拟量

方向盘、模拟传动、油门杆传的是连续值，不是红石的开与关。只有通断的控制层，载具手感会很差。要做驾驶，控制层必须有一条模拟量通路。

### 5.6 教程是运行中的机械，不是预录动画

机械动力的内置演示场景本身是可运行的机械，演示内容与实际行为不会脱节。若本项目要做同类教程，场景应当由真实系统驱动。

## 六、航空学的升力结构

三种来源并存，各自的代价不同：

- **气囊**：浮力取决于排开体积，占空间，不占材料
- **可调燃烧器**：浮力可实时调节，需要燃料
- **浮空石**：升力固定，不占体积，但依赖稀有材料

同一个目标（飞起来）有三条实现路径，玩家才有设计空间。只有一种升力来源时，所有人造出来的东西会趋于同一种形态。

推进侧同理：螺旋桨（受动力驱动）与帆（受风驱动）并存，使得"动力推进"和"风力推进"成为两种可混用的方案。

## 七、两个模组仍空白的部分

- **结构完整性**：不管多大、多重、怎么撞，方块都不会因为受力而断
- **真风**：帆是"有风就推"，不是"在风场里算力矩"
- **整块地形物理**：只处理玩家造的载具，不处理世界本身
- **动态重组**：飞行中拆一块、加一块，整体物理不会跟着变

这四条正是本项目此前物理讨论的核心，也是与这两个模组的真正分界线。

## 八、落地建议

### 8.1 第一版最小方块集（11 个）

结构块、底盘、配重、风车、轴、齿轮、轮子、螺旋桨、开关、座椅、操纵杆。

这 11 个足以造出两样东西：

- 一辆车：底盘 + 轮子 + 轴 + 齿轮 + 风车 + 座椅
- 一台飞行器：底盘 + 螺旋桨 + 风车 + 配重 + 座椅

先做这 11 个，不要一次铺开全部清单。每多一个方块，就多一套演示、物理与平衡成本。

### 8.2 引擎该给"关节"，不是具体机械件

活塞、铰链、轴承、齿轮耦合，本质上是同一种东西：两个结构之间一个带限制的自由度。

- 活塞 = 关节 + 平移自由度 + 行程
- 铰链 = 关节 + 旋转自由度 + 角度限制
- 轴承 = 关节 + 旋转自由度 + 无限制
- 齿轮耦合 = 关节 + 传动比

方块只是参数组合。这样模组加新机械件只需给参数，不必碰物理代码。

### 8.3 面接口定义

每个方块的六个面，各面只能取一个值：

| 接口 | 含义 |
|---|---|
| 无 | 不连接 |
| 结构 | 传递力与质量 |
| 旋转输入 | 接收旋转 |
| 旋转输出 | 输出旋转 |
| 信号 | 控制信号（后置） |
| 物料 | 物品传输（后置） |
| 流体 | 流体传输（后置） |
| 交互 | 玩家可操作或乘坐 |

有了这张表，"两个方块能不能连"变成可判定规则，不需要逐个写特例，模组作者也能自行组合。
