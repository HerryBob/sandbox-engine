# 自研沙盒引擎 · 架构设计文档

> 项目性质：C++ 自研方块沙盒引擎，对标 Minecraft，但在物理与多线程架构上做增强创新。
> 核心定位：**服务端权威逻辑 + 客户端渲染分离**；**三轨时间机制**；**玩家自由拼接方块组成动态复合体**，作为单个刚体进行物理模拟。
> 本文档汇总前期所有设计决策，作为后续开发的地基与参照。

---

## 0. 一句话项目概览

一个可模组化的方块沙盒引擎：业务世界按 20TPS 权威运算，独立物理线程按 25TPS 模拟，输入线程按墙钟独立采样（不受时间缩放影响）；玩家可以把任意方块拼成的巨型结构打包成"动态复合体"，交给物理线程作为单个刚体运动。服务端只管逻辑与物理，渲染、LOD、输入采集全部放客户端。

---

## 1. 整体架构：客户端 / 服务端分离

> 对应 Minecraft 的服务端-客户端模型，但 MC 把所有逻辑挤在一条单线程 tick 里，本项目把物理独立成线程，这是最大区别。

### 1.1 服务端（Server）—— 权威逻辑，无任何渲染
- **没有任何渲染代码**：不生成模型、不做 LOD、不做视锥剔除。
- 运行三轨核心：业务主线程 + 物理子线程。
- 接收各客户端上传的输入事件（带时间戳），但不直接读取本地键鼠。
- 把世界状态快照（方块变更、复合体位置姿态、实体状态）下发所有客户端。
- **权威逻辑源**：方块放置/破坏、物理碰撞、推力、红石运算，全部以服务端结果为准，客户端不能决定逻辑。

### 1.2 客户端（Client）—— 每个玩家独立一份
- 接收服务端快照，在本地维护一份**仅用于渲染 + 本地输入**的世界副本。
- 独立输入线程：采集本机键鼠，打包上传服务端。
- 独立渲染线程：视锥剔除、距离剔除、LOD 选择、提交 GPU。
- **不同玩家相机位置不同 → 每个客户端剔除的物体、选的 LOD 层级完全独立**。A 玩家远处飞船用 LOD2 简化模型，B 玩家近处看 LOD0 完整方块，互不影响。

### 1.3 单机模式（原型阶段）
- 服务端 + 客户端编译进**同一个进程**。
- 客户端与服务端之间不走真实 Socket，改用**进程内内存队列**传递数据包，省去网络 IO 开销。
- 代码架构保持客户端/服务端分离，后续拆联机几乎不用重构这部分。

## 2. 三轨机制（核心创新）

| 轨道 | 线程 | TPS | 时间源 | 职责 |
|---|---|---|---|---|
| 业务世界 | 业务主线程 | 20 (dt=0.05s) | sim_time（受 time_scale） | 方块、TE、放置破坏、事件 |
| 物理世界 | 物理子线程 | 25 (dt=0.04s) | sim_time（受 time_scale） | 独立物理域、刚体、碰撞、读取网络输入 |
| 输入采集 | 独立输入线程 | 墙钟原生 | **墙钟，不受 time_scale** | 键鼠事件采样，带时间戳入队 |

### 2.1 已敲定的时序参数
- 业务世界：**20TPS**（dt=0.05s）
- 物理世界对外模组回调：**25TPS**（dt=0.04s）
- 物理内部预留子步扩展能力，原型阶段先不开，遇到高速刚体抖动/碰撞穿透再启用。
- 输入线程：独立墙钟采样，完全不受业务/物理 sim_time 与 time_scale 影响。

> 后续调整原则：**优先保持对外模组回调 25TPS 不变，用内部子步优化精度**；子步不够再上调物理 TPS 到 30；复合体过多 CPU 压力高则下调到 20。模组 API 稳定不受影响。

### 2.2 时序驱动规则（原型直接落地）
物理线程用**累积待处理模拟时间**驱动，不硬绑定业务 tick 次数：

```
// 全局（服务端权威，单一写者）
global_scale             // 整个世界流速：同时缩放业务、物理模拟增量；输入线程不受影响
business_scale (默认 1)  // 业务域乘数：只缩放业务轨（局部时间缩放预留）
physics_scale (默认 1)   // 物理域乘数：只缩放物理轨（调试慢放/局部缩放预留）
// 业务/物理各自生效系数 = global_scale × 域乘数；输入线程永远不设系数

// 业务主线程 20TPS
while(running) {
    game_sim_time += 0.05 * time_scale;
    RunBusinessTick();
    SyncBusinessToPhysics();   // 业务Tick边界，发刚体指令到物理世界
}

// 物理主线程 25TPS
physics_accumulator = 0.0;
while(running) {
    wall_dt = GetWallDeltaTime();
    physics_accumulator += wall_dt * time_scale;
    while (physics_accumulator >= 0.04) {
        ReadInputQueue();      // 读取带时间戳的操控输入
        RunPhysicsTick();      // 对外25TPS模组回调
        physics_accumulator -= 0.04;
    }
    SyncPhysicsToBusiness();   // 把刚体位置、碰撞标记发回业务世界
}
```
残差 `physics_accumulator` 持续保留，自动处理非整数配比（4 业务 tick = 5 物理 tick）。

### 2.3 同步与线程安全规则（最高优先级）
- 所有同步只在**业务 Tick 边界**交换快照。
- 物理 tick 运行期间，业务世界数据对物理线程**只读隔离**；反之亦然。
- **禁止跨线程直接读写对方对象内存**。
- 数据流：业务 → 物理（刚体创建/销毁、推力、舵面、初始姿态）；物理 → 业务（刚体位置、旋转、碰撞事件标记）。

### 2.4 单机全部线程清单（原型约 6 条）
| 线程 | 归属 | 职责 |
|---|---|---|
| 输入线程 | 客户端 | 键鼠墙钟采样 |
| 客户端本地逻辑线程 | 客户端 | 消费服务端快照、维护本地副本 |
| Vulkan 渲染线程 | 客户端 | 视锥/距离剔除、取就绪 LOD、提交 GPU |
| 后台任务线程池（原型开 1 条） | 客户端 | 复合体 LOD 重建、区块 Mesh、资源加载 |
| 业务主线程 20TPS | 服务端 | 权威业务世界 |
| 物理子线程 25TPS | 服务端 | 权威物理域 |

> **输入线程放在客户端**（采集硬件输入）；**输入逻辑消费在服务端物理线程**（应用推力）。服务端不拥有输入线程。

### 2.5 时间系数分层与输入控制（已确认 2026-09-28）

**时间系数 = global × 域乘数**（原型已实现）：
- `global_scale`：服务端权威单一写者，主控"整个世界快放/慢放"，业务、物理一起缩放。
- `business_scale` / `physics_scale`：每域独立乘数，默认 1，仅缩放对应单轨。用于调试（如单独慢放物理轨排查高速刚体）与为"局部时间缩放"预留扩展点。
- 跨轨交互（复合体打包/推力/碰撞回传）**统一以 `global_scale` 为时间基准**，避免两轨 sim_time 漂移；域乘数只在纯模拟内部生效。

**输入线程：永不设时间系数**：
- 输入事件是墙钟世界的真实硬件事件，**不可缩放**；缩放会导致输入丢失（硬件事件无法重放）、时间戳失真（插值/联机同步失准）、双重缩放（物理已按系数缩放模拟增量）。
- 输入线程永远墙钟采样，不受 global 与任何域乘数影响——这是"时间减速时输入依旧流畅"的立身之本。

**玩家操控权：独立使能开关，不借用时间系数**：
- 用 `系数=0` 表达"玩家无法移动"是语义滥用：0~1 之间无定义、除零隐患、无法归因调试。
- 用 `InputController.enabled`（`std::atomic<bool>`，服务端权威）控制：采样事件带"是否有效"标记，或被禁时丢弃但保留墙钟时间戳。
- "无法移动"分两层实现：**输入禁用**（不再接受玩家指令）+ **物理冻结**（已产生指令失效、速度清零），分开做，不与时间缩放混淆。

### 2.6 跨线程通信方式：事件走队列、状态直接读（已确认 2026-09-28）

通信按语义分两类，机制不同（已实现并验证）：

| 通信类型 | 语义 | 机制 | 用途 |
|---|---|---|---|
| **事件/指令** | 一次性、保序、消费即毁 | **SPSC 队列** | 输入→物理、业务→物理（MoveBlock/打包）、回执 |
| **状态/快照** | 只需最新、可丢旧值 | **直接读**（原子/双缓冲，单写多读）| 渲染读物理位置、渲染读方块世界 |

- **渲染层不参与队列通信**：渲染是纯读消费者，只要"现在什么样"；队列消费即毁、生产>消费会堆积，语义不符。渲染直接读"最新快照"（原子或双缓冲），频率独立（60Hz+），可容忍丢旧值。
- **回执 vs 快照（已实现）**：动作必须全部执行（命令零丢失）；状态只需最新（快照合并，中间态丢弃）。打包/解包确认走**回执**（逐条、不合并）；位置回传走**快照**（合并）。`syncToBusiness` 先发回执再发快照。

### 2.7 方块体系：数据/逻辑/物理三层 + 状态权威（已确认 2026-09-28）

方块 = 三层，目前只建了数据层：

| 层 | 内容 | 归属 | 状态 |
|---|---|---|---|
| 数据层 | 类型+坐标（BlockType/BlockPos/Block）| shared | ✅ 已建（2.1）|
| 逻辑层 | TE 逻辑（熔炉烧炼、红石）| 业务线程 20TPS | ❌ 后置（极简 TE 里程碑）|
| 物理层 | 碰撞体（阻挡/站立/承载）| 物理线程 25TPS | ❌ 后置（2.3 起）|

**状态权威（位置物理权威、后果业务权威）**：
- 存在性/类型/属性/TE 逻辑 → **业务**（放置破坏=玩家意图+世界规则，业务裁决）
- 复合体上的位置/碰撞体 → **物理**（世界坐标 = 刚体位置 + 局部坐标）
- 物理形态（静态 vs 打包）→ **业务裁决 + 物理执行**（打包指令业务发、刚体物理建）
- 大多数方块**无逻辑只有物理**（石头/木头/泥土哑方块）；只有少数方块（熔炉/箱子/红石）三层全有
- 交界处（打包指令、位置快照、碰撞事件）全走队列

**Block vs BlockState 分离：暂缓**，触发时机 = 世界存储/区块里程碑（出现"同类型不同状态"+ 大量存储需调色板压缩时）。

### 2.8 浮点精度策略（已确认 2026-09-28）

- 方块坐标 `int`（±21.4 亿格，MC 同款；MC 世界边界仅 ±3000 万格，用不到 1/70）。
- 物理刚体位置一律 `double`；**禁止 float 存绝对坐标**（MC Far Lands = float 精度崩坏，约 ±1250 万格）。
- **复合体 = 基准 + 局部坐标**：飞船一个 double 世界位置，方块永远存局部 int 坐标，精度问题隔离在单一基准上（"实体方块在飞船上"的正确坐标模型）。
- **渲染偏移（camera-relative）**：GPU 坐标永远 = 世界坐标 − 相机坐标（两个 double 相减 → 小值），渲染精度免疫，将来写渲染层必用。
- **原点漂移（远期）**：玩家远离原点 N 格时整体平移世界坐标回原点（KSP 同款），支持无限大世界。
- 实证参考：Create Aeronautics 把机器放约 2000 万格远的独立子层级跑物理（内部局部坐标 + 渲染投影），double 在 2000 万格仍安全（最小增量 ~4e-9）。

## 3. 动态复合体（核心特性）

玩家把一组方块打包成一个"动态复合体"（巨型飞船/移动要塞），物理层坍缩成**单个刚体**。

### 3.1 开销本质（回答"动态结构为何需要持续计算"）
- **静态方块（主世界）**：放置完成后生成碰撞体，后续只做查询，**无持续计算**，开销固定。
- **动态复合体（打包后，内部方块不变）**：物理层视为**单个刚体**，tick 开销几乎恒定，**不随内部方块数量增长**（物理引擎只认质量、惯性、外部碰撞轮廓，不关心内部有多少方块）。
- **动态复合体（内部方块持续增删）**：每次改动需**重新遍历全部方块**，重算质量、惯性、重建复合碰撞形状。**这是开销爆炸点，也是你说的根本权衡**，无法彻底消除，但可通过优化大幅缓解。

### 3.2 优化方向（后期）
1. **增量更新**：方块增删只局部更新质量/惯性/碰撞形状贡献，不每次全量遍历；缓存每方块贡献。
2. **子复合体分层**：超大建筑拆成多个子刚体 + 约束连接；局部修改只重算局部子刚体。
3. **结构冻结**：标记复合体只读，禁止内部方块改动；关闭重建逻辑，缓存碰撞/LOD 永久复用，随时可解除继续施工。

### 3.3 原型阶段取舍
- **不做增量更新**：方块修改时**全量遍历重算**质量/惯性/碰撞形状。性能差没关系，只求逻辑正确。
- 结构冻结功能后置。

### 3.4 玩家工作流（冻结示例）
1. 移动要塞上搭建、修改方块（未冻结，每次修改触发重建）。
2. 建造完成 → 开启【结构冻结】→ 物理开销极低，不能再改方块。
3. 想改造 → 解除冻结。

## 4. 物理碰撞方案

### 4.1 三种方案对比
| 方案 | 特点 | 适用 |
|---|---|---|
| AABB（MC 原版） | 轴对齐、不旋转、O(1) 相交，速度快、精度差 | MC 实体/方块 |
| OBB（航空仿真） | 跟随刚体姿态旋转、外形包裹紧密 | 飞行器 |
| 粗相 AABB + 窄相多 AABB 转 OBB（航空学 Sable） | 粗筛用膨胀世界 AABB，精细碰撞用局部方块 OBB | 玩家自由方块复合体 |

### 4.2 机械动力航空学（Sable）的包围盒（重点参考）
- **Broad Phase（粗筛）**：复合体整体世界 AABB，旋转时膨胀。用于快速剔除不相交物体，开销极低。
- **Narrow Phase（精细）**：复合体存**局部坐标系下多 AABB 集合**（每个方块一个），tick 时取姿态矩阵把各局部 AABB 顶点变换到世界空间，变成 OBB 参与精细碰撞，轮廓贴合方块外形。
- **代价**：
  - 修改结构 → 一次性尖峰开销（重建局部 AABB 集合）。结构冻结可消除。
  - 每物理 tick → 持续开销（所有方块 AABB 顶点矩阵变换）。载具越大越明显；可用 BVH / 物理 LOD 缓解。

### 4.3 本项目方案
- **原型（已实现，2026-09-29）**：复合体用**增量最小碰撞箱**（Sable 思想的简化落地）——每方块变更时 `recomputeAABB` 实时重算最小包裹：半宽 = (max−min)/2 + 0.5、中心偏移 = (min+max)/2（格索引语义下恰好贴合方块边界）。改造加方块 → 半宽扩张、偏移平移；拆方块 → 收缩贴合。物理碰撞用该 AABB 与静态碰撞体做空间哈希粗相 + 严格区间重叠窄相。
- **碰撞事件 = 接触语义（已实现，2026-09-30，Rapier Started/Stopped 的 Started 部分）**：物理侧维护接触集合（刚体 id → 接触中的方块坐标），只在"接触开始"（新加入集合）时发 CollisionEvent；持续重叠（Stay）不发；接触结束/方块删除后从集合移除。同一对 (刚体, 方块) 只报一次——`collisions_` 从"重叠 tick 数"修正为"真实碰撞次数"（断言由 ≥1 升级为 ==1）。响应（回退+清速）每帧可重复（顶着方块），事件只在接触开始时发一次——行为与语义解耦，对齐 Rapier。
- **后期**：升级为 Sable 同款——粗相全局 AABB + 缓存局部多方块 AABB 列表，tick 变换为 OBB 用于窄相（旋转时轮廓贴合）。

> 区分：物理碰撞形状（服务端，AABB/OBB）与渲染 LOD 网格（客户端，几何体）是**两套独立数据**，服务端不需要知道渲染长什么样。

## 5. LOD 与渲染（全在客户端）

### 5.1 原则
- LOD 是**客户端专属工作**，服务端只同步复合体位置/旋转/方块布局，不知道长什么样，更不知道 LOD。
- 所有 LOD 优化模组必然是客户端模组。

### 5.2 两类实体的 LOD 方案
**常规模组实体（固定模型）**：模组作者预做 LOD0/1/2 模型，客户端按距离切换。简单，传统游戏 LOD。

**方块复合体动态 LOD（玩家自由拼接几何体，重点）**：
- 没有预置模型，必须**客户端实时自动生成** LOD 网格。
- 复合体方块改动 → 客户端重新生成全部 LOD（服务端不参与，无网络流量）。
- 层级：LOD0 完整方块 → LOD1 合并相邻共面面片 → LOD2 体素降采样（包围盒切更大体素格）→ LOD3 包围盒。

### 5.3 LOD 线程设计
- **昂贵的几何体生成丢进后台 LOD 任务线程**；渲染线程只挑选已生成完毕的网格绘制，不阻塞。
- 工作流：服务端下发方块变更 → 客户端逻辑线程压 LOD 重建任务入队 → LOD 后台线程消费并生成 LOD0/1/2 → 原子交换渲染资源 → 渲染线程取用。
- 未生成完成就用上一版旧 LOD 网格，不消失、不卡顿。

### 5.4 渲染剔除规则
1. **视锥剔除**：不在相机视野内直接跳过。
2. **距离剔除**：超过设定最大渲染距离不渲染，可配置。

### 5.5 静态方块世界（主世界）远距离优化
- 不做传统模型 LOD。用 **Chunk 管理 + Mesh 合并（块级顶点烘焙）**：同一 Chunk 相邻方块合并成大顶点缓冲，减少 DrawCall。
- 原型：基础 Chunk + 视锥剔除，超距不画，无 Mesh 合并、无 LOD。

### 5.6 坑点
- **LOD 切换跳动（Pop-in）**：远近切换模型视觉突变。缓解：距离区间内 Alpha 混合、缓冲阈值防抖动。
- **复合体改动时 LOD 需重建**：结构冻结 → LOD 缓存永久保留；未冻结 → 全量重建（与物理惯性重建同类权衡）。

### 5.7 原型阶段处理
- 只绘制 LOD0 完整方块模型，做基础视锥和距离剔除，**不做自动 LOD 生成**。

### 5.8 渲染轨定位（第四轨，客户端角色；约 5.x 启动）
- 渲染 = **第四条轨（客户端轨）**：只读快照显示，**永远不参与权威裁决**。
- 数据源：物理位置快照（刚体/代理）+ 业务方块快照（双缓冲：业务写、渲染读）。**渲染不连任何队列**（见 2.6）。
- **渲染插值**：物理 25Hz 更新、渲染 60Hz+（帧数不限制：渲染循环不锁帧，帧率由硬件决定，可配 VSync/帧率上限/动态分辨率），渲染在两次物理快照之间按时间 lerp 位置 → 画面平滑。**插值基座已落地（2026-09-30）**：业务侧双槽快照 + `sampleShipPos(simT)`，渲染每帧取渲染时刻换算模拟时刻后插值；帧率越高插值点越密，机制与帧率无关。
- **无头验证哲学**：核心玩法（逻辑/物理/时间）全部可用控制台验证，不依赖渲染；渲染排在 5.x（先无头把玩法做对，再显示，返工最少）。
- 过渡形态：控制台伪渲染（读快照画俯视图），4.x 前后可选，提前"看到"世界。
- Vulkan 学习与引擎开发并行：现在学图形技能，5.x 引擎需要时正好衔接。

## 6. 模组系统（类委托拦截，对标 Mixin）

- 目标：可拦截类、原型复制、Wrap/Override 委托链，支持新对象替换行为；可选后期加 tick 边界老对象指针重定向。
- **难点**：引擎是多线程（业务/物理/渲染多轨），模组代码容易错误跨线程读写状态引发竞态崩溃。需要在委托层加安全校验，限制模组 API 只能在指定线程调用。
- **原型阶段推迟**（不实现类拦截系统），原型只验证三轨核心。

1. **① 代码定向清理** ✅ 已完成（2026-09-29/30）：
   - 拆演示状态机 → `demo/DemoDriver`（tick 事件源驱动），`BusinessWorld` 纯能力化（命令式接口：`syncAll/packContraption/unpackContraption/placeBlock/removeBlock`，裁决通过自动排队指令）
   - 拆 main → `runDemo() + main()`，退出码 0/1 可被脚本/CI 用；伪渲染移到 `demo/ConsoleRenderer`
   - 日志分级 `core/Log.hpp`：`LogLevel`（Debug/Info/Warn/Error）+ `g_logLevel` 开关 + `log()` 原子输出 + `LOG_*` 宏，三轨日志全部接入
   - Release 构建（Ninja + /O2）+ 性能基线 `bench/baseline.txt`（27 方块场景 16s 完整输出，17/17 软断言全过，作后续升级对照系）
   - 顺手修复隐藏依赖：`Block.hpp` 显式 `#include <functional>`（之前靠 `<unordered_map>` 传递引入侥幸编译）
2. **② 世界数据升级 ✅（全部完成，2026-09-30）**：
   - **碰撞事件 → 接触语义 ✅**：物理侧接触集合，Started 只在接触开始时发，同一障碍物只报 1 次（断言 ==1）；持续重叠不发；接触结束/方块删除后移除
   - **位置带时间戳 → 插值基座 ✅**：业务侧双槽快照 `PosSample{simT,x,y,z}` + `sampleShipPos` lerp（窗口外钳制）；顺带修复物理位置快照洪水——原本每墙钟循环重复发同 simT 位置 ~15 次，改为只在模拟时刻推进时发（每模拟 tick 一条）
   - **区块化存储 ✅**：`blocks_` 线性 vector → `unordered_map<ChunkPos, ChunkData>`（16³ 立方体密集 `uint8_t[4096]`，空 chunk 不占内存，定位 O(1)）；刚体域方块（contraptionId≥0，局部坐标）独立容器 `bodyBlocks_`（复合体不进 chunk）；`forEachBlockInAABB` 区域查询（同步/LOD 生成/变更广播共用）；修改跟踪 `ChunkData.dirty` 位掩码（Minetest `raiseModified` 思想）；`findBlock` 改 `std::optional` 值返回；`blocks()` 删除 → `renderSnapshot()` 生成全量（协议边界保持 vector<Block>，物理侧零改动）
   - **变更事件流 ✅**：业务→渲染增量通道 `BlockChangeEvent{tick, dirtyChunks[]}`——写操作（放置/破坏/碰撞破坏/解包重建）标脏 `dirtyChunksThisTick_`，业务 tick 边界 `flushChanges` 聚合一条发出；渲染端消费标记脏 chunk → 只重建变过的 chunk mesh。与位置快照语义区分：快照满则丢（中间态可弃）、变更事件满则不丢（下 tick 重试，丢变更 = 漏重建）。刚体域变更不进流（复合体 = 动态渲染单元，由 RigidBodyPos 驱动）
   - **bug 修复（审查发现）**：打包时业务侧主世界 chunk 未置空（物理形态转移不同步，幽灵飞船 + 解包残留）→ 打包同步置空标脏 `0x20`；解包 `chunks_.clear()` 全清主世界丢其他方块 → 只清刚体域+写回执；tps 日志口径 `tick/模拟时间` 在 time_scale≠1 时失真 → 改墙钟口径
3. **③ 线程架构决策 ⚠️ 渲染线程骨架已落地**：第 4 轨 ThreadLoop("render") ~60Hz 正式立起（2026-09-30）——消费 businessToRender 变更事件流 → 标记脏 chunk → `sampleShipPos` 插值刚体位置 → 伪渲染帧（降频 1Hz，console ASCII）；渲染线程只读消费（不向模拟发任何指令）；停轨顺序：模拟三轨先停、渲染最后停。剩余：GLFW 窗口/消息泵归属、输入扩展鼠标视角、真实 mesh 重建。
4. **④ 数学库 + 图形 API ⚠️ 依赖已接入，渲染实现未开始**：vcpkg manifest 接入（2026-09-30）——glm（GL 数学 header-only）、glfw3（窗口）、vulkan-headers + volk（Vulkan API 免 SDK 动态加载，无 LunarG SDK 也能调用全部 API）；CMakePresets 接 vcpkg toolchain，链接验证通过。剩余：GLFW 窗口 + vkCreateInstance 实例 → 枚举设备 → swapchain → pipeline 画第一个方块。
5. **⑤ CMake 依赖 + 拆静态库** ❌ 未开始：core/business/physics/render 拆静态库，依赖接入。

**重构策略（已定，不做 Big Bang）**：渲染前定向清理、渲染后结构调整（拆静态库、统一分层）；软断言（26 条）当行为不变护栏；每次改动"改→编译→跑断言→全过再下一块"。

**性能验证体系（硬性要求）**：必须在 **Release 构建**测（Debug /RTC1 会扭曲 5-10 倍）；墙钟计时（time_scale 缩放模拟时间不可作性能依据）；warmup 后取中位数；对比 `bench/baseline.txt`；压力场景：10 万方块全量同步、1 万次/秒变更事件、1000 刚体碰撞。

## 9. 性能预期（单机原型）

- 约 6 条常驻线程，现代 4 核 8 线程 CPU 压力不大；**瓶颈不在线程数量，在线程内做什么**。
- 大部分时间：渲染线程 + GPU 是主要负载，其余线程多处于等待/休眠。
- 两个短时 CPU 尖峰场景：
  1. 大型动态复合体增删方块 → 服务端物理重算质量惯性 + 客户端 LOD 后台线程重建网格，同时爆发。
  2. 视野内大量方块/复合体 → 渲染提交压力大，GPU 成为瓶颈。
- 单机优化空间：进程内无锁队列免网络 IO；写时复制/双缓冲快照避免每次完整拷贝；可选线程亲和性把服务端线程绑独立核心。

## 10. 已确认的设计决策速查

| 项 | 决策 |
|---|---|
| 业务世界 TPS | 20（dt=0.05s） |
| 物理对外回调 TPS | 25（dt=0.04s），内部可开子步 |
| 输入线程 | 客户端，墙钟独立采样，不受 time_scale |
| time_scale 结构 | global × 域乘数（业务/物理各一，默认 1）；跨轨交互以 global 为基准 |
| 输入线程时间系数 | 无，永远墙钟原生，不受任何系数影响 |
| 玩家操控权 | InputController.enabled 独立开关（服务端权威），不用时间系数表达 |
| 跨线程通信 | 事件走 SPSC 队列；状态直接读（单写多读原子/双缓冲）；渲染不参与队列 |
| 回执 vs 快照 | 打包/解包确认走回执（逐条不合并）；位置回传走快照（合并，中间态丢弃） |
| 位置快照语义 | 带模拟时间戳（simT），只在模拟时刻推进时发（每模拟 tick 一条，2026-09-30 修复重复洪水） |
| 渲染插值 | 业务侧双槽快照 + `sampleShipPos(simT)` lerp（2026-09-30 已实现）；渲染帧率不限，帧率越高插值点越密 |
| 变更事件流 | 业务→渲染增量通道（2026-09-30 已实现）：写操作标脏 → tick 聚合 `BlockChangeEvent` 发出；快照满则丢、变更事件满则不丢（下 tick 重试） |
| 区块存储 | 16³ 立方体 `unordered_map<ChunkPos, ChunkData>`（2026-09-30 已实现）：空 chunk 不占内存、定位 O(1)、修改跟踪 dirty 位掩码 |
| 渲染线程 | 第 4 轨只读观众 ~60Hz（2026-09-30 落地）：消费变更事件流 → 标记脏 chunk → 插值刚体位置 → 伪渲染帧；不向模拟发指令；模拟三轨先停、渲染最后停 |
| 渲染依赖 | vcpkg manifest（2026-09-30 接入）：glm（数学）/ glfw3（窗口）/ vulkan-headers + volk（Vulkan 免 SDK 动态加载）；CMakePresets 接 vcpkg toolchain |
| 方块状态权威 | 存在/类型/属性归业务；复合体位置/碰撞归物理；打包=物理形态权威转移 |

| 物理碰撞（原型） | 增量最小碰撞箱（半宽/偏移实时贴合，2026-09-29）+ 接触语义事件（Started 只在接触开始时发，2026-09-30） |
| 物理碰撞（后期） | 粗相全局 AABB + 窄相局部多 AABB 转 OBB（Sable 同款） |
| 复合体重建（原型） | 方块改动全量重算 |
| 复合体优化（后期） | 增量更新、子复合体、结构冻结 |
| LOD | 客户端后台任务线程生成，渲染线程只取用 |
| LOD（原型） | 只画 LOD0，不做自动生成 |
| 渲染 API | Vulkan |
| 服务端 | 无渲染、无 LOD、无输入线程 |
| 单机 | 客户端+服务端同进程，内存队列通信 |
| 仓库 | GitHub 私有，原型稳定后公开只读，MIT |
